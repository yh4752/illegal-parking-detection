# 개발 AI용 자료 — 여기서 시작

문서 판본: v1.43 / 기준 설계: v1.42 / 정리일: 2026-11-06.

이 자료는 엣지 AI 주정차 안내 시스템의 구현 기준이다. v1.43은 사람용 요약과 개발 AI용 상세 자료를 분리한 판본이다. 기존 기능·역할·통신 계약을 바꾸지 않았다. 서비스 코드와 실차 시험은 아직 없다.

## 처음 읽을 파일

1. 이 문서와 [현재 상태](PROJECT_STATUS.md)를 읽는다.
2. [공통 개발 지침](AGENTS.md)을 확인하고 아래에서 자신의 담당 안내 하나를 선택한다.
3. 담당 안내의 **첫 작업**에 연결된 명세를 읽는다. 다른 절은 해당 작업이 필요할 때 찾아 읽는다.

| 담당 | 시작 문서 | 첫 작업 |
|---|---|---|
| Data | [자료 수집·정답·평가](tasks/data.md) | W14: 자료 출처·라벨·분할·개발 영상 인계 계획 |
| AI 모델·현장 장치 | [판단·출력·보드 결합](tasks/vision.md) | W01: 실제 보드 환경과 모델 실행 경로 확인 |
| 백엔드 | [계약·SDK·서버·운영](tasks/backend.md) | W00: 계약·예제 검증과 공통 입력 확인 |
| 프론트 | [관리자 화면](tasks/frontend.md) | W07: 가상 상태로 조회·명령·최신성 화면 구성 |

여기서 **개발 AI**는 이 자료를 읽는 코딩 도구를 뜻한다. 팀의 **AI 담당자**는 모델·판단·실제 보드와 출력을 담당하는 사람이다.

## 모든 담당이 지켜야 할 기준

- 한 모의 구역·한 차량을 대상으로 정차를 관찰하고 현장에서 안내한다. 법적 위반 확정·과태료 부과·자동 신고는 구현 범위가 아니다.
- AI가 판단 상태와 실제 출력을 소유한다. 백엔드는 장치용 저장·통신 SDK를 작성한다. AI가 그 SDK를 실제 보드에 설치·결합한다. 기본 구성은 같은 프로세스다.
- 첫 안내는 유효한 정차 후보 300초와 모든 허용 조건을 요구한다. 재안내는 첫 음성 종료 후 30초 이상과 현재 후보 300초 이상을 모두 요구하며 사건당 시도는 최대 2회다. 600초 미해소 기준은 별도다. 정확한 초기화·보류 규칙은 [A2](spec/protocol/A2.md)를 따른다.
- 새 안내는 로컬 저장 완료와 최신 조건 확인 뒤 실행한다. 안전 중단은 저장·사진·네트워크를 기다리지 않는다. [D3](spec/storage/D3.md)
- MQTT PUBACK는 브로커 수신 확인이다. 서버 저장 확인은 DB 커밋 뒤의 응용 ACK다. HTTP 202 접수와 장치 APPLIED도 구별한다. [C2](spec/protocol/C2.md), [C4](spec/protocol/C4.md)
- 과거 메시지·늦은 HTTP 응답·중복 명령으로 현재 상태를 되돌리거나 출력을 반복하지 않는다. 각 경로의 순서값과 멱등 규칙을 따른다.
- 시뮬레이터·문법 검증 성공을 실보드·물리 출력·실차 성능 성공으로 보고하지 않는다. 미정 환경은 추정해서 확정하지 않는다.

## 자료의 기준 위치

| 확인할 내용 | 기준 파일 |
|---|---|
| 서비스 범위·운영 의미 | `spec/project/`, `spec/protocol/` |
| 상세 저장·복구·동시 처리 | `spec/storage/`와 [DB 안내](db/README.md) |
| API·메시지 필드·자료형 | [계약 안내](contracts/README.md)의 OpenAPI·JSON Schema |
| Schema로 검사되지 않는 의미 조건 | 상세 명세와 `semantic_checks.json` |
| SDK 경계·전송·로컬 영속화 | [SDK 안내](edge_sdk/README.md) |
| 역할·인계·일정 | `spec/roles/`, `spec/plan/`, 기존 작업 목록의 W00~W14 |
| 아키텍처·흐름 | [텍스트 아키텍처](architecture/README.md)와 F01~F17 도식 |
| 시험과 결과 해석 | [시험 안내](tests/README.md) |

`개발자료/`의 v1.4 파일명과 내부 버전은 참조 호환성을 위해 보존했다. 문서 판본 v1.43, 내부 계약 버전, 네트워크 `schema_version=2`는 서로 다른 값이다. 문서 판본에 맞추려고 메시지 버전을 바꾸지 않는다.

사람용 PDF와 이전 판본은 이 묶음의 필수 입력이 아니다. 필요한 설계 설명은 Markdown에, 정밀 계약은 원본 파일에 있다. 그림만 보고 생략된 조건을 추측하지 않는다.

이전 문서의 절을 찾을 때는 [원문 위치 대응표](SOURCE_MAP.md)를 사용한다. 전체 명세 목록은 [spec 안내](spec/README.md)에 있다.

## 개발 AI에게 전달할 요청 예시

압축을 풀고 전체 개발 AI용 폴더를 도구가 읽을 수 있는 작업 폴더에 둔다. ZIP이나 폴더를 열 수 없는 도구는 자료를 읽었다고 가정하지 말고, 작업에 필요한 파일 목록을 요청한다. 접근하지 못한 파일을 확인한 것처럼 보고하지 않는다.

> 이 폴더의 START_HERE.md와 PROJECT_STATUS.md를 읽어 주세요. 제 담당은 **백엔드**입니다. tasks/backend.md에서 첫 작업을 확인하고, 그 작업에 필요한 명세와 공통 계약을 읽은 뒤 구현을 진행해 주세요. ZIP이나 폴더를 열 수 없다면 읽었다고 가정하지 말고 필요한 파일 목록을 먼저 알려 주세요. 먼저 읽은 파일, 이해한 담당 범위, 첫 작업과 완료 시험을 짧게 보고해 주세요. 미정 사항이나 명세 충돌이 있으면 근거 위치와 영향을 알려 주고, 그 결정에 의존하지 않는 작업은 계속해 주세요. 기존 필드·상태·시간값·역할을 임의로 바꾸지 말고, 실행한 시험과 아직 실행하지 못한 시험을 구분해 주세요.

담당에 맞게 `백엔드`와 작업 안내 경로를 바꾼다. 도구가 `AGENTS.md`를 자동으로 읽는다고 가정하지 않고 이 시작 문서를 명시한다.
