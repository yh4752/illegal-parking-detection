# 이 설계 자료를 사용하는 개발 AI 지침

## 적용 범위

이 폴더는 v1.42 설계를 재구성한 v1.43 개발 자료다. 실제 구현은 사용자가 요청한 작업 범위에서 진행한다. 먼저 [START_HERE.md](START_HERE.md), [PROJECT_STATUS.md](PROJECT_STATUS.md), 해당 `tasks/` 안내를 읽는다.

## 설계 해석과 변경

- `tasks/`는 작업 진입점이다. 동작을 축약한 설명만으로 구현하지 않고 연결된 상세 명세와 계약을 읽는다.
- API·메시지 형식은 OpenAPI·JSON Schema, 동작 조건은 상세 Markdown와 의미 검사 목록, DB 구조는 SQL, SDK 입력·출력은 내부 계약을 기준으로 삼는다. 어느 한 파일이 모든 분야를 무조건 덮어쓴다고 해석하지 않는다.
- 두 기준이 충돌하면 파일·절·필드, 실제 차이, 영향을 받는 작업, 가능한 수정안을 보고한다. 관련 결정을 임의로 선택하지 않는다. 충돌과 무관한 작업은 계속한다.
- 공통 필드·토픽·상태·시간·역할을 담당별로 복사해 따로 유지하지 않는다. 계약 변경이 승인되면 원본·예제·검증·영향받는 명세를 함께 갱신한다.
- v1.43 문서 판본과 `schema_version=2`를 혼동하지 않는다. 기존 v1.4 파일명도 임의로 일괄 변경하지 않는다.
- 설계 초기값·목표·실제 측정값을 구분한다. 지원 여부가 미정인 보드 언어·ABI·카메라·장소·배포 주소를 확정된 사실처럼 채우지 않는다.

## 책임 경계

- Data: 출처·권리·영상·라벨·정답·개발/평가 분리와 평가 기록.
- AI 담당: 실제 보드 환경, 모델·추적·품질·상태 판단, 카메라·시계·출력 어댑터, 실제 배선·SDK 결합·현장 시험.
- 백엔드: 공통 계약, 장치 저장·통신 SDK, PC 가상 장치, Mosquitto 브로커 설정·운영, 서버·DB·API·권한·배포·모니터링과 연동 인수. MQTT 브로커 자체를 새로 개발하는 범위는 아니다.
- 프론트: React 관리자 화면과 REST/SSE 연결, 요청·적용 결과·최신성·연결 이상 표시.

코드 작성 담당과 실행 위치는 다르다. 백엔드 작성 SDK가 실제 보드에서 실행되어도 판단과 물리 출력 책임까지 백엔드로 옮기지 않는다. [역할 기준](spec/roles/B1.md)

## 구현과 증거

- 새 출력은 로컬 저장 완료와 최신 guard 확인 후에만 실행한다. 안전 중단은 저장 장애에도 우선한다. 늦은 COMMITTED로 중단된 출력을 다시 시작하지 않는다.
- 성공을 보고할 때는 어느 경계의 성공인지 명시한다. 접수, 브로커 전달, DB 커밋, 장치 적용, 물리 관측은 서로 다르다.
- 네트워크·사진 I/O가 제어 루프를 막지 않도록 기존 worker·큐·단일 writer 규칙을 따른다.
- 실제 비밀값·인증서 개인키·촬영 원본을 예제나 로그에 넣지 않는다. 기존 권한·보관 규칙을 따른다.
- 기존 검증 보고서는 당시 범위의 기록이다. 현재 환경에서 실행했다고 재표기하지 않는다.
- 매 시험에 입력·환경·버전·실행 방법·기대값·관측값·판정을 남긴다. 실패·미수행·보류를 성공으로 합치지 않는다.
- 가상 장치 시험 BC01~BC05와 실제 보드 시험 BC06을 별도로 기록한다. 구현하지 않은 코드나 수행하지 않은 실차 시험을 완료했다고 보고하지 않는다.
