# 현재 상태와 남은 결정

기준일: 2026-11-06 / 문서 판본: v1.43 / 원설계: v1.42.

## 현재 상태

| 항목 | 상태 |
|---|---|
| 서비스·SDK·화면 구현 | 아직 시작하지 않음 |
| 데이터 수집·실차 평가·보드 성능 시험 | 아직 수행하지 않음 |
| 임베디드 보드 | 대여 완료, QCS610 플랫폼 사용 예정 |
| 설계·계약·예제 | 문서와 개발 자료로 제공 |
| 기존 검증 기록 | Schema/API·예제 및 SQL 문법/구조 등의 제한된 검사 기록. 실제 서비스·브로커·DB 동시성·실보드 인수 결과 아님 |
| v1.43 재현 검사 | 재편한 폴더에서 기존 계약 검증 코드 실행: 정상 예제 25개·오류 입력 45개·API 작업 15개·합성 시계 경계 7개 통과. [실행 결과](tests/validation_v1.43.json) |

이 파일은 설계 재편 시점의 상태다. 실제 구현이 진행되면 작업 결과와 증거를 근거로 갱신한다.

## 이미 정한 설계

- 한 모의 구역·한 차량을 실제 차량 촬영으로 시험한다. 현장 안내와 관리자 관제를 구현하며 법적 단속 판정을 자동 확정하지 않는다.
- 서버는 Kotlin + Spring Boot, MQTT 5, MVC SSE, Security, Spring JDBC, Flyway와 PostgreSQL 기준이다. 프론트는 React 관리자 웹이다.
- Mosquitto가 MQTT 메시지를 중계한다. 사진은 별도 HTTPS 업로드를 사용한다. 상세 접속·세션·재시도 설정은 [D1](spec/storage/D1.md)·[D2](spec/storage/D2.md)를 따른다.
- AI가 상태 전이를 결정하고 백엔드 작성 SDK가 SQLite의 단일 저장 경계와 통신을 맡는다. AI와 SDK는 기본적으로 같은 프로세스에서 결합한다.
- 첫 안내 300초, 재안내 간격 30초와 현재 후보 300초, 사건당 최대 시도 2회, 미해소 600초의 조건은 기존 명세를 유지한다. 단순히 시간이 지났다는 이유만으로 안내를 허용하지 않는다.

## 확인이 필요한 요소

| 확인할 것 | 담당·시점 | 기다리지 않고 할 수 있는 일 |
|---|---|---|
| 보드 정확한 제품·OS·ABI·런타임·TLS/MQTT5/SQLite·시각·장치 지원 | AI, W01·D+5 잠정 목표 | 계약·서버·가상 입력·화면 설계 |
| 장치 SDK 언어·라이브러리·바인딩 | W01 근거를 바탕으로 AI+백엔드 | 언어 독립 계약, PC 시험 시나리오, 서버 구현 |
| 장소 허가·촬영 참여·카메라 모델·설치·보정·전원·출력 연결 | Data 현장 준비 + AI 장비 인수, 실차 전 | 개발 자료·평가 계획과 모의 시험 |
| 실제 호스트·주소·인증서·장치 자격증명 | 백엔드, 원격 통합 전 | 로컬 격리 환경과 설정 예제 |
| 계정 운영·자격증명 만료·백업 주기·복원시간 목표 | 백엔드, 운영 설정 때 | 복원 절차와 장애 시험 구현 |
| 실제 착수일·제출일·투입시간·예산 | 전원, 일정 확정 때 | 작업 의존관계와 완료 기준 검토 |

D+일정은 실제 착수일을 기준으로 한 달력일 잠정 목표다. D+14 보드 통신 연결과 D+21 실제 SDK·출력·장애 인수, D+35 실차·비교 기록을 구별한다. 실제 날짜나 성능을 이미 확보한 것으로 간주하지 않는다.
