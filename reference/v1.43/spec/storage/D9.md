# D9 개발 시작 조건과 실제 확인이 남은 부분

> v1.43 개발 AI 상세 명세 · v1.42 본문 이관 · 구현·실차 시험 전

원문: `08_연동과_저장_상세설계_v1.42.docx` / D9 개발 시작 조건과 실제 확인이 남은 부분

문서 번호·이전 파일명은 [절별 위치 안내](../README.md)에서 찾는다. 표와 설명의 조건을 함께 적용한다.

서버 저장·API·MQTT 설정과 가상 장치의 구현은 이 문서의 기준을 따른다. 팀은 공통 계약과 시험 입력을 사용해 필드나 재시도 규칙의 해석이 달라지지 않도록 한다.

| 담당 | 다음 작업과 인수 기준 |
| --- | --- |
| 백엔드 | 계약 검증 실행 → 격리 DB에 DDL 적용 → 가상 사건 수신·저장·REST/SSE → 중복·역순·명령·저장 실패 시험. 서버·SDK 구현은 별도 착수. |
| AI | 실제 QCS610 제품·OS/ABI·언어·TLS/MQTT5/SQLite·카메라/출력 지원을 기록. SDK 바인딩과 실제 실행 로그를 제공. |
| 프론트 | OpenAPI와 공개 ZoneView 예제로 연결. 접수/적용/미확인·사진 만료·연결 이상·권한을 구분. 화면 구성은 담당자가 구체화. |
| Data | 개발 영상·정답·라벨·분할·평가 입력을 인계. AI 출력이 아닌 별도 정답으로 시험. |

자동 검사는 명세와 예제의 일치·오류 입력 거부·SQL 구조 범위를 확인한다. 실제 PostgreSQL 트랜잭션 경쟁, 브로커 단절, 카메라·스피커, 보드 FPS·중단 지연은 구현 후 지정 시험으로 확인해야 한다.

| 남은 확인 | 결정 시점 |
| --- | --- |
| SDK 구현 언어·바인딩 | AI의 실제 보드 환경표 확인 뒤 공동 확정. |
| 장소·카메라·전원·출력 배선 | 실차 시험 준비 전 현장 적합성 확인. |
| 배포 호스트·DNS·인증서 | 원격 장치 연결 전에 백엔드 담당자가 확보한다. 신규 구매는 필수 조건이 아니다. |
| 계정 운영·백업 주기·복원 목표 | 운영 설정을 확정할 때 백엔드 담당자가 결정한다. 현재 설계에서는 데이터 정합성과 복원 절차를 먼저 정한다. |
| 착수일·제출일·가용시간 | D+일정에 실제 날짜를 배치한다. 시험 완료 여부는 구현 후 실행 결과로 판단한다. |

측정 결과에 따라 세부 값을 조정할 때는 변경 이유와 영향을 받는 설정·계약·예제·시험을 함께 기록한다. 구현 언어와 성능은 담당 범위와 보드 지원 여부를 확인한 뒤 확정한다.
