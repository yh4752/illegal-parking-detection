# D7 API와 메시지를 자동 검사하는 계약

> v1.43 개발 AI 상세 명세 · v1.42 본문 이관 · 구현·실차 시험 전

원문: `08_연동과_저장_상세설계_v1.42.docx` / D7 API와 메시지를 자동 검사하는 계약

문서 번호·이전 파일명은 [절별 위치 안내](../README.md)에서 찾는다. 표와 설명의 조건을 함께 적용한다.

04의 설명용 JSON을 검증 도구가 읽을 수 있는 규격으로 정리했다. JSON Schema는 데이터 형식과 필수값을, OpenAPI는 웹 요청·응답과 권한을 정의한다. 서버와 장치 구현은 별도로 진행한다.

| 산출물 | 구현자가 사용하는 방법 |
| --- | --- |
| parking.schema.json | 20개 객체와 8개 MQTT 계열을 정의한다. 수신 토픽에 맞는 정의로 검사하며, 전체 합집합 검사를 통과했더라도 잘못된 토픽은 허용하지 않는다. |
| openapi.json | 15개 API 작업의 요청·응답·오류, 세션/CSRF와 장치 인증을 정의한다. 프론트와 백엔드는 같은 명세를 사용한다. |
| validate_examples.py | 기존 25개 예제와 잘못된 입력 45개, API 15개 작업, 합성 시계 경계 7개를 검사. |
| semantic_checks.json | 스키마만으로 검사할 수 없는 사건·토큰·동시 처리·권한·물리 출력의 구현 검사 목록이다. |

필수 키를 빠뜨리는 것과 키의 값이 null인 것은 다르다. null 허용 필드도 키는 필요하다. 0·false·빈 배열을 null로 바꾸지 않는다. 알 수 없는 일반 필드는 거부한다. 오류의 details만 원래 계약대로 JSON 값 맵을 허용한다.

JSON 해석 전 UTF-8·중복 키·NaN/Infinity·전송 크기를 검사한다. 날짜 format 검증은 명시적으로 켜며 UTC Z 형식을 사용한다. 메타데이터 64 KiB와 JPEG 5 MiB 제한은 실제 전송 bytes에도 적용한다.

같은 메시지의 envelope와 snapshot 순서값 일치, 명령 60초, 미해소시간>첫 안내시간처럼 필드 간 비교는 별도 검증을 수행한다. 현재 fixture 검사에 포함한 항목과 실제 DB/보드 시험이 필요한 항목은 SC01~SC10으로 구별했다.

검증 결과: JSON Schema 문법·OpenAPI 3.1 문법·기존 예제와 부정 입력 검사를 통과했다. 브로커·서버·DB·보드·실제 출력·성능은 아직 시험하지 않았다. clock_policy_boundaries는 전송 메시지가 아닌 문서용 경계 사례다.
