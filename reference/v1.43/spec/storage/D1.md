# D1 MQTT 접속과 재연결의 확정값

> v1.43 개발 AI 상세 명세 · v1.42 본문 이관 · 구현·실차 시험 전

원문: `08_연동과_저장_상세설계_v1.42.docx` / D1 MQTT 접속과 재연결의 확정값

문서 번호·이전 파일명은 [절별 위치 안내](../README.md)에서 찾는다. 표와 설명의 조건을 함께 적용한다.

토픽, 메시지, QoS와 5초 heartbeat는 기존 계약을 따른다. 아래 수치는 단일 구역 개발을 위한 초기 설정이며 실측값이나 MQTT 표준의 권고값은 아니다. 상세 설정과 근거는 transport_settings_v1.4.json을 참고한다.

| 항목 | 결정한 값과 이유 |
| --- | --- |
| 연결 ID | 장치는 edge0001, 서버 수신은 serverin0001, 서버 발신은 serverout0001처럼 서로 다른 고정 ID를 사용한다. 각 ID를 등록 계정에 연결하며 중복 실행을 금지한다. |
| 세션 | Clean Start=true, Session Expiry=0으로 설정한다. 연결할 때마다 다시 구독하며, 장치/서버 outbox에서 전송을 복구한다. |
| 연결 초기값 | MQTT 5, TLS 포트 8883을 사용하고 인증서와 호스트를 검증한다. Keep Alive는 15초, 연결·구독 제한은 10초다. QoS 1의 inflight 한도는 8이다. |
| 재연결 | 1→2→4→8→16→30초 간격으로 재연결하며 ±20% 범위로 분산한다. 60초간 안정적으로 연결되면 간격을 초기화한다. 인증·ACL·Client ID 충돌은 설정을 확인한다. |
| 장치 연결 순서 | CONNECT/CONNACK → 자기 acks·commands·desired 구독/SUBACK → ONLINE → 최신 보고·heartbeat → 과거 기록 재전송. |
| 서버 연결 순서 | DB·수신 구독·발신 연결 확인 → 최신 desired 복원 → 기한 안의 명령 재발행. |
| 연결 판정 | Will은 현재 connection_id를 확인하는 보조 정보로 사용한다. 최신성은 새 heartbeat로 판단하며 15초/30초 기준을 유지한다. |

세션 만료값이 0이면 브로커는 연결이 끊긴 수신자의 명령을 장기 보관하지 않는다. 서버는 영속 명령 대기함에 기록하고 주기적으로 재발행해야 한다. 오래된 사건이나 retained ONLINE을 받아도 현재 연결을 정상 상태로 바꾸지 않는다.
