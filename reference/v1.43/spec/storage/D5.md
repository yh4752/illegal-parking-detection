그림 F11. 관련 DB 변경은 함께 저장하고 응답은 커밋 뒤에 보낸다

텍스트 도식: [F11](../../architecture/F11.mmd). 그림별 조건은 [아키텍처 안내](../../architecture/README.md)를 함께 확인한다.

사건 수신과 명령 접수는 각각 필요한 변경을 하나의 트랜잭션에 기록한다. ACK·SSE·HTTP 접수 응답은 커밋 성공 후 전송하며, 네트워크나 파일 작업 동안 DB 행 잠금을 유지하지 않는다.

· 그림은 두 처리 경로의 예시이며 하나의 트랜잭션에서 양쪽 데이터를 모두 생성한다는 뜻이 아니다.

· 실제 결과가 먼저 도착하면 늦은 발행 콜백이 완료 상태를 되돌리지 않는다.

격리 수준은 READ COMMITTED, 잠금 순서는 구역 → 장치 → 사건 → 명령 → 사진이다. 사건·heartbeat·명령·정책·사진·정리 작업이 같은 구역 경계를 사용한다. 네트워크·파일 I/O 동안 DB 잠금을 유지하지 않는다.

| 단계 | 한 트랜잭션으로 보장할 것 |
| --- | --- |
| 1 수신 검증 | 토픽/계정/장치를 대조하고 Schema와 의미를 검증한다. 본문 동일성은 RFC8785 canonical JSON의 SHA-256으로 판단한다. |
| 2 중복 검사 | device_id/message_id와 내용이 같으면 DUPLICATE로 응답한다. 내용이 다르면 격리하고 REJECTED로 응답한다. 저장 실패 시 성공 응답을 보내지 않는다. |
| 3 이력·현재 상태 | 사건은 사건별 seq, snapshot은 장치 seq로 갱신한다. 종료된 사건을 과거 상태로 되돌리지 않는다. |
| 4 화면 순서 | 화면에 보이는 상태 변경과 view_revision 증가를 같은 커밋으로 확정한다. ACK와 SSE는 커밋 성공 후 전송한다. |
| 5 명령 접수 | 권한과 대상을 확인한 뒤 command+outbox+request_receipt를 저장한다. 202는 요청 접수를 뜻하며 APPLIED와 구분한다. |
| 6 비동기 발행 | 15초 lease를 확보하고 커밋한 뒤 MQTT로 발행한다. PUBACK는 5초간 기다린다. command는 5초 간격으로 재시도하며 원래 60초 기한을 유지한다. |

lock_timeout 1초·statement_timeout 3초가 초기값이다. 허용한 잠금/직렬화 오류만 전체 롤백 후 제한 재시도하며 ID·payload·expires_at을 바꾸지 않는다. 최종 실패에는 성공 ACK/HTTP 성공을 반환하지 않는다.

실제 결과가 먼저 오면 늦은 PUBACK 콜백이 DONE을 되돌리지 않는다. 서버 재시작 후에도 같은 command_id만 사용한다. 기한+5초 무응답은 DELIVERY_TIMEOUT이며 늦은 실제 결과와 구별해 기록한다.

REST ZoneView는 단일 SELECT 또는 읽기 전용 REPEATABLE READ로 한 시점의 snapshot·명령·사진을 읽는다. SSE 누락은 기존 REST 재조회 규칙으로 회복한다.
