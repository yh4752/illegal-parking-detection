# D0 상세 설계의 범위와 읽는 순서

> v1.43 개발 AI 상세 명세 · v1.42 본문 이관 · 구현·실차 시험 전

원문: `08_연동과_저장_상세설계_v1.42.docx` / D0 상세 설계의 범위와 읽는 순서

문서 번호·이전 파일명은 [절별 위치 안내](../README.md)에서 찾는다. 표와 설명의 조건을 함께 적용한다.

v1.4의 역할 분담과 동작 규칙을 구현하기 위한 상세 설계다. 서버와 가상 장치는 보드 없이 개발할 수 있다. SQL, 설정 예제, 검증 스크립트는 구현 기준으로 제공한다. 실제 서버·장치의 동작 시험은 구현 후 수행한다.

| 항목 | 구체화한 결정 |
| --- | --- |
| MQTT 연결·복구 | 접속 ID, 세션, 재구독, 저장 확인, 재전송과 명령 잔여 기한을 정한다. 브로커의 전송 확인과 서버의 저장 확인을 구분한다. |
| DB와 동시 처리 | 테이블, 제약, 인덱스, 구역 잠금, 트랜잭션 순서와 파일/DB 복구 절차를 정한다. |
| SDK 내부 | AI의 상태 관리, 단일 저장 writer, 통신/사진 worker의 책임을 구분한다. 큐의 한도와 중단 우선순위를 정한다. |
| API·메시지 | JSON Schema·OpenAPI와 정상/오류 예제 검증을 제공한다. 시각·소유권·상태 조건은 별도로 검사한다. |

MQTT 토픽과 schema_version=2, 25개 예제, 첫 안내 300초·미해소 600초 기준을 유지한다. REST 즉시 STOP의 starts_at=null은 발행 시각으로 변환한다. 보관 만료 후 같은 요청에는 410을 반환하며 재실행하지 않는다. 공개 토큰은 null로 표시한다. 시각 회복 후에는 새 후보를 300초 관찰하며, 잘못된 입력에는 INVALID_SCHEMA를 사용한다.

| 용어 | 뜻 |
| --- | --- |
| SDK | AI가 호출하는 통신·저장 공통 코드다. 백엔드가 작성하고 AI가 실제 보드에 설치·연결한다. |
| 트랜잭션 | 여러 DB 변경을 전부 반영하거나 전부 취소하는 작업 단위. |
| outbox | 전달을 완료하지 못한 메시지를 저장하는 영속 대기함이다. |
| Schema / OpenAPI | 메시지의 검사 규칙 / HTTP 요청·응답과 권한을 도구가 읽을 수 있게 적은 명세. |
