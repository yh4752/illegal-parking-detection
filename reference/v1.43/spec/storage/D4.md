# D4 DB 구조와 중복 방지 기준

> v1.43 개발 AI 상세 명세 · v1.42 본문 이관 · 구현·실차 시험 전

원문: `08_연동과_저장_상세설계_v1.42.docx` / D4 DB 구조와 중복 방지 기준

문서 번호·이전 파일명은 [절별 위치 안내](../README.md)에서 찾는다. 표와 설명의 조건을 함께 적용한다.

테이블 정의는 schema.sql, 관계도는 erd.mmd에 있다. PostgreSQL·Spring JDBC·Flyway를 사용한다. 단일 구역의 쓰기는 zone_view 행 잠금으로 직렬화한다. 실제 DB 적용 시험은 구현 후 수행한다.

| 저장 묶음 | 담는 내용과 제약 |
| --- | --- |
| 계정·구역·장치 | app_user / zone / device에 사용자 역할, 1구역 1장치 관계, 장치 HTTPS 토큰 hash를 저장한다. 비밀값 원문은 저장하지 않는다. |
| 정책·현재 상태 | zone_policy의 (zone_id,version)은 유일하며 과거 버전은 변경하지 않는다. zone_view에는 최신 snapshot·heartbeat·view_revision을 저장한다. |
| 사건·수신 이력 | incident에서 사건별 순서를 관리한다. inbound_receipt에서 장치+message_id로 중복을 확인한다. event_message 원문은 30일 보관한다. |
| 명령·발송 대기 | command와 server_outbox를 같은 트랜잭션에 저장한다. lease_token으로 늦게 도착한 발행 콜백을 배제한다. |
| 중지·확인 기록 | pause_projection에는 장치의 실제 상태를 반영한다. review의 수동 용도 수정은 서버 overlay이며 자동 면제에 사용하지 않는다. |
| 사진·업로드 작업 | device_image와 image_upload_intent로 파일/DB 저장 사이에 발생한 중단을 복구한다. 파일은 접근이 제한된 비공개 경로에 저장한다. |
| 중복·종료 표식 | request_receipt와 entity_tombstone에 최소 키/hash/결과를 보존한다. 원문이 삭제된 뒤에도 명령·사건이 다시 생성되지 않도록 한다. |

HTTP 중복 키는 사용자별 client_request_id다. 같은 키의 method·대상·본문이 달라지면 409다. 동일 재시도는 최초 201/202 응답을 재현하고, 원래 자원이 보관기간 후 삭제됐다면 410으로 응답한다.

늦은 종료 메시지 때문에 이력 A가 아직 열려 있어도 실제 현재 차량은 B일 수 있다. DB에 “장치당 미종료 사건 1개” 제약을 추가하지 않고 최신 구역 상태와 사건 이력을 구분한다.
