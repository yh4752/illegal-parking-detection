# D8 즉시 중지 입력과 토큰 공개 범위의 확정

> v1.43 개발 AI 상세 명세 · v1.42 본문 이관 · 구현·실차 시험 전

원문: `08_연동과_저장_상세설계_v1.42.docx` / D8 즉시 중지 입력과 토큰 공개 범위의 확정

문서 번호·이전 파일명은 [절별 위치 안내](../README.md)에서 찾는다. 표와 설명의 조건을 함께 적용한다.

브라우저는 서버가 나중에 만들 issued_at를 미리 알 수 없다. 따라서 REST 즉시 STOP 입력과 MQTT 장치 명령을 구분해 정규화한다. 기존 MQTT 필드와 60초 유효시간은 유지한다.

| 경우 | 확정한 처리 |
| --- | --- |
| REST 즉시 STOP | params.starts_at=null. 서버가 issued_at 생성 후 MQTT params.starts_at에 같은 UTC를 넣음. pause_id도 서버 생성. |
| REST 예약 STOP | params.starts_at=미래 UTC 문자열, scope=ZONE. 이미 지난 예약을 즉시 요청으로 바꾸지 않고 INVALID_SCHEMA로 거부. |
| MQTT STOP | starts_at는 계속 UTC이며 null 금지. issued_at와 같으면 즉시, 더 늦으면 예약. 수신 보드의 불확실한 현재 시각으로 구분하지 않음. |
| 공개 명령 결과 | ZoneView·SSE·VIEWER의 confirmation_token은 필드를 유지하고 null로 제공한다. 필드 삭제로 기존 예제를 변경하지 않는다. |
| 운영자 토큰 조회 | 유효한 OPERATOR의 GET /api/commands/{id}에서만 토큰 문자열을 제공한다. 서버가 사용자 권한과 기한을 검사한다. |
| 잘못된 시간 정책 | unresolved_ms<=first_guidance_ms는 INVALID_SCHEMA(HTTP400). 기존 명세에 없던 VALIDATION_ERROR 문구 정정. |

HTTP 이름은 JSESSIONID 쿠키, X-CSRF-TOKEN 헤더다. 장치 사진 업로드는 별도 장치별 HTTPS Bearer 토큰을 사용하며 JWT를 요구하지 않는다. 실제 인증 정보는 명세·예제에 넣지 않는다.

재현: contracts 폴더에서 requirements.txt 설치 후 python validate_examples.py 실행. 다른 경로의 04 계약은 --contract로 지정한다. JSON Schema 4.25.1, OpenAPI Spec Validator 0.7.2 기준이며 결과와 한계는 validation_report.json에 남긴다.
