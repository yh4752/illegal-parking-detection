# D2 전송 성공과 저장·실행 성공을 구별하는 복구

> v1.43 개발 AI 상세 명세 · v1.42 본문 이관 · 구현·실차 시험 전

원문: `08_연동과_저장_상세설계_v1.42.docx` / D2 전송 성공과 저장·실행 성공을 구별하는 복구

문서 번호·이전 파일명은 [절별 위치 안내](../README.md)에서 찾는다. 표와 설명의 조건을 함께 적용한다.

| 대상 | 완료·재시도 기준 |
| --- | --- |
| 사건·명령 결과 | PUBACK 후 5초 안에 응용 ACK가 없으면 1·2·4·8·16·30초 간격으로 재시도한다. ID·본문·device_seq는 유지한다. 응용 ACK를 기다리는 메시지는 최대 8개다. |
| STORED/DUPLICATE | 서버 DB 저장을 확인한 뒤 전송을 완료한다. REJECTED는 실패함으로 옮기고 자동 재전송을 종료한다. |
| 관리자 명령 | 결과를 기다리는 동안 서버는 5초 간격으로 같은 명령을 재발행한다. 원래 유효시간 60초는 연장하지 않으며 MQTT expiry는 매번 남은 초로 계산한다. |
| 시간·재시작 | SDK는 수신 expiry를 단조시계 기준 deadline으로 고정한다. 큐 대기시간도 유효시간에서 차감한다. 서버 재시작 후 UTC를 신뢰할 수 없으면 이전 명령을 재발행하지 않는다. 새 즉시 STOP에만 기존 예외를 적용한다. |
| heartbeat/보고 | heartbeat는 과거 기록을 대기함에 쌓지 않고 최신 1개만 유지한다. reported는 현재 보고만 재발행한다. 재전송할 때 원래 관측 시각을 바꾸지 않는다. |
| 사진 | 별도 worker 1개, 대기 2개, 저장 한도 50 MiB와 기존 재시도/만료 규칙을 유지한다. 사진 실패로 사건 종료나 중지를 지연시키지 않는다. |

명령 수신·브로커 PUBACK·실제 적용은 서로 다른 단계다. 60초+5초 결과 유예가 지나도 결과가 없으면 기존 DELIVERY_TIMEOUT으로 미확인을 표시한다. ACK 유실·중복 재수신이 같은 음성이나 재개를 반복시키면 실패다.

브로커 설정 예제에는 TLS·계정·토픽 ACL·영속 볼륨과 대기 한도가 포함되어 있다. 인증서와 계정 파일은 별도로 준비한다. 배포와 접속 여부는 실제 환경에서 확인한다.
