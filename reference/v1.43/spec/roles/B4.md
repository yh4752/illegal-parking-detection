# B4 백엔드 담당자가 실제 보드 없이 개발하는 범위

> v1.43 개발 AI 상세 명세 · v1.42 본문 이관 · 구현·실차 시험 전

원문: `06_역할분담과_보드없는_개발명세_v1.42.docx` / B4 백엔드 담당자가 실제 보드 없이 개발하는 범위

문서 번호·이전 파일명은 [절별 위치 안내](../README.md)에서 찾는다. 표와 설명의 조건을 함께 적용한다.

백엔드 개발 PC에서 Compose로 Mosquitto·PostgreSQL·Spring·웹을 실행하고 가상 장치를 연결한다. 가상 장치는 실제 보드에 넣을 SDK의 저장·전송 경로를 사용하며 AI/시계/출력/사진 입력만 대체한다. 완성된 JSON을 보내기만 하는 도구는 1차 연결 확인용이고 SDK 인수를 대신하지 않는다.

| 진행 단계 | 백엔드가 만드는 산출물 |
| --- | --- |
| 1 계약 고정 | 04의 정상·보류·종료·중복·명령 예제와 기대 DB/웹 상태. schema2를 유지하며 장치·서버의 해석 일치. |
| 2 서버 기반 | 등록·계정·브로커 인증·ACL, 메시지 수신·DB·ACK, REST·SSE·사진 API·명령 outbox. |
| 3 SDK와 대역 | 시간·출력·사진·AI 상태를 주입하는 가상 장치. 동일 SDK·SQLite·재시도 경로로 테스트. |
| 4 장애 검증 | 단절·재연결·저장 실패·ACK 유실·중복·역순·만료·재시작과 늦은 사진을 재현. |
| 5 운영 환경 | HTTPS·배포 설정·영속 볼륨·Actuator·로그·백업/복구. 백엔드 담당자가 접속 정보와 인수 절차 제공. |
| 6 화면 연동 | 프론트 담당자에게 API·SSE 예제와 테스트 계정 제공. 화면 제작은 프론트가 수행하고 백엔드가 통합 결과 확인. |

시험은 별도 개발 환경·자격증명·등록 ID로 구분한다. 테스트 데이터임을 실행 설정·로그·보고서에 표시하고 실제 사건 데이터와 섞지 않는다. 구분용 임의 필드를 외부 JSON에 추가하지 않는다.

보드가 없으면 판정 정확도, SNPE 실행 성능, 카메라 지연, 실제 소리·LED·배선은 검증할 수 없다. PC용 모의 어댑터의 성공은 소프트웨어 계약 검증 결과로만 기록한다.
