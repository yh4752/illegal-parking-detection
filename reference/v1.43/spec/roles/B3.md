# B3 저장·명령·출력의 책임이 어긋나지 않는 규칙

원문: `06_역할분담과_보드없는_개발명세_v1.42.docx` / B3 저장·명령·출력의 책임이 어긋나지 않는 규칙

문서 번호·이전 파일명은 [절별 위치 안내](../README.md)에서 찾는다. 표와 설명의 조건을 함께 적용한다.

| 구분 | 개발 기준 |
| --- | --- |
| 상태·outbox 원자 저장 | SDK가 로컬 DB의 단일 쓰기 경계를 소유. AI checkpoint·사건·횟수·메시지·사진 작업 의도를 같은 트랜잭션으로 커밋. |
| 멱등 호출 | operation_id는 재시도 때 유지. 같은 요청은 원래 결과, 다른 내용은 충돌. 중복 응답을 새 재생 허가로 사용하지 않음. |
| 현장 출력 | 새 play는 로컬 COMMITTED 뒤 최신 조건을 재검사하고 실행. 안전 stop·LED off는 저장 장애에도 우선 수행. 적용 성공 회신은 실행 확인·상태 영속화 후 전송. |
| 관리자 명령 | SDK는 수신·중복·전달, AI는 조건·실행 담당. 재개·종료는 선저장, 즉시 안전 중단은 예외. 전달만으로 APPLIED 생성 금지. 상세 순서는 08 D3. |
| 제어 우선 | 네트워크·사진 업로드는 별도 worker. 이 작업이 AI의 이동·STOP 처리나 출력 중단을 기다리게 하지 않음. |
| 장애 처리 | 로컬 필수 상태 저장 실패는 새 안내 금지·AI 출력 중단 경로로 전달. 사진만 실패한 경우는 안내·사건 종료 유지. |

## 관측의 신선도

SDK가 마지막 snapshot을 받았더라도 실제 observed_at을 현재 시각으로 바꾸거나 정차시간을 임의 누적하지 않는다. heartbeat는 통신 생존을 뜻하며 영상의 정상 동작까지 보증하지 않는다. AI의 프레임/제어 감시와 A3의 FRAME_STALE·NO_FRAME 처리를 연결한다.

## 기존 기준 유지

첫 안내는 유효 후보 300초, 재안내는 현재 유효 후보 300초와 직전 종료 후 최소 30초를 함께 충족하며 사건당 최대 2회다. 미해소는 최초 후보 시작에 고정된 600초다. C1~C17·A1~A6의 시각·명령·중지 규칙을 유지한다.
