개발 담당과 코드 실행 위치. 장치 SDK는 백엔드가 작성하고 AI가 실제 보드에 연결한다.

· Data·AI·백엔드·프론트의 기존 역할을 실행 위치와 함께 정리했다.

· SDK 언어·바인딩과 실제 보드 지원은 환경 확인 후 확정한다.

팀은 Data·AI·백엔드·프론트 각 1명으로 구성한다. 백엔드는 보드 없이 개발할 수 있는 소프트웨어와 연동을 주도한다. AI는 실제 보드 OS, 카메라, 모델, 배선, 출력과 설치를 맡는다. 프론트는 관리자 화면을 구현한다. 코드 작성 담당과 실행 위치는 구분한다.

| 담당 | 책임과 인계 산출물 |
| --- | --- |
| Data | 영상 수집·정제·라벨·분할·정답·평가표. 실시간 MQTT 메시지 생성은 담당하지 않음. |
| AI | 보드 환경·모델·탐지·추적·품질·정차·출력. SDK의 플랫폼 어댑터·결합·실보드 인수. |
| 백엔드 | 공통 계약·보드용 통신/저장 SDK·가상 장치·브로커·Spring 서버·API·배포·모니터링·통합 시험. |
| 프론트 | React 관리자 웹, REST/SSE 연결, 설정·제어 요청과 결과·최신성 표시. |

## 엣지 안에서 실행되는 두 모듈

AI 모듈은 무엇을 관측했고 언제 안내할지 결정한다. 백엔드가 작성한 통신 SDK는 같은 보드에서 상태·메시지를 저장하고 외부와 통신한다. 기본은 동일 프로세스 내 호출이며 네트워크 서비스나 별도 IPC를 새로 만들지 않는다.

보드용 SDK는 서버의 Kotlin과 다른 언어로 구현할 수 있다. AI가 W01에서 실제 OS·ABI·런타임·TLS/SQLite 지원을 확인한 뒤 백엔드와 바인딩을 정한다. 특정 Python 버전의 지원 여부와 C++ 빌드 가능 여부는 보드에서 검증한다.

## 개발 소유권

백엔드는 SDK 코어·저장소·통신·가상 장치 코드를 관리한다. AI는 보드 빌드·카메라/시계/출력 바인딩과 AI 제어 코드를 관리한다. 문제 발생 시 AI가 실보드 로그를 제공하고 원인 모듈 담당자가 수정한다. 보드 호환 확인이 늦어도 서버·공통 예제·가상 장치 작업은 진행한다.

접속·재전송·큐·DB·정식 Schema의 구현 세부 기준은 08 상세 설계서와 개발자료/09_구현설계에 추가했다. SDK의 실제 구현 언어·보드 바인딩은 환경 확인 후 확정한다.
