문서 번호·이전 파일명은 [절별 위치 안내](../README.md)에서 찾는다. 표와 설명의 조건을 함께 적용한다.

| 담당 / 작업 | 인계물과 완료 조건 |
| --- | --- |
| 백엔드 W13 | SDK·가상 장치·설정 예제·라이브러리 버전·재현 명령·로그. BC01~BC05 PC 시험 후 AI에 전달. 비밀값은 예제/ZIP에서 제외. |
| AI W01·W03·W04 | QCS610 세부 환경표·플랫폼 어댑터·판단/출력 구현·설치 절차. SDK를 보드에 연결하고 BC06 로그와 실제 출력 검증 제공. |
| Data W14·W11 | 출처/사용권·라벨 규칙·분할 목록·개발 10건·최종 120건 계획·정답·평가표. 실제 촬영과 평가 분모를 관리. |
| 프론트 W07 | REST/SSE·명령·사진·권한 상태별 화면. 접수와 적용을 구별하고 최신 상태가 과거로 회귀하지 않음을 확인. |

| 시험 | 통과해야 하는 동작 |
| --- | --- |
| BC01 | 같은 SDK로 사건·heartbeat·사진·명령 결과를 송수신 |
| BC02 | 로컬 커밋 전/후 종료, 서버 ACK 유실, 같은 operation_id 및 message_id 재시도 |
| BC03 | 늦은 RESUME, 중복 STOP, 실행 회신 누락, 만료·다른 사건 명령 |
| BC04 | JPEG 업로드 실패·지연, 오래된 관측 snapshot과 새 heartbeat |
| BC05 | 브로커 차단·사진 지연·SDK 저장 불가 중 모의 이동/STOP 입력 |
| BC06 | 동일 SDK를 보드 런타임에 연결해 TLS·사진·명령·재시작·출력 및 저장 검증 |

기존 TC01~TC24와 OP01~OP05의 기준은 유지한다. BC 시험은 SDK 경계와 보드 없는 개발의 추가 인수다. 완료 증거에는 입력 버전·실행 환경·기대값·실제값·로그·실패/재시험을 기록한다.

D+2 계약·업무량, D+5 보드 지원표, D+7 PC 기본 흐름, D+10 가상 명령 왕복, D+14 보드 통신 중간 인수, D+21 BC06 완료를 잠정 목표로 둔다. W14는 D+28 평가 계획 고정, D+35 평가 전 실차 자료·정답 인수를 목표로 한다.
