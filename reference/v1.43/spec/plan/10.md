# 10 배포·모니터링 작업과 운영 인수

> v1.43 개발 AI 상세 명세 · v1.42 본문 이관 · 구현·실차 시험 전

원문: `03_개발과_검증계획서_v1.42.docx` / 10 배포·모니터링 작업과 운영 인수

문서 번호·이전 파일명은 [절별 위치 안내](../README.md)에서 찾는다. 표와 설명의 조건을 함께 적용한다.

C14~C17을 구현할 작업을 기존 W05·W06·W08·W09에 연결한다. 아래는 추가 운영 인수 항목이며 기존 TC01~TC24와 실차 성능 시험을 대체하지 않는다. D 기준 목표는 유지하되 팀 가용시간을 확인해 조정한다.

| 항목 | 설계 기준 |
| --- | --- |
| D+2 계약 확인 | 백엔드: SDK·가상 메시지·API·자격증명 기준. AI: 입력·상태·보드 연결 검토. Data: 시험 정답, 프론트: 표시 계약. |
| D+7 기본 연동 | Compose의 DB·브로커·서버와 가상 장치 연결. 사건 수신→DB→REST/SSE와 중복 방지 확인. |
| D+14 배포 기준 | AI가 보드에 SDK와 플랫폼 어댑터를 설치·실행. 백엔드가 TLS·사진·명령 왕복을 인수하고 서버 주소·인증서·비밀값을 제공. 미확인 항목은 실패 로그와 재시험일 기록. |
| D+21 장애 인수 | OP01~OP05와 기존 관련 TC를 실행하고 결과·로그·실패·재시험 기록. 필요한 지표를 그래프로 확인. |

| 시험 상황 | 완료 근거 |
| --- | --- |
| OP01 DB 쓰기 실패 및 커밋 후 ACK 유실 | 저장 전 성공 ACK 없음. 복구·재전송 후 사건은 한 건이고 STORED/DUPLICATE를 정확히 회신. |
| OP02 브로커 차단과 재연결, 과거 사건 재전송 | 관리 조회 유지, MQTT 이상과 장치 최신성 구분. 과거 events로 ONLINE이 되지 않음. 명령은 기한과 미확인 표시 준수. |
| OP03 프록시 경유 SSE·느린 연결·서버 재시작 | 프록시가 SSE를 일괄 버퍼링하지 않고 이벤트별 전달. 느린 연결이 장치 처리를 막지 않음. 재로그인·SSE/REST 복구 뒤 최신 revision 표시. |
| OP04 컨테이너 재생성·권한·설정·영속 볼륨·코드 롤백 | DB·사진 유지. 공개 API의 세션·CSRF·권한 준수. DB/Actuator 외부 비공개. 미확인 명령 복구. 호환 스키마에서만 롤백. |
| OP05 장치 저장 이상·로그 상관관계·격리 백업 복원 | storage_ok=false와 관련 장애 표시. ID로 수신~저장~명령 추적, 비밀값 미노출. 복원 데이터·보관기한·상태 대조 및 웹 재초기화 절차 기록. |

명령 TTL 60초+결과 유예 5초, heartbeat 5초/STALE 15초 초과/OFFLINE 30초 초과는 기존 계약값이다. MQTT 단절 30초 알림과 SSE keepalive 15초·프록시 유휴 60초는 배포 초기값이다. 설정 출처를 구별해 기록한다.

추가 학습과 운영 작업을 고려하면 D+42는 잠정 목표다. 실제 주당 투입시간과 제출일을 확인한 뒤 일정을 조정한다. 시간이 부족하면 추가 통계와 대시보드 장식을 줄인다. 중지·복구·실차 검증은 완료 여부를 별도로 확인해 보고한다.
