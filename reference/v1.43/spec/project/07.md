그림 F15. 모의 구역과 이탈 관찰 영역

텍스트 도식: [F15](../../architecture/F15.mmd). 그림별 조건은 [아키텍처 안내](../../architecture/README.md)를 함께 확인한다.

현장 관찰 범위를 설명하는 개념도다. 실제 카메라 시야, ROI와 이탈 영역은 장소 선정과 보정 후 확정한다. 그림은 실제 설치 사진이나 실험 결과가 아니다.

· 번호판 인식 없이 차량의 관측과 동일성으로 사건을 관리한다.

· 출력 장치의 배선·인터페이스는 실제 보드 점검 후 결정한다.

그림 F06. 첫 안내·재안내·미해소는 서로 다른 시계다

텍스트 도식: [F06](../../architecture/F06.mmd). 그림별 조건은 [아키텍처 안내](../../architecture/README.md)를 함께 확인한다.

세 시간 기준은 시작점과 목적이 다르다. 첫 안내는 유효 정차 후보 300초, 재안내는 첫 음성 종료 후 30초 이상과 현재 후보 300초를 모두 요구한다. 미해소는 최초 확인 후보 시작으로부터 600초이며 법적 위반 확정 기준이 아니다.

· 재생 직전에도 관측·동일성·품질·중지·출력·시각 조건을 다시 검사한다.

· 600초 경계에서는 새 안내보다 미해소 처리를 우선한다.

## 일반 차량이 제한 구역에 멈춘 상황

| 시점 | 관찰과 동작 | 관리자가 보는 기록 |
| --- | --- | --- |
| 진입 | 차량을 발견하고 임시 추적 번호 부여<br>구역 안 위치와 움직임 관찰 | 구역 점유, 관찰 중 |
| 정차 후 5분 | 정상 영상에서 정차가 이어지면<br>LED와 첫 음성 안내 | 안내 시작, 시각과 적용 규칙 |
| 첫 재생 종료 후 30초 이상 | 현재 정차도 연속 300초 이상이고<br>판단이 유효하면 1회 더 안내 | 누적 안내 2회 |
| 정차 시작 후 10분 | 관리자 확인 요청·새 자동 안내 금지<br>기준은 최초 정차 후보 시작<br>10분은 법정값이 아닌 운영 초기값 | 장기 미해소 |
| 구역 밖 이동 후 3초 | 동일 차량이 구역 밖으로 나간<br>상태가 확인되면 종료 | 관찰된 이탈, 점유시간 |

안내 문구는 “이곳은 주정차 제한 구역입니다. 차량을 안전하게 이동해 주세요”로 한다. 차량 용도 추정이 틀릴 수 있으므로 특정 택시나 업체를 지목하지 않는다. 재생 요청과 재생 프로그램의 완료 응답을 구분해 기록한다. 실제 스피커 출력은 현장 시험으로 확인하며, 프로그램 완료만으로 스피커의 고장까지 판단하지 않는다.

## 차량 유형과 운영 상황이 달라질 때

| 상황 | 이번 시스템의 처리 |
| --- | --- |
| 택시가 20초 뒤 출발 | 300초 기준에 도달하지 않아 음성 안내 없음<br>법적으로 허용된 정차라고 판정한 것은 아님 |
| 배송차량이 계속 정차 | 첫 안내 종료 후 30초 이상 경과하고 현재 정차도 300초 이상이면 재안내<br>배송 로고만으로 면제하지 않음 |
| 관리자가 하역 작업 확인 | 현재 사건에 안내 중지 사유와 만료시각 등록<br>장치 적용 회신 후 중지 완료로 표시 |
| 학원차량 조건부 허용 시험 | 모의 허용 구역·시간·관리자 확인 조건이 맞을 때만 보류<br>실제 지자체 30분 기준을 우리 기본값으로 복사하지 않음 |
| 14~16시 사전 공사 | 등록된 구역은 자동 안내 중지, 관찰·기록은 지속<br>종료 예정 시각에 재확인 요청 후 관리자가 재개 |
| 사고나 고장 확인 | 현장 또는 웹에서 안내 중지, 이유와 처리자 기록<br>카메라가 사유를 알아채지 못하면 오안내 가능성은 남음 |

차량 가림과 장치 장애는 9장의 보류 규칙을 우선 적용한다. 관리자 확인 종료는 장치의 적용 회신 후 확정하며, 이후 빈 구역 확인과 명시적 재개 전까지 새 사건을 만들지 않는다. 안내 중지와 차량 이탈은 별개다.
