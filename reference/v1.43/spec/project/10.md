그림 F05. 장치·브라우저·서버의 실제 배치

텍스트 도식: [F05](../../architecture/F05.mmd). 그림별 조건은 [아키텍처 안내](../../architecture/README.md)를 함께 확인한다.

시연 환경을 기준으로 한 배포도다. React는 브라우저에서 실행되며 Nginx는 정적 파일 제공과 API·SSE 프록시를 담당한다. SQLite는 보드에서 사용하는 내장 저장소다.

· 서버와 브로커를 같은 호스트에 두지만 서로 다른 프로그램으로 실행한다.

· 단일 호스트 구조이므로 고가용성·무중단 배포를 보장하지 않는다.

구성도는 보는 범위에 따라 나누어 읽는다. C4의 컨테이너는 애플리케이션이나 저장소를 뜻하며 Docker 컨테이너와 같은 개념은 아니다.

## 시연 환경에서의 배치

Spring 서버는 HTTP·MQTT 처리와 배경 작업을 한 애플리케이션으로 구성한다. Docker Compose로 백엔드·브로커·DB·웹을 한 대의 개발 PC에 배치한다. 02의 C14~C17에 수신·웹 전달·배포·모니터링을 정한다. 장치만 현장에 두고, 같은 공유기나 실험용 네트워크로 연결한다. 클라우드·별도 GPU 서버를 필수로 두지 않는다. 네트워크 차단 시험은 이 연결을 끊어 수행한다. 보드와 카메라의 전원 장애는 별도의 시험이다.

보드의 정확한 모델과 출력 전기 규격을 확인하기 전에는 보드 입출력 핀이나 LED 배선을 단정하지 않는다. 카메라 확정 시 해상도·시야각·연결·지연을 검증하고, 보드 성능에 맞춰 입력 크기를 결정한다. 장소와 카메라가 바뀌면 위치 보정과 품질 기준을 다시 설정한다.
