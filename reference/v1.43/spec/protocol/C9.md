# C9 데이터 소유권과 장애 복구 및 보관

> v1.43 개발 AI 상세 명세 · v1.42 본문 이관 · 구현·실차 시험 전

원문: `02_통신과_상태_구현명세서_v1.42.docx` / C9 데이터 소유권과 장애 복구 및 보관

문서 번호·이전 파일명은 [절별 위치 안내](../README.md)에서 찾는다. 표와 설명의 조건을 함께 적용한다.

| 저장 대상 | 책임과 핵심 제약 |
| --- | --- |
| device와 zone_view | 등록·현재 snapshot·last_heartbeat·view_revision. device_id 유일 |
| zone_policy | (zone_id,version) 유일. 과거 규칙 불변, 최신본 별도 참조 |
| event와 event_message | event_id 유일. (device_id,message_id) 중복 금지. 사건과 현재 구역 순서 분리 |
| command와 server_outbox | command_id 유일. 요청 저장과 발행 대기 등록을 한 트랜잭션으로 처리 |
| pause와 review | pause_id와 review_id 유일. 사용자 입력은 서버, 실제 중지 적용 상태는 장치가 권위 |
| device_image | image_id 유일, hash 비교. device_id 필수, event_id 선택 |
| 장치 SQLite | device_seq·mode_revision·사건·시도 횟수·중지·규칙·명령 결과·미ACK outbox |

장치 상태 변경과 발송 대기를 함께 저장한 뒤 전송한다. ACK가 없으면 같은 message_id로 재전송하며 음성은 재실행하지 않는다. 서버는 event_id별 사건 순서와 device_id별 현재 snapshot 순서를 각각 검사한다. snapshot의 현재 사건 요약도 해당 event의 최신 상태에 반영한다. 종료 사실은 durable events로 남기며 종료 사건을 늦은 과거 상태로 다시 열지 않는다.

장치 재시작은 기존 사건·횟수·중지·발송 대기를 복원하지만 정차 연속시간은 0으로 만든다. RESTART 확인 후 재개한다. 시각은 새 부팅의 동기 근거를 다시 확보하며 미전송 사진의 나이를 복원하지 못하면 사진만 만료한다. 장치 DB 초기화는 관리자 재등록 대상으로 처리한다. 서버 DB 복구 때는 백업 DB 외부에 영속 예약한 revision 상한 다음 범위를 사용하고 웹을 재접속시킨다. 외부 상한을 검증할 수 없으면 자동 복원을 완료 처리하지 않는다. 구체 절차는 08과 09의 DB 설계를 따른다. 순서가 뒤로 가는 상태로 기존 연결에 갱신하지 않는다.

| 자료 | 기한과 삭제 조건 |
| --- | --- |
| 사진 | 신뢰되는 captured_at부터 7일. 시각 불신은 최초 received_at부터 7일. 재업로드로 연장 금지 |
| event_message·review·조작 이력 | 서버 received_at 또는 created_at부터 30일 |
| 종료 event 요약 / command | 신뢰되는 closed_at / 서버 terminal_at부터 30일. 종료 시각 불신은 최초 종료 수신시각 사용 |
| 활성 사건·중지·미ACK 기록 | 운영 최소 상태는 이력 청소로 삭제하지 않음. 사진·불필요한 원문 이력의 기한은 유지 |

삭제 작업은 매일 실행하며 만료 직후 24시간 안에 제거한다. 접근 API는 기한이 지나면 먼저 410을 반환한다. 중복 방지 ID·해시·처리 여부는 원문과 분리한다. 미ACK 사건·명령 결과 outbox는 100 MiB, 미전송 JPEG는 별도 50 MiB 한도다. 사진 한도는 사진만 실패시키며 사건 저장을 막지 않는다. 사건 저장 한도 초과 시 신규 자동 안내를 보류하며 미전송 사건을 임의로 삭제하지 않는다.
