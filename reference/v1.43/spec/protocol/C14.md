그림 F03. Spring 내부의 책임과 호출 관계

텍스트 도식: [F03](../../architecture/F03.mmd). 그림별 조건은 [아키텍처 안내](../../architecture/README.md)를 함께 확인한다.

C4 컴포넌트도다. 저장소 접근, 명령 발행, 사진 처리와 SSE 전달은 하나의 Spring 애플리케이션 안에서 구현한다. 수신 성공 ACK와 SSE는 DB 커밋 후에 전송한다.

· 웹 API·사진 처리·업무 서비스의 세부 호출은 기존 C14~C17과 D5·D6을 따른다.

· 그림의 명칭은 책임 단위이며 클래스나 메서드 이름을 새로 확정한 것은 아니다.

백엔드는 Kotlin + Spring Boot 단일 애플리케이션으로 구현한다. 장치 어댑터·웹 API·업무 서비스·저장소·배경 작업을 분리한다. AI 추론·정차 시간 판단·LED/음성 제어는 엣지가 맡는다. 서버가 원본 영상을 계속 받아 재판정하지 않는다.

| 항목 | 설계 기준 |
| --- | --- |
| HTTP와 권한 | Spring MVC REST + Spring Security. 같은 출처 HTTPS 세션·CSRF·VIEWER/OPERATOR 권한 유지. 장치 사진 업로드에는 웹 세션과 분리한 장치 자격증명을 적용한다. |
| MQTT 입출력 | Spring Integration MQTT 5 어댑터로 TLS 연결한다. Mosquitto ACL이 계정별 허용 토픽을 강제하고, 백엔드는 수신 토픽과 본문의 device_id를 대조한다. MQTT 3 예제를 그대로 복사하지 않는다. |
| DB와 트랜잭션 | PostgreSQL + Spring JDBC로 명시적 SQL을 사용한다. Flyway로 스키마를 관리한다. 서비스 트랜잭션에서 중복 제약·순서 검사·상태 갱신을 함께 처리한다. |
| 웹 실시간 갱신 | SseEmitter로 ZoneView 전체 값을 전달한다. DB 커밋 뒤 발행하며 SSE 실패로 DB 저장을 취소하지 않는다. 접속별 버퍼·실행기는 상한을 두고 느린 연결을 종료한다. |
| 발송·정리 작업 | command와 server_outbox를 같은 트랜잭션에 저장한다. 배경 발행기는 재시작 후 미확인 작업을 복구하고 C4의 기한·결과 기준을 적용한다. 보관 정리는 C9를 따른다. |
| 운영 상태 | Actuator/Micrometer로 HTTP·JVM·DB·MQTT·발송 대기를 관찰한다. 상세 기준은 C17. 관리용 엔드포인트는 일반 웹에 공개하지 않는다. |

## 프레임워크가 대신 보장하지 않는 것

MQTT 콜백·스레드 실행 순서는 업무 순서가 아니다. READ COMMITTED에서 zone_view 행을 SELECT FOR UPDATE로 잠가 동일 구역의 쓰기를 직렬화한다. 네트워크·사진 파일 I/O는 DB 잠금 밖에서 수행한다. 상태와 view_revision 증가는 한 트랜잭션에서 확정한다. @Transactional 메서드는 프록시를 통하는 서비스 경계에 두며 자기 호출에 의존하지 않는다.

Kotlin DTO와 Jackson 설정에서 필수값·null·빈 배열·0·false를 구별하고 C1의 타입·범위·상태값을 검증한다. 라이브러리 버전은 착수 시 Gradle 의존성과 실행 이미지에 고정한다. 기본 세션은 단일 서버 메모리로 두며 서버 재시작 후 재로그인한다. 운영 기록과 명령은 DB에 남는다.
