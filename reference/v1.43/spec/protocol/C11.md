# C11 자동 사진과 실패를 분리하는 업로드

> v1.43 개발 AI 상세 명세 · v1.42 본문 이관 · 구현·실차 시험 전

원문: `02_통신과_상태_구현명세서_v1.42.docx` / C11 자동 사진과 실패를 분리하는 업로드

문서 번호·이전 파일명은 [절별 위치 안내](../README.md)에서 찾는다. 표와 설명의 조건을 함께 적용한다.

사진은 사건의 상황을 확인하는 기록이다. 첫 안내 시도 직전 FIRST_GUIDANCE 1장, 사건 종료 때 EVENT_CLOSE 1장을 예약한다. 안내를 시작하지 않은 사건에는 첫 안내 사진이 없다. 재안내 때 추가 촬영하지 않으며 사진 실패로 안내·횟수·종료를 되돌리지 않는다.

| 사진 종류 | 생성과 의미 |
| --- | --- |
| FIRST_GUIDANCE | 첫 시도·횟수와 작업 ID를 함께 저장 → 현재 유효 프레임 참조를 확보 → 출력을 진행. 인코딩·저장·전송을 기다리지 않음 |
| EVENT_CLOSE | 자연 종료는 현재 정상 영상(빈 구역 가능). 화질 불량은 FAILED/NO_VALID_FRAME. 수동 종료는 CLOSE_CONFIRM 원본을 새 image_id로 재사용하며 촬영시각·해시는 유지 |
| VIEW / RESUME_CONFIRM<br>CLOSE_CONFIRM | 요청 purpose VIEW / RESUME / CLOSE_EVENT와 대응. 제어 토큰은 뒤의 두 확인사진에만 발급(C6) |

JPEG는 긴 변 최대 1280 px, 종횡비 유지·확대 금지, quality 80, 최대 5 MiB의 고정 프로파일이다. worker는 1개, 대기는 2개까지며 초과 시 새 사진만 FAILED/QUEUE_FULL이다. 미전송 JPEG 50 MiB와 사건 outbox 100 MiB는 별도다. 사진 한도 초과는 IMAGE_STORAGE_FULL이고 사건을 지우지 않는다.

| 상태 | 서버·화면 처리 |
| --- | --- |
| PENDING | 작업이 있으나 조회할 파일은 없음. image_update로 전달 |
| AVAILABLE | HTTPS 201/200으로 서버 저장 확인. 늦은 실패·대기 메시지로 회귀 금지 |
| FAILED | 촬영·인코딩·용량·HTTP 4xx(408/429 제외) 실패. 같은 자동사진 대체 촬영 금지 |
| EXPIRED | 전송 24시간 경과 또는 재부팅 후 생성 나이 불명확. 저장본은 7일 보관 만료. 최소 메타는 남김 |

재시도 간격은 1·2·4·8·16초 뒤 최대 30초 반복이다. network·408·429·5xx만 재시도하며 유효 Retry-After는 최대 120초까지 반영한다. image_id·해시·원본은 고정한다. 24시간은 단조 시간으로 재고 재부팅 후 신뢰 UTC로 복원하지 못하면 AGE_UNKNOWN 만료다. 서버 저장 성공 후 로컬 bytes를 지운다.

IMAGE_STATUS_CHANGED는 event=null, image_update=사진 상태이며 다른 events는 image_update=null이다. 과거 사진의 event_id와 현재 snapshot 사건이 달라도 된다. ImageRef의 received_at은 첫 수신시각, expires_at은 파일이 없으면 null이다. 촬영 원본의 보관기한은 재사용·재전송으로 연장하지 않는다.
