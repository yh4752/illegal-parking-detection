문서 번호·이전 파일명은 [절별 위치 안내](../README.md)에서 찾는다. 표와 설명의 조건을 함께 적용한다.

서비스 운영 화면은 사건·장치·명령을 보여주고, 개발 운영 지표는 서버·DB·통신의 건강 상태를 보여준다. Actuator와 구조화 로그는 필수다. 지표 시각화는 Prometheus·Grafana를 Compose 모니터링 프로필로 붙이되 서비스 핵심 연동의 선행 조건으로 두지 않는다.

| 항목 | 설계 기준 |
| --- | --- |
| 서버와 DB | liveness는 프로세스 내부 생존이며 DB·MQTT 장애를 포함하지 않는다. readiness는 기동과 DB 처리 가능 여부를 검사한다. DB 장애 시 저장·제어 요청에 성공을 반환하지 않는다. |
| 브로커 연결 | MQTT 연결/구독 상태와 재연결 횟수를 기록한다. 단절은 운영상 성능 저하로 별도 표시하고 관리자 조회까지 차단하지 않는다. 메시지 저장·명령 결과가 지연될 수 있음을 알린다. |
| 장치와 처리 | heartbeat 경과시간·STALE/OFFLINE, fps·pending_message_count·storage_ok를 기록한다. 사건 수신 STORED/DUPLICATE/REJECTED, DB 저장 실패, 수신부터 커밋까지 지연을 측정한다. |
| 명령과 SSE | server_outbox 개수·최고 대기시간, 명령 결과별 건수·DELIVERY_TIMEOUT, SSE 연결 수·전송 실패·느린 연결 종료 수를 기록한다. 성공 여부는 장치 결과와 구분한다. |
| 사진과 자원 | 사진 업로드 실패·PENDING 체류, JVM heap·GC·HTTP 오류/지연·DB 연결 풀·호스트 디스크를 관찰한다. 저장 공간 부족과 사진 실패를 사건 처리 실패와 구분한다. |
| 로그와 접근 | 구조화 로그에 request_id·device_id·message_id·event_id·command_id와 처리 결과를 필요에 따라 기록한다. 사진 원본·비밀번호·세션·확인 토큰은 제외한다. 사건 ID는 지표 라벨로 쓰지 않는다. |

## 알림 기준과 담당자의 행동

장치 OFFLINE은 기존 30초 기준을 따른다. 운영 초기 알림은 MQTT 단절 30초 지속, DB 저장 오류 발생, 명령 DELIVERY_TIMEOUT 발생, storage_ok=false로 정한다. 각 항목은 중복 알림을 묶고 복구를 표시한다. 추가 임계값은 측정 후 정하며 실제 성능 결과로 쓰지 않는다.

백엔드는 SDK·DB·브로커·발송 대기·SSE 로그를, AI는 보드 OS·카메라·출력·플랫폼 어댑터를, 프론트는 화면 연결·최신성을 점검한다. Data는 시험 입력과 정답을 추적한다. 같은 호스트 전체 장애는 외부 PC에서 확인하며 외부 알림 채널·24시간 운영은 필수 범위가 아니다.
