# C10 공통 예제로 확인할 통합 동작

> v1.43 개발 AI 상세 명세 · v1.42 본문 이관 · 구현·실차 시험 전

원문: `02_통신과_상태_구현명세서_v1.42.docx` / C10 공통 예제로 확인할 통합 동작

문서 번호·이전 파일명은 [절별 위치 안내](../README.md)에서 찾는다. 표와 설명의 조건을 함께 적용한다.

이 예제는 설계 기준이며 실행 결과가 아니다. 개발자는 동봉 계약 데이터의 예제 객체를 같은 입력으로 사용한다. 사건 이력 event와 현재 snapshot을 별도 저장하므로, 과거 기록의 복구가 현재 차량과 화면을 바꾸지 않아야 한다.

| 입력 순서 | 장치와 서버의 기대 결과 |
| --- | --- |
| 진입 e1 → 정차 → 안내 | e1 유지, 시도 선저장 후 guidance_count=1. 종료 전 새 사건 생성 금지 |
| 안내 완료 m10을 두 번 전달 | event_message 1건. 두 번째 ACK DUPLICATE. 음성 추가 실행 없음 |
| snapshot device_seq=12 후 10 도착 | 현재 snapshot은 12 유지. m10 과거 이력만 중복 없이 저장 |
| 서버 view_revision=8 SSE 후 7 REST | 프론트는 8 유지. 늦은 조회 응답으로 화면 회귀 금지 |
| e1의 정책 3 중 시간 규칙 4 도착 | received=4, active=3, event=3. e1 종료 후 다음 사건에 4 적용 |
| 공사 p1·사고 p2 중 p2만 해제 | p1은 ACTIVE 유지. 결과 APPLIED여도 mode는 PAUSED |
| 사진 발급 후 새 중지 발생 | mode_revision 증가와 토큰 폐기. 이전 재개는 MODE_CHANGED |
| e1 관리자 확인 종료 후 차량 잔류 | e1 CLOSED_MANUAL, REARM_REQUIRED. 새 사건과 추가 안내 없음 |
| 빈 구역 3초 확인 후 새 사진·재개 | 재감시 중지만 해제. 다른 중지가 없을 때 다음 진입부터 새 사건 |

## 최소 명령 결과 예시

{
  "command_id": "cmd-002", "result": "APPLIED",
  "error_code": null,
  "result_data": {
    "pause_ids": ["p2"], "image_id": null,
    "confirmation_token": null, "token_valid_for_ms": null,
    "closed_event_id": null
  }
}

위는 command-results의 업무 부분만 보여 준 예시다. 실제 전송에는 C1의 envelope와 전체 snapshot을 포함한다. APPLIED는 요청한 p2 해제가 적용됐다는 뜻이며 모든 중지가 사라졌다는 뜻이 아니다. 화면은 result와 최종 mode·남은 pauses를 함께 읽는다.

장치 결과가 없으면 “성공”으로 가정하지 않는다. 동일 명령을 중복 전달해도 시도 횟수가 증가하지 않는지, 사진 토큰의 목적·사건·세대가 맞는지, UI의 수동 용도 값이 장치 추정에 덮이지 않는지까지 첫 통합 시험에서 확인한다.
