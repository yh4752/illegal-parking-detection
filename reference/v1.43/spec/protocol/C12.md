# C12 시각 신뢰와 오프라인 운영

> v1.43 개발 AI 상세 명세 · v1.42 본문 이관 · 구현·실차 시험 전

원문: `02_통신과_상태_구현명세서_v1.42.docx` / C12 시각 신뢰와 오프라인 운영

문서 번호·이전 파일명은 [절별 위치 안내](../README.md)에서 찾는다. 표와 설명의 조건을 함께 적용한다.

UTC는 기록·예약에, 단조 시간은 정차·재시도·토큰 유효시간에 사용한다. 네트워크 단절만으로 현장 판단을 멈추지는 않는다. 다만 예약과 오래된 명령을 안전하게 구별할 시각 근거가 사라지면 자동 안내를 보류한다. 아래 수치는 초기 운영값이며 실제 시계 정확도를 보증하는 측정 결과가 아니다.

| 시각 상태 | 판정 조건 |
| --- | --- |
| SYNCED | 5초마다 Linux chrony tracking 조회. Leap Normal, stratum 1~15, 외부 동기원, E≤1000 ms, 최근 동기≤300초 |
| HOLDOVER | 같은 부팅의 이전 동기 근거가 있고 데몬의 현재 오차 추정이 유효. E≤1000 ms, 최근 동기≤1800초 |
| UNTRUSTED | 위 조건 불충족, 조회 실패가 10초 이상, 또는 UTC 경과와 단조 경과 차이 변화가 500 ms 초과. 점프 후 새 외부 동기 필요 |

E=|System time|+Root dispersion+max(Root delay,0)/2를 ms로 바꾸어 올림한다. OS가 다르면 동등한 근거를 제공하는 어댑터를 사용한다. 단순 네트워크 연결·NTP 실행만으로 true를 보내지 않는다. 동기 나이는 실제 외부 동기 때만 갱신하며 조회 때마다 0으로 만들지 않는다.

| 필드·동작 | 계약 |
| --- | --- |
| snapshot.clock_status | state, error_bound_ms, last_sync_at, sync_age_ms. 근거 없는 수치는 null. clock_synced=true는 SYNCED/HOLDOVER만 |
| 불신·회복 | CLOCK_UNTRUSTED 표시, 신규·진행 안내 보류, continuous_stop_ms=0. 새 pause는 만들지 않음. 신뢰 5초 연속 회복 후 다시 정차 300초; 기존 중지는 유지 |
| 예약·운영시간 | now±E가 중지 구간과 겹치면 중지. 운영 허용은 신뢰구간 전체가 허용 시간 안일 때. 연속 24시간은 자정에 끊지 않음 |
| 명령·서버 | 즉시 STOP 외에는 now+E+1000 ms < expires_at. 서버 불신이면 신규 제어·예약 보류. 즉시 STOP은 서버 단조 60초·MQTT TTL>0 예외; 예약 STOP 제외 |

시각 불신의 촬영·관측·발생 시각은 null이며 서버 received_at을 별도로 남긴다. VIEW를 포함한 새 사진 명령과 제어 토큰은 허용하지 않는다. null 촬영시각은 자동 종료·기존 이력사진에만 남을 수 있다. 기존 기록의 시각을 나중에 덮어쓰지 않는다. 웹은 mode가 AUTO여도 CLOCK_UNTRUSTED 조건이면 자동 안내 불가 상태를 표시한다. 저장된 정책·중지·사건·횟수는 시각 복구로 초기화하지 않는다.

시간 원리 참고: chrony tracking의 오차 추정식 https://chrony-project.org/doc/4.7/chronyc.html · 단조시계 https://docs.python.org/3/library/time.html#time.monotonic . 동기화 5분·유지 30분·오차 1초는 공식 권장치가 아닌 팀의 운영 초기값이다.
