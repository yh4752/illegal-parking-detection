# C13 최초 등록과 정책 설치 순서

> v1.43 개발 AI 상세 명세 · v1.42 본문 이관 · 구현·실차 시험 전

원문: `02_통신과_상태_구현명세서_v1.42.docx` / C13 최초 등록과 정책 설치 순서

문서 번호·이전 파일명은 [절별 위치 안내](../README.md)에서 찾는다. 표와 설명의 조건을 함께 적용한다.

첫 개발은 1개 구역·1개 장치로 시작한다. 백엔드가 등록·자격증명·통신 SDK를 준비하고 AI가 실제 보드 설정·연결·현장 적용을 맡는다. QCS610 플랫폼은 확인되었으며 세부 OS·ABI·입출력 규격은 W01에서 기록한다. 보드 없는 개발은 06의 B4를 따른다.

| 순서·담당 | 입력과 완료 기준 |
| --- | --- |
| 1 백엔드 등록 | zone_id·device_id 및 VIEWER/OPERATOR 계정 seed. 같은 ID 재실행은 중복 생성·묵시 덮어쓰기 금지 |
| 2 백엔드 제공 / AI 설치 | 백엔드가 MQTT-TLS/HTTPS 주소·ID·CA·장치별 자격증명과 SDK 설정 예제를 제공. AI가 보드에 안전하게 설치하고 자기 토픽·업로드 접근 확인. |
| 3 AI 현장 입력 | 측정한 ROI·출구 다각형·기준점·calibration_id 및 vision_profile_id와 보정 결과 JSON 제공 |
| 4 정책 검증·저장 | 백엔드가 기존 Policy 형식·도형·기준점·프로파일 참조를 검증. 기존 PUT 정책 API 사용; 최초 expected_version=0, 서버 version=1 |
| 5 현장 적용 | RECONFIGURE를 유지한 채 현장 apply-policy(version). 보정·품질 설정 일치 확인 후 활성화; 웹 재개가 대신하지 않음 |
| 6 운영 진입 | 정상 영상의 빈 구역 3초 → 새 RESUME 사진 → 지정 중지 명시 해제. 시각·화질·남은 중지 조건까지 충족해야 자동 운영 |

관리자 화면은 정책 JSON 업로드·미리보기·검증 결과와 저장을 제공한다. 자유롭게 ROI를 그리는 편집기는 필수 범위에서 제외한다. 업로드 파일은 기존 Policy 필드만 사용하고 버전은 서버가 부여한다. 실제 현장 측정값은 AI가 채우며, 계약의 정책 3→4 예제는 변경 동작을 보여 주는 가상 값이다.

AI는 실제 관측·사건 상태·출력 결과와 플랫폼 어댑터를 제공한다. 백엔드의 장치 통신 SDK가 JSON·메타데이터·로컬 영속화·전송을 담당한다. Data는 자료·정답·평가, 프론트는 화면을 맡는다. 같은 프로세스에서 결합하는 내부 호출 계약은 06과 07에 정한다.

등록된 ID, 보정·프로파일, TLS·권한, 시각 신뢰 중 하나라도 준비되지 않으면 초기 안내를 허용하지 않는다. 최초 설치도 RECONFIGURE → 현장 적용 → 빈 구역 확인 → 새 사진 → 명시 재개를 따른다. 비밀값을 계약 JSON·Git·배포 ZIP에 넣지 않는다.
