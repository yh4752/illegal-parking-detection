# C7 REST API 요청과 응답

> v1.43 개발 AI 상세 명세 · v1.42 본문 이관 · 구현·실차 시험 전

원문: `02_통신과_상태_구현명세서_v1.42.docx` / C7 REST API 요청과 응답

문서 번호·이전 파일명은 [절별 위치 안내](../README.md)에서 찾는다. 표와 설명의 조건을 함께 적용한다.

주소의 id는 인증 사용자가 접근할 수 있는 등록 장치·구역·사건인지 검사한다. 조회는 VIEWER와 OPERATOR, 변경과 제어는 OPERATOR만 허용한다. 장치 업로드는 웹 세션 대신 별도의 장치 자격증명을 사용한다. 표의 요청·응답 객체의 전체 필드 정의는 함께 제공하는 계약 데이터에 고정한다.

| API | 요청 | 성공 응답 |
| --- | --- | --- |
| GET /api/csrf | 없음 | 200 {token} |
| POST /api/auth/login<br>POST /api/auth/logout | username,password / 없음<br>CSRF 헤더 | 200 {user_id,role} / 204 |
| GET /api/auth/me | 없음 | 200 {user_id,role} |
| GET /api/zones/{id}/status | 없음 | 200 ZoneView 전체 상태 |
| GET /api/events | zone_id, from, to, state, cursor, limit | 200 {items,next_cursor} |
| GET /api/events/{id} | 없음 | 200 EventDetail |
| GET /api/zones/{id}/policy | 없음 | 200 {latest_policy,device_versions} |
| PUT /api/zones/{id}/policy | expected_version, policy, reason | 200 {version,delivery_status} |
| POST /api/devices/{id}/commands | client_request_id, type, scope,<br>target_event_id, 기대값, token, params | 202 {command_id,status,expires_at} |
| GET /api/commands/{id} | 없음 | 200 접수 상태·장치 결과·시각 |
| POST /api/events/{id}/reviews | client_request_id, note, use_type<br>use_type는 수정 없으면 null | 201 {review_id,manual_use_type} |
| POST /api/devices/{id}/images | multipart image와 meta JSON | 201 신규 / 200 동일 재업로드<br>{image_id,stored_at} |
| GET /api/images/{id} | 없음 | 200 image/jpeg / 미저장 404 / 만료 410 |
| GET /api/stream | zone_id | 200 text/event-stream |

목록 limit는 기본 20, 최대 100이다. from 포함·to 제외의 UTC 범위를 사용하며 created_at와 ID 순서의 불투명 cursor를 반환한다. 명령·review의 client_request_id는 사용자별 중복 방지 키다. 같은 키와 같은 본문은 원래 결과, 다른 본문은 409를 반환한다. PUT은 expected_version이 현재 최신본과 다르면 409이며 자동 덮어쓰지 않는다. 보관 만료로 원래 HTTP 자원을 지운 뒤 같은 요청 키가 오면 GONE/410이며 재실행하지 않는다. 즉시 STOP의 REST params.starts_at은 null, MQTT에서는 issued_at과 같은 UTC다. 정식 요청·응답은 09의 OpenAPI를 따른다.

review는 의견과 차량 용도 수동 수정만 수행한다. manual_use_type과 추정 use_type은 별도 필드이며 화면은 수동값이 있으면 이를 우선하고 “관리자 수정”을 표시한다. 이후 장치 추정 갱신이 수동값을 덮어쓰지 않는다. 사건 종료는 반드시 CLOSE_EVENT 명령을 거친다.
