# C5 중지 중첩과 관리자 확인 종료

> v1.43 개발 AI 상세 명세 · v1.42 본문 이관 · 구현·실차 시험 전

원문: `02_통신과_상태_구현명세서_v1.42.docx` / C5 중지 중첩과 관리자 확인 종료

문서 번호·이전 파일명은 [절별 위치 안내](../README.md)에서 찾는다. 표와 설명의 조건을 함께 적용한다.

중지는 pause_id별 기록 집합이다. 필드는 source, scope, target_event_id, starts_at, expires_at, status, reason이다. source는 USER, SCHEDULE, PHYSICAL, RESTART, RECONFIGURE, REARM_REQUIRED, OBSERVATION_REVIEW, OUTPUT_FAULT다. status는 SCHEDULED, ACTIVE, ACK_REQUIRED, CLEARED다. 만료는 ACK_REQUIRED 전환이다.

ACTIVE가 하나라도 있으면 mode=PAUSED, ACTIVE가 없고 ACK_REQUIRED가 있으면 AWAITING_RESUME다. 둘 다 없으면 AUTO이며 관찰 품질 등 별도 조건을 추가 검사한 뒤 안내한다. 아직 시작되지 않은 SCHEDULED는 출력을 막지 않는다. 일정 시각을 신뢰할 수 없으면 시각을 확인할 때까지 해당 일정은 보수적으로 ACTIVE로 처리한다.

| 입력 | 장치의 원자적 처리 |
| --- | --- |
| 새 중지·일정 등록 또는 시작 | 중지 기록 반영, mode_revision 증가, 확인 토큰 폐기, 필요한 출력 중단 |
| RESUME_GUIDANCE | 토큰·기대 버전·중지 세대 검증 후 지정 pause_ids만 CLEARED |
| 중지 만료 | ACK_REQUIRED로 전환, mode_revision 증가. 자동 재개하지 않음 |
| 사건 자연 종료 | 그 사건의 EVENT 중지만 종료 처리. 구역·장치 중지는 유지 |
| 물리 중지 해제 | 현장 확인 절차만 허용. 웹에서 PHYSICAL을 지우지 못함 |

예를 들어 공사 p1과 사고 p2가 함께 적용 중일 때 p2만 재개해도 p1은 유지된다. mode_revision은 중지 집합·상태·대상, 사건 생성·종료, 적용 규칙이 바뀔 때마다 증가한다. 토큰은 이전 세대에서 발급됐으면 거부한다. 처리 중 새 중지가 생길 수 있으므로 검증과 상태 변경을 장치 제어 루프의 한 작업으로 수행한다.

CLOSE_EVENT는 새 사진에 연결된 현재 사건만 CLOSED_MANUAL로 닫는다. 서버의 review 기록만으로 사건을 닫지 않는다. 장치가 사건 종료와 REARM_REQUIRED를 함께 저장하고 결과를 회신한 후 웹이 종료 확정으로 표시한다. 다른 중지는 유지하고 해당 사건에 한정된 중지만 종료 처리한다.

수동 종료 직후에는 차량이 남아 있거나 존재가 불명확하므로 새 사건을 만들지 않는다. 현재 설정의 정상 관측에서 구역이 3초 비어 있음을 확인하고 관리자가 새 사진으로 RESUME을 실행해야 REARM_REQUIRED를 해제한다. 그 뒤에 들어온 차량부터 새 사건이다. 단순 미검출·가림은 빈 구역 확인으로 세지 않는다. 따라서 같은 차량을 닫았다 다시 만들어 안내 횟수를 초기화할 수 없다.

동일성 불명확은 OBSERVATION_REVIEW 중지다. 관리자가 현장·추가 관측으로 같은 차량임을 확인한 경우 RESUME에 identity_confirmed=true와 근거 reason을 넣어 기존 사건·횟수를 유지한다. 확인 불가면 CLOSE 후 재감시한다. 이 확인으로 나쁜 화질을 우회하지 않는다. RESTART는 명시 재개, PHYSICAL·OUTPUT_FAULT는 현장 확인 후 현장 해제만 허용한다.
