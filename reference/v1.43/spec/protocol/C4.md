그림 F08. 관리자 명령의 접수부터 적용 결과까지

텍스트 도식: [F08](../../architecture/F08.mmd). 그림별 조건은 [아키텍처 안내](../../architecture/README.md)를 함께 확인한다.

서버는 명령과 발송 대기를 저장한 뒤 202로 접수를 알린다. SDK와 AI가 명령을 검사하고 적용 결과를 저장·전송하면 서버가 화면을 갱신한다. 60초 기한과 5초 결과 유예까지 결과가 없으면 적용 여부 미확인으로 표시한다.

· 60초 기한 + 결과 유예 5초 뒤 DELIVERY_TIMEOUT: 적용 여부 미확인. 실행 실패 단정 금지.

· 즉시 STOP의 APPLIED는 논리 중지·드라이버 확인·결과 저장이며 실제 무음 보증은 아니다.

· 예약 STOP은 일정 등록 완료다. RESUME 후에도 다른 중지가 남으면 PAUSED를 유지한다.

웹 요청 접수와 장치 적용은 구분한다. 서버는 명령과 발행 대기 기록을 같은 트랜잭션에 저장하고 202 QUEUED를 반환한다. 장치는 명령을 검증하고 적용 또는 거부한 결과를 저장한다. 동일 command_id 재전송은 기존 결과만 회신하며 동작을 반복하지 않는다.

| 모든 명령의 필드 | 형식 |
| --- | --- |
| schema_version / command_id / device_id | 2 / 서버가 발급한 ID / 대상 장치 ID |
| type / scope / target_event_id | 아래 type / DEVICE, ZONE, EVENT / 사건 ID 또는 null |
| issued_at / expires_at | 서버 UTC. 전달 유효기간은 issued_at부터 60초 |
| expected_mode_revision | 음이 아닌 정수 또는 null. STOP·사진 요청은 null 허용 |
| expected_received_policy_version<br>expected_active_policy_version<br>expected_event_policy_version | 기대 버전 정수 또는 null. RESUME·CLOSE는 현재 snapshot과 일치해야 함 |
| confirmation_token / params | 새 사진 확인 토큰 또는 null / type별 객체 |

| type | params와 적용 결과 |
| --- | --- |
| STOP_GUIDANCE | pause_id, starts_at, expires_at, reason. 즉시 또는 미래 구역 일정 등록 |
| RESUME_GUIDANCE | pause_ids, identity_confirmed, reason. 지정한 중지만 해제. 나머지는 유지 |
| REQUEST_SNAPSHOT | purpose VIEW, RESUME, CLOSE_EVENT. 촬영·업로드 완료 후 image_id 반환 |
| CLOSE_EVENT | reason. target_event_id 사건만 관리자 확인 종료. C5 재감시 적용 |

STOP은 DEVICE·ZONE·EVENT, RESUME·사진 요청은 DEVICE, CLOSE는 EVENT 범위다. EVENT 대상은 현재 사건과 일치해야 한다. RESUME의 target_event_id는 토큰의 현재 사건 ID 또는 null이다. STOP은 예상 버전·세대 불일치를 무시하되 잘못된 사건은 거부한다. 즉시 STOP은 starts_at=issued_at, 예약은 starts_at>issued_at·ZONE으로 구별한다. 명령 60초는 등록 전달 기한이며 중지 종료시각과 다르다. REST 입력의 starts_at=null은 즉시 중지이며 서버가 Command.issued_at과 같은 값으로 변환한다. UTC 문자열은 미래 예약이며 과거 예약 시각을 즉시 요청으로 바꾸지 않는다.

장치 result는 APPLIED, REJECTED, EXPIRED, FAILED다. result_data의 미해당 값은 null 또는 []다. 즉시 STOP의 APPLIED는 논리 중지와 드라이버 중단 확인을 뜻하며 실제 스피커 무음 보증은 아니다. 중단 실패면 논리 중지는 유지한 채 FAILED·OUTPUT_FAULT와 output_status=FAILED 또는 UNKNOWN을 보낸다. 미래 일정의 APPLIED는 등록 완료만 뜻한다.

서버나 장치 시각 불신은 RESUME·CLOSE·모든 사진 요청(VIEW 포함)을 CLOCK_UNTRUSTED로 거부한다. 즉시 STOP만 서버 단조 60초 및 MQTT 남은 만료시간 양수로 허용하며, 예약 STOP은 예외가 아니다. 그 외 명령은 수신 now+오차상한+발행 오차여유 1초 < expires_at을 만족해야 한다(C12). 결과가 기한 후 5초까지 없으면 웹은 DELIVERY_TIMEOUT·“적용 여부 미확인”을 표시하고 늦은 실제 결과를 구분해 갱신한다.
