# C1 공통 형식과 장치의 현재 상태

> v1.43 개발 AI 상세 명세 · v1.42 본문 이관 · 구현·실차 시험 전

원문: `02_통신과_상태_구현명세서_v1.42.docx` / C1 공통 형식과 장치의 현재 상태

문서 번호·이전 파일명은 [절별 위치 안내](../README.md)에서 찾는다. 표와 설명의 조건을 함께 적용한다.

이 명세는 장치·백엔드·프론트가 함께 사용하는 v1.41 개발 기준이다. JSON 키는 snake_case이며 schema_version은 2이다. 시간 길이는 정수 ms, 지면 거리는 m, UTC 시각은 ISO 8601의 Z 표기로 통일한다. 시각 동기화가 안 된 관측 시각은 null과 clock_synced=false를 함께 보낸다. 경과·재시도·사진 토큰은 단조 시간으로 계산한다. clock_synced는 C12의 SYNCED 또는 HOLDOVER에서만 true다. v1.4는 계약 필드 확장으로 schema 2와 parking/v2를 사용한다. 아직 구현 전이므로 운영 데이터 이관 없이 개발 예제·입출력을 함께 교체한다.

| 공통 필드 | 형식과 의미 |
| --- | --- |
| schema_version | 정수 2. 지원하지 않는 값은 거부 |
| device_id / zone_id | 등록된 문자열 ID. 토픽·인증된 장치와 일치 |
| message_id / boot_id | 메시지 고유 ID / 프로세스 시작 ID. 재전송은 원래 값 유지 |
| device_seq | 0 이상의 정수. 장치가 새 상태 메시지를 만들 때 SQLite에서 증가·저장 |
| occurred_at / clock_synced | UTC 문자열 또는 null / boolean. 서버는 received_at을 별도 기록 |
| event_id | 해당 사건 ID 또는 null. 장치 전체 사건·빈 구역 메시지도 허용 |

현재 상태 snapshot은 전체 값이다. device_seq·boot_id·clock_synced는 envelope와 같으며 observed_at을 남긴다. 현재 사건 ID·상태·버전, guidance_count, continuous_stop_ms, overdue, clock_status(C12), 차종·용도, camera_health, mode, output_status, reason_codes, pauses, received/active_policy_version, mode_revision, rearm_required를 담는다. 사건이 없으면 사건 ID·상태·버전·차종은 null, 횟수·정차시간은 0, overdue=false다.

| 분류 | 허용 값 |
| --- | --- |
| incident_state | OBSERVING, STOP_CONFIRMED, GUIDING, GUIDED, LONG_UNRESOLVED, HELD, CLOSED_EXIT, CLOSED_MANUAL |
| camera_health / mode | OK, SUSPECT, BLOCKED, NO_FRAME, RECONFIGURE / AUTO, PAUSED, AWAITING_RESUME |
| output_status | IDLE, PLAYING, STOPPING, FAILED, UNKNOWN |
| body_type / use_type | CAR, BUS, TRUCK, UNKNOWN / TAXI, SCHOOL, DELIVERY, OTHER, UNKNOWN |

초기 설정 전 received·active 버전은 null을 허용하지만 사건 생성과 안내를 금지하고 RECONFIGURE로 표시한다. 배열은 없으면 []다. 필수 키를 생략하거나 빈 문자열로 null을 대신하지 않는다. 정수는 JavaScript 안전 범위 이내, ID는 길이 1~128의 불투명 문자열이다. 새 버전 전에는 정의되지 않은 필드·상태값을 추가하지 않는다.
