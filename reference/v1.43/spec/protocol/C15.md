문서 번호·이전 파일명은 [절별 위치 안내](../README.md)에서 찾는다. 표와 설명의 조건을 함께 적용한다.

AI는 보드의 인식·정차 판단·출력과 SDK 연결을 맡는다. 백엔드는 보드용 통신·저장 SDK, 가상 장치, 브로커·서버를 구현한다. SDK는 보드에서도 실행되지만 보드 설치·드라이버·실물 시험은 AI 책임이다. Data는 데이터·평가, 프론트는 화면을 맡는다. 04의 전송 형식은 유지한다. 접속·재전송·큐의 상세 설정은 08 D1~D3과 09의 MQTT/SDK 명세를 따른다.

| 항목 | 설계 기준 |
| --- | --- |
| 사건·명령 결과 | AI가 상태 전이를 생성 → 백엔드 SDK가 장치 SQLite의 상태·outbox를 한 트랜잭션으로 저장 → QoS 1 발행 → Mosquitto → Spring 검증·DB 커밋 → acks. 로컬 커밋과 서버 저장 확인을 구별한다. |
| 현재 상태·생존 | 장치가 heartbeat를 5초마다 전송(QoS 0). 전체 snapshot, fps, pending_message_count, storage_ok를 전달한다. heartbeat에는 애플리케이션 ACK를 요구하지 않는다. |
| 중복·지연 수신 | 같은 ID·내용은 기록을 늘리지 않고 DUPLICATE ACK. ID에 다른 내용이면 격리 저장 후 REJECTED. DB 저장 실패는 성공 ACK 없이 재전송을 기다린다. 과거 이력은 저장해도 현재 상태를 과거로 되돌리지 않는다. |
| 사진 전송 | AI가 유효 프레임·촬영시각과 JPEG를 제공. SDK가 사진 작업·재시도·HTTPS 업로드를, 서버가 저장·권한·보관을 담당. 사진 실패는 사건·출력과 분리한다. |
| 화면 초기화·갱신 | GET /api/stream?zone_id=... 연결 후 GET /api/zones/{id}/status 조회. event=zone_snapshot의 ZoneView를 받고 더 큰 view_revision만 반영한다. SSE 재연결 때도 REST로 최신 상태를 가져온다. |
| 관리자 명령 | 웹 요청 → Spring 권한·대상 검사/command+outbox → 202 QUEUED → MQTT → SDK 중복·기한 검사 → AI 현장 조건·실행 → SDK 상태/결과 원자 저장·회신 → 서버 ACK/SSE. |

## 운영 화면에서 구분할 세 가지

① HTTP 202는 요청 접수다. ② APPLIED는 장치가 적용했다고 응답한 결과다. ③ TTL 60초 후 결과 유예 5초까지 응답이 없으면 DELIVERY_TIMEOUT, 즉 적용 여부 미확인이다. 늦은 결과는 명세대로 반영하며 미확인을 실패 또는 성공으로 단정하지 않는다.

새 heartbeat가 15초 초과 없으면 STALE, 30초 초과면 OFFLINE이다. 과거 사건의 재전송으로 ONLINE을 복구하지 않는다. 웹은 장치와 별도로 SSE 연결 이상도 표시한다. 서버는 마지막 상태를 현재의 빈 구역으로 추정하지 않는다.
