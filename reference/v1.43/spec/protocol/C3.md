# C3 운영 규칙과 세 가지 버전

> v1.43 개발 AI 상세 명세 · v1.42 본문 이관 · 구현·실차 시험 전

원문: `02_통신과_상태_구현명세서_v1.42.docx` / C3 운영 규칙과 세 가지 버전

문서 번호·이전 파일명은 [절별 위치 안내](../README.md)에서 찾는다. 표와 설명의 조건을 함께 적용한다.

규칙 저장과 장치 적용, 사건에 사용된 규칙은 다르다. 서버의 latest_policy_version은 최신 승인본이고, 장치 received_policy_version은 검증 후 저장한 최신본이다. active_policy_version은 현재 장치가 활성화한 규칙이다. event_policy_version은 사건 생성 때 고정하며 사건이 끝날 때까지 바꾸지 않는다.

| desired_policy 필드 | 형식과 고정 의미 |
| --- | --- |
| zone_id / version / base_version | 문자열 / 양의 정수 / 이전 버전. 버전은 서버가 배정 |
| change_class | TIMING 또는 GEOMETRY. 서버가 이전 정책과 비교해 산출 |
| geometry | roi_polygon_m, exit_polygon_m, calibration_id, reference_points |
| reference_points | 4개 이상 image_uv[0..1,0..1] ↔ ground_xy_m[x,y]. 일직선 배치 금지 |
| timers | first_guidance_ms, confirm_ms, repeat_after_end_ms, max_attempts, unresolved_ms, exit_confirm_ms |
| vision_profile_id / operating_hours | 버전 고정된 판단 설정 ID / Asia/Seoul의 요일·시작·종료. 초기값은 매일 00:00~24:00 |

timers 초기값은 순서대로 300000, 3000, 30000, 2, 600000, 3000이다. 첫 안내는 유효 정차 5분, 재안내 간격은 첫 재생 종료 후 30초이며 현재 후보도 300초 이상이어야 한다. 10분 미해소는 최초 정차 후보 시작 기준이다. 첫 안내 5분은 강남구 CCTV 운영 사례를 참고한 실험 정책이며 법적 위반 확정 기준이 아니다. 운영시간이 끝나면 새 안내와 재생을 보류한다. unresolved_ms≤first_guidance_ms인 정책은 INVALID_SCHEMA로 거부한다.

TIMING 변경은 현재 사건이 있으면 RECEIVED_PENDING 상태로 저장한다. 현재 사건은 이전 버전을 유지한다. 사건 종료 후 새 사건을 만들기 전에 active를 received로 바꾸고 CONFIG_ACTIVATED를 발행한다. 현재 사건이 없으면 즉시 적용할 수 있다. geometry·vision_profile_id 변경은 GEOMETRY로 취급한다.

GEOMETRY 변경은 즉시 재생을 보류하고 RECONFIGURE 중지를 만든다. 기존 사건은 이전 geometry로 보존한다. 관리자 확인 종료 → 현장 apply-policy(version)로 보정·품질 기준 검증 후 active 갱신 → 새 구역이 비어 있음을 정상 영상으로 3초 확인 → 새 사진으로 명시적 재개 순서다. 현장 적용은 웹 재개와 별개이며 실패하면 이전 active와 중지를 유지한다.

예를 들어 사건의 버전이 3일 때 시간 규칙 4를 받으면 received=4, active=3, event=3이다. 사건 종료 후 active=4가 되고 다음 사건도 4를 사용한다. 같은 version에 다른 내용이 오면 POLICY_CONTENT_CONFLICT로 거부한다. 새 수정은 항상 버전을 올린다. config_status는 RECEIVED_PENDING, APPLIED, RECONFIGURE_REQUIRED, REJECTED 중 하나다.
