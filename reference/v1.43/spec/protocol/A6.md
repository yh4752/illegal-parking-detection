문서 번호·이전 파일명은 [절별 위치 안내](../README.md)에서 찾는다. 표와 설명의 조건을 함께 적용한다.

아래 수치는 우리 시험의 초기 통과 목표다. 법적 단속 기준·공인 성능·이미 달성한 결과가 아니다. 실제 이동과 영상 판단 사이의 지연을 숨기지 않도록 정답 영상 시각, 판단 로그 시각, 출력 확인 시각을 분리한다.

파일 영상의 순수 로직 시험은 PTS를 가상 단조 시각으로 사용해 재생 배속과 무관하게 같은 상태 전이를 검증한다. 실제 반응시간·FPS 시험은 1배속 입력과 장치의 실제 단조 시계로 측정한다. PTS 기반 시뮬레이션 시간으로 실제 스피커 반응시간을 달성했다고 보고하지 않는다.

| 측정 구간 | 초기 기준과 미실행 처리 |
| --- | --- |
| 정차 충족 → 안내 요청 | 유효 후보 300초 및 모든 조건 충족 시각부터 play 요청까지. p95 2초 이하. 미안내는 성공률 실패에 포함하고 지연 통계에서 별도 건수 표시. |
| 실제 이동 → MOVE 판단 | 0.2m/s 이상으로 계속 이동하는 지정 시험에서 1.5초 이내. 0.2m/s보다 느린 서행은 별도로 지연과 잘못 안내한 건수를 보고. |
| MOVE 판단 → 출력 중단 | 판단 로그 시각부터 실제 음성·LED 중단까지 500 ms 이내. 요청 발행·프로그램 회신·현장 확인을 따로 남김. |
| 관찰 불능·중지 → 중단 | 보류 또는 중지 입력을 장치가 수락한 시각부터 실제 출력 중단까지 500 ms 이내. 통신으로 명령이 도달하기 전의 지연도 별도 기록. |
| 이탈 3초 충족 → 종료 | 동일 차량의 ROI 밖 실제 관찰 3초 완료 후 2초 이내 CLOSED_EXIT를 로컬 DB에 저장. 미검출 종료·조기 종료·기한 초과는 실패. |

대상 사건 성공은 정답 허용 구간의 새 안내, 금지 상황에서 새 안내 없음, 이미 재생 중이던 안내의 정해진 중단기한 준수를 모두 요구한다. 실제 움직임이 시작된 순간의 0 ms 중단을 요구하지 않는다. 다만 이동 감지 지연과 중단 지연을 각각 채점해 늦은 감지가 성공으로 숨지 않게 한다.

## G AI 초기 실행 검증

별도 개발 자료에서 정상 정차 360초 영상 10건을 준비한다. 구역 보정과 초기 품질 정상 5초를 촬영 전에 완료하고, 사람이 영상에 표시한 실제 정차 시작 시각을 t_ready로 고정한다. 프로그램이 탐지를 성공한 늦은 시각으로 옮길 수 없다. 10건 중 9건 이상이 t_ready부터 302초 이내 첫 안내 요청에 도달해야 판단기를 고정하는 다음 단계로 간다. 최종 120건 성능을 통과했다는 뜻은 아니다. 360초는 실제 1배속 영상 길이이며 30초로 단축한 시연은 이 검증을 대신하지 않는다.

같은 검증에서 서행·20초 간격 검출 누락·위치 흔들림·프레임 지연 입력을 넣어 후보 초기화와 보류 로그도 확인한다. 정상 영상 실패 시 검출 하한, 카메라 구도·차량 크기, 보정 오차, 평활화와 처리 지연을 우선 점검한다. 누락 시간을 무조건 더하거나 시험 분모에서 실패를 빼지 않는다.

조정은 개발 자료에서만 한다. 변경한 모델·품질 설정·임계값과 근거를 새 vision_profile_id 및 관련 규칙 버전으로 남긴다. 300초 연속 관측 정책 자체를 바꾸면 설계와 시험 정답도 함께 수정해 재검토한다. 카메라·장소가 확정되면 그 입력으로 G AI를 다시 확인한 뒤 사용하지 않은 최종 촬영 자료를 평가한다.

지면 보정은 독립 표식 9개로 RMSE 0.05m 이하·최대 0.10m 이하를 확인한다. 이 검사는 바닥 좌표변환만 평가하므로 검출 상자의 위치 편향·떨림과 G-AI 시험을 대체하지 않는다. 실제 지연은 03의 외부 영상·오디오 측정 절차를 따른다.
