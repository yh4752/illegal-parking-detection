# A5 음성 재생과 LED 제어의 실패 처리

> v1.43 개발 AI 상세 명세 · v1.42 본문 이관 · 구현·실차 시험 전

원문: `02_통신과_상태_구현명세서_v1.42.docx` / A5 음성 재생과 LED 제어의 실패 처리

문서 번호·이전 파일명은 [절별 위치 안내](../README.md)에서 찾는다. 표와 설명의 조건을 함께 적용한다.

판단 모듈은 드라이버에 play(attempt_id, audio_asset_id), stop(attempt_id), setLED(on)를 호출한다. attempt_id는 사건별 안내 시도 식별자다. 같은 시도의 재호출로 새 재생을 만들지 않는다. 드라이버는 시작·정상 완료·중단·실패·불확실 결과와 단조 증가 시각을 반환한다.

| 출력 상태 | 전이와 저장 규칙 |
| --- | --- |
| IDLE | 재생 없음. 모든 안내 조건을 다시 확인한 뒤 시도 횟수 증가와 시도 기록을 먼저 DB에 저장. 저장 실패 시 재생 금지. |
| PLAYING | play 요청 후 시작 회신을 받음. 2초 내 시작 회신이 없으면 출력 고장으로 보류하고 STOPPING 절차를 실행. LED는 확인된 재생 중에만 켬. |
| STOPPING | 이동·품질 저하·중지·종료 조건을 받으면 같은 제어 루프에서 stop 요청과 LED 끄기. 새 play 요청은 거부. |
| FAILED | 명확한 실행 실패·완료시간 초과·강제 종료 사용. OUTPUT_FAULT를 고정하고 자동 재안내 금지. |
| UNKNOWN | 전원 중단이나 kill 실패 등으로 실제 재생 여부를 확인할 수 없음. 시도는 사용한 횟수로 유지하고 현장 확인 요청. |

오디오 파일은 배포 전에 길이 L을 확인하고 해시와 함께 고정한다. 재생 시작부터 L+2초 안에 완료 회신이 없으면 watchdog이 stop을 요청한다. 정상 완료 시 output_status=IDLE과 완료 결과를 기록한다. 정상 stop 완료도 IDLE로 돌아가며 결과는 STOPPED다. 이때 종료 시각이 재안내 간격의 기준이 된다.

stop 요청 후 500 ms 안에 중단 확인이 없으면 플레이어 프로세스 강제 종료를 시도한다. 강제 종료 요청 후 1초 안에 종료 확인이 오면 FAILED, 확인할 수 없으면 UNKNOWN으로 기록한다. 둘 다 OUTPUT_FAULT를 유지하고 안내 횟수를 되돌리지 않는다. OUTPUT_FAULT는 현장에서 출력을 확인하고 현장에서 해제해야 한다. 웹 재개로 우회할 수 없다.

현장 물리 중지는 웹 명령보다 우선한다. 소프트웨어 종료와 별도로 즉시 스피커 출력을 끊을 수 있는 현장 전원 또는 출력 차단 수단을 시험 전에 마련한다. 구체적인 전원·배선·GPIO 규격은 대여 보드와 출력 장치 확인 후 기록한다. 소프트웨어 stop 회신은 실제 스피커 무음의 증거가 아니므로 시험에서 실제 소리를 별도로 확인한다.

시도 선저장과 실제 재생은 한 트랜잭션으로 묶을 수 없다. 재생 직전에 전원이 끊기면 방송이 실제로 나오지 않았더라도 시도 횟수는 사용된 것으로 유지한다. 이 보수적 선택은 중복 방송을 방지하는 대신 한 번의 안내가 누락될 수 있다는 제한을 가진다. 재시작 시 기존 음성을 다시 실행하지 않는다.

드라이버 인수시험은 완료 콜백 누락, 시작 회신 누락, 재생 프로세스 정지, stop 응답 지연, kill 실패를 각각 주입한다. 시간 초과가 사건을 무한히 GUIDING으로 남기거나 재시도로 같은 음성을 반복하지 않아야 한다.
