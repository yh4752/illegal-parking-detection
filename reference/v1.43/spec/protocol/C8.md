그림 F09. 화면은 가장 큰 상태 버전만 반영한다

텍스트 도식: [F09](../../architecture/F09.mmd). 그림별 조건은 [아키텍처 안내](../../architecture/README.md)를 함께 확인한다.

웹은 SSE를 연결한 뒤 REST로 현재 상태를 조회하며, 두 경로에서 받은 ZoneView를 같은 view_revision 기준으로 비교한다. 재연결 때도 REST 재조회로 누락을 회복하고 과거 버전은 반영하지 않는다.

· 장치 상태의 최신성과 웹 연결 상태는 별개다.

· 그림의 11·12·13은 비교 규칙을 설명하는 가상 버전이다.

서버는 구역별 view_revision을 DB에 저장하고 화면에 보이는 상태가 바뀔 때 증가시킨다. REST ZoneView와 SSE event=zone_snapshot은 동일한 전체 객체를 사용한다. 객체는 zone_id, view_revision, received_at, last_heartbeat_at, connection_state, snapshot, commands, image_refs를 포함한다. image_refs에는 image_id·image_kind·event_id·captured_at·received_at·expires_at·status·error_code를 넣고 제어 토큰은 넣지 않는다. 상태는 PENDING·AVAILABLE·FAILED·EXPIRED다(C11). 공개 commands의 result_data.confirmation_token은 필드를 유지하고 null로 보낸다. 유효한 OPERATOR 명령 조회에서만 토큰 문자열을 반환한다.

브라우저는 SSE를 연 뒤 REST를 조회한다. 응답의 view_revision이 현재 값보다 클 때만 교체하며 같은 값은 중복으로 처리한다. 재연결 때도 REST를 다시 조회한다. SSE는 영구 기록 복구 수단이 아니므로 이력은 REST로 읽는다. 서버는 늦은 device_seq를 현재 snapshot에 덮어쓰지 않지만 해당 사건 이력과 명령 결과는 중복 검사 후 저장한다.

| 오류 코드 | HTTP와 장치 결과 처리 |
| --- | --- |
| INVALID_SCHEMA / UNSUPPORTED_SCHEMA | 400 / REJECTED. 필수값·자료형·알 수 없는 상태 확인 |
| UNAUTHENTICATED / FORBIDDEN | 401 / 403. 로그인 또는 권한 확인 |
| NOT_FOUND / GONE | 404 / 410. 대상 없음 또는 보관기한 종료 |
| VERSION_CONFLICT / POLICY_CONTENT_CONFLICT | 409 / REJECTED. 최신 규칙 다시 조회 |
| EVENT_MISMATCH / NO_ACTIVE_EVENT | 409 / REJECTED. 현재 사건과 요청 대상 재확인 |
| MODE_CHANGED / INVALID_TOKEN<br>SNAPSHOT_EXPIRED / CLOCK_UNTRUSTED | 409 / REJECTED. 최신 상태·새 사진 확인 |
| PHYSICAL_STOP_ACTIVE / PAUSE_NOT_RELEASABLE<br>REARM_NOT_READY / OBSERVATION_UNSAFE | 409 / REJECTED. 현장 또는 관찰 조건 먼저 해소 |
| COMMAND_EXPIRED / OUTPUT_FAULT | EXPIRED / FAILED. 재요청 여부와 실제 적용 상태 확인 |
| MESSAGE_ID_CONFLICT / IMAGE_ID_CONFLICT<br>IDEMPOTENCY_CONFLICT / STORAGE_FULL | 409 또는 503 / REJECTED·FAILED. ID 재사용 또는 저장 이상 확인 |

REST 오류 본문은 {code,message,details,retryable,request_id}로 통일한다. message는 사람에게 보여 줄 설명이고 분기는 code로 한다. UI는 연결 끊김·접수 중·장치 적용·거부·만료·적용 미확인을 구별한다. 중지 요청을 보냈다는 이유만으로 현장이 중지됐다고 표시하지 않는다.

웹은 같은 출처 HTTPS, Secure·HttpOnly·SameSite=Lax 세션 쿠키와 변경 요청의 CSRF 헤더를 사용한다. VIEWER의 제어는 화면 숨김뿐 아니라 서버에서 403으로 막는다. 장치 MQTT 계정은 자기 토픽만 발행·구독한다. 브라우저에는 장치 비밀번호나 브로커 계정을 배포하지 않는다. 장치 HTTPS 키도 장치 ID에 제한한다.
