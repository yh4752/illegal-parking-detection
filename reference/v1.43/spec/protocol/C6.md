# C6 사진 확인과 제어 토큰

> v1.43 개발 AI 상세 명세 · v1.42 본문 이관 · 구현·실차 시험 전

원문: `02_통신과_상태_구현명세서_v1.42.docx` / C6 사진 확인과 제어 토큰

문서 번호·이전 파일명은 [절별 위치 안내](../README.md)에서 찾는다. 표와 설명의 조건을 함께 적용한다.

상시 영상 스트리밍은 필수 범위에 포함하지 않는다. 웹은 사건 사진과 상태를 보여주며, 재개·관리자 종료에는 새 확인 사진을 사용한다. REQUEST_SNAPSHOT의 purpose로 VIEW·RESUME·CLOSE_EVENT를 구별한다. VIEW 사진은 제어 토큰을 발급하지 않는다. 서버나 장치 시각이 UNTRUSTED면 VIEW를 포함한 새 사진 요청도 거부한다.

| 단계 | 고정 절차 |
| --- | --- |
| 1 촬영 | 장치가 요청 ID·boot_id·현재 사건·세 버전·mode_revision을 함께 고정 |
| 2 업로드 | JPEG와 메타데이터를 HTTPS로 전송. image_id와 SHA-256으로 중복 확인 |
| 3 결과 | 서버 저장이 확인되면 image_id와 필요 시 일회 토큰을 command-result에 반환 |
| 4 웹 확인 | 촬영시각과 현재 사건을 표시. OPERATOR가 사진을 보고 해당 제어 실행 |
| 5 장치 검증 | 토큰 목적·boot·세대·버전·사건·현재 관찰 상태와 남은 유효시간을 다시 확인 |

토큰은 촬영부터 장치 단조 시간으로 30초 유효하며 성공적으로 적용한 한 명령에서만 사용한다. 재시작·새 사건·사건 종료·설정 및 중지 변경에 무효화한다. image_id, request_command_id, purpose, boot_id, current_event_id, received/active/event_policy_version, mode_revision에 결합한다. 업로드 완료 시 남은 시간이 0이면 토큰을 발급하지 않는다. 확인사진 실패·만료 처리는 C11에 따른다. 명령 자체의 60초도 동시에 만족해야 한다. 30초 뒤 저장된 사진은 이력만 남기며 토큰·APPLIED를 소급 발급하지 않는다.

새 사진이 없거나 관찰 품질이 정상으로 회복되지 않으면 RESUME을 적용하지 않는다. CLOSE_EVENT도 현재 사건과 사진이 연결되어야 한다. 차가 없는 구역의 사진은 event_id=null이다. 사진 촬영과 저장 API를 사건 하위에 두지 않으므로 빈 구역 재개 확인에도 사용할 수 있다.

| 사진 업로드 메타데이터 | 형식 |
| --- | --- |
| image_id / request_command_id | 고유 이미지 ID / 사진 요청 명령 ID 또는 null |
| event_id / captured_at / clock_synced | 사건 ID 또는 null / UTC 또는 null / boolean |
| boot_id / mode_revision | 촬영 구간 ID / 촬영 당시 중지 세대 |
| received_policy_version / active_policy_version<br>event_policy_version | 촬영 당시 세 버전. 사건 버전은 사건이 없으면 null |
| sha256 / width / height | 파일 해시 / 양의 정수 픽셀 크기. JPEG 최대 5 MiB |
| image_kind / image_profile_id | 사진 목적 / jpeg-1280-q80-v1 고정 프로파일(C11) |
| created_at / source_image_id | 작업 생성 UTC 또는 null / 원본 재사용 ID 또는 null |

동일 image_id·동일 해시는 기존 저장 결과를 반환하고, 다른 해시는 IMAGE_ID_CONFLICT로 거부한다. 사진은 인증된 API로만 조회하고 서버가 저장 경로를 정한다. 제어 토큰은 OPERATOR에게만 전달한다. 일반 사건 이력·접근 로그·SSE 전체 공개 상태에는 토큰 원문을 넣지 않는다. 재전송에 필요한 명령 결과의 제한된 저장본은 ACK 후 제거한다.
