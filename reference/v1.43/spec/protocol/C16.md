문서 번호·이전 파일명은 [절별 위치 안내](../README.md)에서 찾는다. 표와 설명의 조건을 함께 적용한다.

초기 배포는 접근 권한이 있는 개발 PC 또는 Linux 서버 1대의 Docker Compose로 구성한다. 클라우드 구매와 특정 사업자는 필수가 아니다. 호스트·접속 주소·인증서 확보는 D+14 통합 전에 확인한다. 배포 파일을 구현한 상태가 아니라 만들 기준이다.

| 항목 | 설계 기준 |
| --- | --- |
| 프로세스 배치 | Nginx: React 정적 파일과 HTTPS 역방향 프록시. Spring: API·SSE·MQTT·배경 작업. Mosquitto: 메시지 중계. PostgreSQL: 영속 데이터. 필요 시 모니터링 프로필로 Prometheus·Grafana 추가. |
| 노출과 내부망 | 허가한 네트워크에서 HTTPS 443, 장치용 MQTT/TLS 8883만 허용한다. Spring 8080·DB 5432·관리 포트·Prometheus·Grafana는 외부에 직접 열지 않는다. 운영 지표는 SSH 터널 등 관리자 경로로 확인한다. |
| 웹과 SSE 프록시 | 웹과 /api를 동일 출처로 제공한다. /api/stream은 proxy_buffering off·캐시 비활성화. SSE 주석 keepalive 15초, proxy_read_timeout 60초를 초기값으로 사용한다. 장치 heartbeat와 별도다. |
| 영속 저장·비밀값 | DB·사진·브로커 persistence를 별도 볼륨에 둔다. DB 암호·장치 자격증명·TLS 개인키는 Git과 공유 ZIP에 넣지 않는다. 사진은 정적 공개 경로로 서비스하지 않는다. |
| 기동과 상태 검사 | DB 준비 확인 → Flyway → 서버 기동·MQTT 구독 → API/SSE 확인. Compose healthcheck와 service_healthy로 순서를 제어한다. 실행 중 재연결은 애플리케이션이 처리하며 unhealthy만으로 자동 재시작되지는 않는다. |
| 배포와 되돌리기 | 테스트 통과 → 버전 태그 이미지 생성 → DB 변경 전 백업 → 배포 → 가상 사건·명령 확인. 스키마가 이전 이미지와 호환될 때만 코드 롤백한다. DB를 임의로 과거 상태로 되돌리지 않는다. |

## 정지·복구와 운영의 한계

정상 종료 시 신규 요청을 중단하고 진행 중 DB 작업을 제한 시간 내 마무리한다. 미확인 메시지·명령은 영속 기록에서 복구한다. SSE 연결과 메모리 세션은 재연결·재로그인이 필요하다. 서버 중단 중 엣지는 기존 정책과 C12의 시각 신뢰·저장 한도 조건 안에서 판단한다. 원격 제어는 사용할 수 없다.

백업은 DB·필요 사진을 일관된 시점에 보관하고 기존 보관기한을 함께 적용한다. 복원 시험은 격리 환경에서 수행한다. 운영 DB 복원 시 웹 세션·SSE를 초기화하고 장치 상태·버전·중복 기록을 대조한 뒤 재개한다. 단일 호스트이므로 고가용성이나 무중단 배포를 보장하지 않는다.
