# 검증과 완료 판단

이 자료에는 설계 검증 기록과 앞으로 수행할 인수시험이 함께 있다. 저장된 보고서가 존재한다는 이유로 현재 구현·실보드·실차 시험이 끝났다고 보지 않는다.

v1.43에서는 재편한 폴더의 기존 검증 코드를 실제 실행해 정상 예제 25개·오류 입력 45개·API 작업 15개·합성 시계 경계 7개의 통과를 확인했다. 결과는 [validation_v1.43.json](validation_v1.43.json)에 있다. `개발자료/` 안의 원래 보고서는 당시 기록으로 보존했다. 이번 실행 역시 서버·DB 동시성·브로커·SDK·실보드·물리 출력 시험은 포함하지 않는다.

## 기존 계약 검증을 재현하는 방법

개발 AI용 폴더의 루트에서 다음과 같이 실행한다. 패키지 설치에는 다운로드 환경이 필요하다.

```sh
cd 개발자료/09_구현설계/contracts
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python validate_examples.py --report validation_report_local.json
```

Windows에서는 `.venv/Scripts/python.exe`를 사용한다. 기본 공통 계약 입력은 원래 상대 경로의 `../../04_공통_통신계약과_메시지예제_v1.4.json`이다. 파일 위치를 바꾼 경우에는 `--contract`로 실제 경로를 지정한다. 새 결과를 별도 파일에 기록해 배포된 과거 보고서와 구분한다.

이 검증의 범위는 Schema/OpenAPI 문법·예제 형식·일부 의미 비교다. 서버·브로커·DB 동시성·SDK·실제 보드·물리 출력·성능을 실행해 확인하는 시험이 아니다. 입력 키·타입 검증만으로 권한·시각·중복·실제 실행을 통과했다고 판단하지 않는다.

## 기록할 최소 항목

| 항목 | 기록 내용 |
|---|---|
| 시험 | TC·OP·BC·DB 식별자와 해당 조건 |
| 환경 | PC/실보드, OS·런타임·모델·SDK·서버·DB·정책 버전 |
| 입력 | 사용 자료와 시나리오, 주입한 장애, 반복 수 |
| 기대값 | 기준 명세가 요구하는 상태·시간·저장·출력 |
| 관측값 | 실제 로그·DB·화면·물리 관측과 측정 방법 |
| 판정 | 통과 / 실패 / 미수행 / 조건 미충족으로 보류 |
| 후속 | 원인·담당·수정·재시험 항목 |

BC01~BC05는 PC 가상 장치 시험, BC06은 실제 QCS610 결합·출력·저장 시험이다. 둘을 분리한다. 120건 최종 평가에서는 미안내·보류·개입·미실행·지연을 제외해 분모를 줄이지 않는다.

시험 실패나 환경 미확인으로 막힌 작업은 그대로 기록하고, 해당 조건에 의존하지 않는 작업은 계속할 수 있다. 목표 수치와 일정은 실제 결과가 확보됐을 때만 달성으로 표시한다.
