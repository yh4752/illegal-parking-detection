# AI 모델·현장 장치 담당 작업 안내

AI 담당은 모델·탐지·추적·관측 품질·정차 판단과 실제 출력을 맡는다. 실제 보드 환경, 카메라·시계·출력 어댑터, 배선과 SDK 설치·결합도 담당한다. 저장·통신 SDK의 공통 코드는 백엔드가 작성한다. [B1](../spec/roles/B1.md), [B2](../spec/roles/B2.md)

## 먼저 진행할 작업

W01: 대여한 QCS610 보드의 실제 제품·OS·ABI·메모리·런타임·TLS/MQTT5/SQLite·시각·입출력 지원을 기록하고, 기준 모델 추론과 후처리 경로를 확인한다. PC 사양을 보드 사양으로 옮겨 적지 않는다. 카메라가 정해지지 않았어도 권리와 보정 가능성이 확인된 개발용 파일 영상으로 시작할 수 있다.

먼저 읽을 자료: [AI·장치 작업](../spec/plan/03.md), [남은 실물 확인 B6](../spec/roles/B6.md), [작업·시험 원본](../개발자료/05_개발작업과_시험목록_v1.4.json)의 W01·TC02.

## 입력과 전달물

| 받는 것 | 만드는 것 | 전달 대상 |
|---|---|---|
| Data의 개발 영상·정답·라벨 지침 | 탐지·추적·품질·판단 결과와 정답 대조 | Data·백엔드 |
| 공통 계약과 백엔드 SDK | 실제 보드 바인딩·플랫폼 어댑터·설치 설정·실행 로그 | 백엔드 |
| 현장 시야·실측 좌표·장치 규격 | geometry/vision/보정 파일, 카메라·시계·출력 연결 | 백엔드·Data |
| SDK에서 전달한 명령과 저장 완료 통지 | 현장 조건 최종 검사, 실제 실행·출력 결과 | SDK·서버 |

세미나의 Vehicle 가중치와 CAR/BUS/TRUCK 형태 분류 요구를 구분한다. 용도 분류를 근거 없이 정답이나 자동 안내 면제로 사용하지 않는다. [차량 분류 범위](../spec/project/06.md)

## 완료 확인

- W02의 개발 영상 10건 중 9건 이상에서 관측 가능 시점 후 302초 이내 첫 안내 시도가 성립하는지 정답과 로그로 확인한다. 실패하면 원인을 개선하고 재검증한다.
- TC04~TC08, TC14·TC15 및 관련 명령·정책 시험에서 판단·보류·중단·재시작을 확인한다.
- 새 안내는 로컬 COMMITTED 후 최신 조건을 재검사한다. 안전 stop/LED off는 저장 지연에도 우선한다. [D3](../spec/storage/D3.md)
- BC06에서 실제 보드의 TLS·사진·명령·재시작·출력·저장을 검증한다. PC BC01~BC05 결과로 대체하지 않는다.
- 실제 성능·실차 준비·비교 결과는 각각 TC21·TC24와 고정된 평가 조건으로 보고한다. D+14 통신 연결은 전체 성능 인수 완료가 아니다.

시험 절차·반복 수·전체 기대값은 [작업·시험 원본](../개발자료/05_개발작업과_시험목록_v1.4.json)에 있다.

## 팀원에게 넘길 결과

보드·OS·ABI·라이브러리·모델 버전, 실행·변환 명령, 어댑터 입력/출력, 보정 파일, 실제 관측 로그, 성공·실패·미수행 시험, SDK 호환 제약과 재현 절차를 전달한다. 물리 출력 확인과 드라이버 응답만 받은 경우를 구분한다.
