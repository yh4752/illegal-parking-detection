# 프론트 담당 작업 안내

프론트는 React 관리자 웹에서 현재 상태·이력·사진·정책·제어 요청과 결과를 표시한다. 장치의 정차를 재판정하거나 명령 접수만으로 적용 완료 상태를 만들지 않는다. [역할 기준 B1](../spec/roles/B1.md)

## 먼저 진행할 작업

W07: 공통 ZoneView와 API 예제로 가상 상태 화면을 만든다. 실제 카메라와 AI 출력이 없어도 상태·명령·사진·연결 이상의 표시 및 순서 처리를 검증할 수 있다.

먼저 읽을 자료: [C1 현재 상태](../spec/protocol/C1.md), [C7 REST](../spec/protocol/C7.md), [C8 갱신·오류·권한](../spec/protocol/C8.md), [계약 안내](../contracts/README.md), [구현 작업](../spec/plan/04.md).

## 입력과 전달물

| 받는 것 | 만드는 것 | 전달 대상 |
|---|---|---|
| REST 현재 상태·SSE ZoneView | 동일 revision 기준의 현재 화면·연결 표시 | 관리자 |
| 사건·명령·사진·리뷰 응답 | 시간순 이력, 접수·적용·미확인·거부 구분 | 관리자 |
| 사용자 조작과 세션·CSRF 토큰 | 계약에 맞는 조회·정책·제어·수정 요청 | 백엔드 |
| 가상 상태·실제 서버 환경 | 화면 시험 결과·재현 절차 | 백엔드·팀 |

## 이후 작업과 참조

1. SSE 연결 후 REST 현재 상태를 조회한다. 두 경로의 ZoneView는 더 큰 `view_revision`만 반영한다. 재연결 때도 REST 재조회로 복구한다. [C8](../spec/protocol/C8.md), [F09](../architecture/F09.mmd)
2. 명령 접수·실제 적용·거부·실패·결과 미확인을 구별한다. DELIVERY_TIMEOUT을 장치 미실행으로 단정하지 않는다. [C4](../spec/protocol/C4.md)
3. 사진 PENDING/AVAILABLE/FAILED/EXPIRED, 자동 기록용과 제어 확인용, 촬영시각·토큰 유효 조건을 구별한다. [C6](../spec/protocol/C6.md), [C11](../spec/protocol/C11.md)
4. OPERATOR와 VIEWER, 로그인·세션·CSRF·오류 처리를 구현한다. 공개 응답의 확인 토큰은 null이며 유효한 OPERATOR의 명령 상세 조회에서만 제공된다. [C7](../spec/protocol/C7.md), [D8](../spec/storage/D8.md)
5. 중지 중첩·정책·최초 설정·명시 재개 화면을 연결한다. 남은 중지와 현장 확인 조건이 있는데 사용 가능 상태로 바꾸지 않는다. [C5](../spec/protocol/C5.md), [C13](../spec/protocol/C13.md)

## 완료 확인

- TC16: 늦은 REST와 SSE가 현재 화면을 후퇴시키지 않으며 재연결로 누락을 회복한다.
- TC17: 접수·적용·미확인, 사진 상태, 장치 최신성, 시각 신뢰, 초기 설정 미완료를 구별한다. 마지막 관측이 빈 구역이었다고 현재도 비었다고 표시하지 않는다.
- TC18·TC19: 수동 용도 수정 이력과 권한을 백엔드와 대조한다. 수정만으로 안내 면제를 만들지 않는다.
- OP03: 실제 프록시 경유 SSE·느린 연결·서버 재시작 후 복구를 백엔드와 확인한다.
- 웹 SSE 연결 상태와 장치 heartbeat 최신성은 서로 다른 항목이다. 서버가 주는 상태와 시각을 임의로 새 값으로 바꾸지 않는다.

정확한 기대값과 반복 수는 [작업·시험 원본](../개발자료/05_개발작업과_시험목록_v1.4.json)의 W07·TC16~TC19·OP03을 따른다.

## 팀원에게 넘길 결과

실행 방법, 연결 주소 설정, 사용한 API·예제 버전, 가상 상태별 화면과 기대 동작, 순서·재연결·권한 시험 결과, 아직 연결하지 못한 API와 다음 확인 사항을 전달한다. 가상 화면의 성공을 실제 장치 제어 성공으로 보고하지 않는다.
