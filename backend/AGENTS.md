# 백엔드 추가 지침

루트 AGENTS.md와 CONTRIBUTING.md에 더해 이 폴더에 적용한다.

- Kotlin/Spring Boot 단일 애플리케이션을 기준으로 한다. C4 컴포넌트를 별도 서버로 해석하지 않는다. 신규 계층은 실제 기능과 함께 추가한다.
- 차량 인식·현장 판단·출력 실행은 보드의 책임이다. 백엔드는 수신 계약 검증·저장·조회·관리 요청 전달을 맡는다. 서버의 수신 시각으로 보드의 관측 시각을 덮어쓰지 않는다.
- MQTT의 프로토콜 ACK와 애플리케이션의 저장 확인 ACK를 구분한다. 성공 ACK는 해당 DB 트랜잭션 커밋 이후 보낸다. 정확한 결과 코드와 재전송·순서 규칙은 docs/first-slice.md 및 그 계약 링크를 따른다.
- 중복 message_id, 같은 ID의 다른 내용, 순서가 뒤바뀐 메시지, DB 실패, ACK 유실을 해당 기능의 테스트에 포함한다. 통신 처리는 HTTP/MQTT 경계와 업무 처리·저장 책임을 구분하되 공통화는 실제 필요에 따라 한다.
- 제품 경로의 접근 제한을 기동 편의를 위해 전역 해제하지 않는다. 개발용 조회를 추가한다면 적용 범위·활성화 방법·운영 인증과의 차이를 명시한다.
- SQL 설계 원본을 그대로 실행 완료로 취급하지 않는다. 마이그레이션 승격 시 빈 DB 적용과 계약 정합성을 검증한다. 적용된 마이그레이션은 수정하지 않고 새 변경을 추가한다.
- 실행은 이 폴더에서 ./gradlew test bootJar, ./gradlew bootRun이다. 실행 결과가 기동·단위·통합 중 어느 범위인지 보고한다.
