# 팀 통합용 조기 배포 준비

**2026-11-19 구현 업데이트:** S3 revision gateway, age 암호화·버전 지정 백업/회수, DB 백업·로그 복사 작업, 서버용 Compose·권한 정책 생성기를 로컬에서 구현·검증했다. 실제 AWS 권한·공인 인증서·전체 서버 유실 복구는 아직 검증하지 않았다. [외부 저장·서버 준비 안내](external-storage-preparation.md)를 최신 구현 기준으로 읽는다.

2026-11-18 · 총 예산 목표 50,000원 · 실제 자원 생성·구매·외부 배포 미승인/미실행

서로 다른 장소의 보드 담당자와 같은 서버에서 통합하기 위해 발표 직전 일주일 운영안에서 조기 배포 방향으로 바꿨다. 12월 11일 발표까지 사용하되 생성·종료 시각은 아직 확정하지 않았다. Lightsail 4GB는 사전 자원 시험과 실제 서버 인수 조건부다. AI 추론은 현장 보드에서 수행하며 이 서버의 GPU 추론 비용을 포함하지 않는다.

## 비용과 실행 경계

총 5만 원은 운영·백업·발표 후 증거 보관을 함께 고려하는 계획 예산이며 자동 결제 차단 한도가 아니다. 2026-11-18 공식 가격표에서 재확인한 공인 IPv4 포함 Linux 일반형 4GB·2 vCPU·SSD 80GB 월 $24 상품을 30일로 단순 환산하면 24일 서버 비용은 $19.2, 계획 환율 1,500원/$와 10% 여유를 적용해 31,680원이다. 이는 실제 시간 요율·카드 환율·세금의 확정 견적이 아니다. 남은 약 18,320원 안에서 저장·요청·전송·필요한 매체와 증거 장기 보관 비용을 검토해야 한다. 새 무료 크레딧은 가정하지 않는다. [Lightsail 가격](https://aws.amazon.com/lightsail/pricing/)

기존 별도 AWS 백업 계정, Bitwarden 무료 개인 금고·암호화 USB·종이 복구 안내서, 본인 단독 관리 결정은 유지한다. 실제 장소·계정·매체는 미정이다. 반복되는 계정 질문을 개발의 선행 조건으로 만들지 않고, 실제 생성 전 필요한 입력을 한 번에 확인한다.

## 보드 담당자에게 전달할 연결 기준

| 항목 | 현재 계약 / 배포 시 준비 |
|---|---|
| 서버 | `illegal-parking-detection.duckdns.org` 후보. 미등록·접속 불가. 등록 가능 여부도 미확인 |
| 보드 연결 | MQTT over TLS, 포트 8883 후보. HTTPS URL을 MQTT host 필드에 넣지 않음 |
| 인증 | 등록된 장치별 계정과 해당 장치 토픽 권한. 실제 비밀번호는 별도 비공개 전달 |
| 서버 인증서 | 배포 도메인과 일치하는 SAN·유효한 인증 체인. 로컬 `mosquitto` SAN 인증서를 외부 도메인에 재사용하지 않음 |
| 발행 | `parking/v2/devices/{device_id}/events`, `/heartbeat`, `/availability` |
| 구독 | `parking/v2/devices/{device_id}/acks` |
| 사건 전달 | 기존 SDK처럼 QoS 1, retain=false. 응용 ACK 전까지 outbox 보존·재전송 |
| 의미 | MQTT 수신 확인과 DB 커밋 후 응용 ACK는 다름. 중복 응용 ACK도 계약대로 처리 |
| 메시지 | 기존 schema_version=2 및 JSON Schema·의미 검사. AI 내부 출력은 SDK 계약으로 변환 |

현재 로컬 ACL은 `edge-01` 시험 계정에만 맞춰져 있다. 실제 장치 ID·구역 등록과 장치별 ACL은 배포 시 확정해야 한다. 임의의 새 JSON이나 명령 토픽을 이 문서로 추가하지 않는다. [계약](contracts.md), [가상 장치 구현](../simulator/device.py), [ACL](../infra/deploy/mosquitto/acl)을 기준으로 한다.

## 현재 구현과 배포 전에 남은 차이

| 영역 | 현재 확인한 상태 | 배포 전에 해야 할 일 |
|---|---|---|
| 자원 | [사전 측정](preflight-4gb.md)의 제한 환경·측정 조건 참조 | 로컬 연속 시나리오는 완료. 승인된 실제 Linux amd64/2vCPU·4GB에서 다시 측정 |
| 공개 포트 | 로컬 Compose는 HTTPS·Grafana를 loopback으로 제한, MQTT host 포트 없음 | 별도 서버 생성기는 기본 loopback·명시 공개 80/443/8883 지원. 실제 방화벽·SSH 관리자 범위 검증 필요 |
| TLS | 로컬 CA 시험 + 공인 도메인 SAN/키/체인 staging 도구 검증 | 도메인 인증서 발급·갱신·권한·Nginx/MQTT 재적용 시험 |
| 이미지 | 로컬 image ID에 묶인 빌드 | Linux amd64 이미지 빌드·레지스트리 digest 고정·이전 버전 복귀 확인 |
| revision | 기존 LOCAL_ONLY 보존 + AWS_S3 gateway의 모의 저장소·HTTP 로컬 검증 | 실제 S3 인증/TLS·조건부 생성/갱신·응답 유실·단조 증가·삭제 거부 시험. URL만 바꿔 배포 금지 |
| 백업 | O4 `backup()`은 web/backend/simulator 중지 후 dump·암호화·격리 복원 비교·fence·재기동 | 초기 팀 통합은 새벽 03:00 KST 중단형 백업을 권장하며, 발표·집중 통합 중에는 실행하지 않는 운영안을 검토한다. DB·revision·outbox 정합성 확보가 이유다. 연속 수신이 필요해지면 온라인 백업 정합성을 따로 설계한다. 외부 전송·새 DB 회수 복원은 로컬 모의 S3로 검증했다. 실제 IAM·예약 작업 설치·보존 삭제·키 회수·전체 서비스 검증은 남음 |
| 관측 | 같은 Docker 호스트의 Prometheus·Grafana | 서버 외부의 접속 검사와 실제 알림 전달·해제 확인 |
| 증거 | 기존 로컬 로그·캡처·수치 보존 | 새 운영 증거의 독립 사본 검증, 비밀값 가림, 반납 전 회수 |

이 표의 외부 미검증 사항은 팀 공개 전 확인할 조건이다. 사전 메모리 시험 통과로 O5 또는 이슈 #6의 F2~F6을 완료 처리하지 않는다.

## 실제 연결 확인 순서

1. 기존 계약의 가상 사건 1건을 고정한 뒤 보드 담당자의 출력과 매핑한다.
2. 승인된 외부 작업 단계에서 서버·주소·인증서·장치 계정을 설정한다.
3. 다른 네트워크에서 TLS 이름 검증·잘못된 인증 거부·다른 장치 토픽 거부를 확인한다.
4. 사건 발행 → DB 행 확인 → 응용 ACK → 웹 조회/SSE 반영을 동일 message_id/event_id로 대조한다.
5. 연결 단절·재접속·중복 전송·오래된 순번을 시험하고 잘못된 상태 덮어쓰기가 없는지 확인한다.
6. 백업 중 실제 접속 상태, 재개 후 pending 해소, 외부 사본 복원 결과를 확인한다.

현재 작업은 30분 연속 로컬 시나리오와 외부 저장·서버 준비 코드의 로컬 검증까지다. 앞선 두 번의 절전 기록을 보존했고 사용자 재개 후 새 실행을 완료했다. 실제 4GB 호스트·외부 인수는 미완료다. 사용할 AWS 계정·지역·정확한 실행 시각·결제 수단·실제 서버 생성은 아직 확정하거나 실행하지 않았다.
