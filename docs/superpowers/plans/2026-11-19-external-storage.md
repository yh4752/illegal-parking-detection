# 외부 저장·배포 준비 구현 계획

2026-11-19 · 승인된 S3 분리 저장·단일 Linux/Compose 방향의 후속 구현. 실제 계정 생성·구매·외부 배포·push 없음.

## 경계와 결정

기존 서버의 원장 HTTP 계약을 유지하고 내부 전용 gateway의 저장 계층을 S3로 구현한다. 서버에 AWS 키를 배포하는 직접 SDK 방식보다 AWS 권한·저장 로직을 좁게 격리할 수 있다. 로컬 SQLite 어댑터는 기존 검증용으로 보존한다. S3는 TLS/SigV4·예상 계정·Versioning·조건부 쓰기를 강제한다. 현재 head 읽기 실패를 과거 버전으로 대체하지 않는다. 최초 생성은 별도 명시 명령이며 실행 중 자동 초기화하지 않는다.

백업은 age 표준의 스트리밍 파일 암호화와 S3의 덮어쓰기 없는 객체 저장을 사용한다. 개인 비밀금고/추가 사본의 실제 배치는 변경하지 않는다. DB 일관성·revision 경계·격리 복원 성공과 단순 업로드 성공을 구분한다. 외부 검증 전 성공 표시는 로컬 시험 범위로 제한한다.

운영 Compose는 로컬 fixture를 자동 인수하지 않는 별도 생성물로 준비한다. 기본 host 바인딩은 loopback이고 공개는 명시 설정으로만 전환한다. 이미지 digest·linux/amd64·DB/관리 포트·권한·파일 secret 경계를 검사한다. 서버 생성 코드는 포함하지 않는다.

## 실행 순서와 검사

1. `infra/external-storage/s3_store.py`, `ledger_s3.py`: 조건부 갱신·경합·응답 유실·손상·잘못된 identity·미초기화·과거 head 거부 시험을 먼저 작성한다. boto3 Stubber와 loopback S3 emulator를 사용하며 실제 AWS 호출을 금지한다.
2. 기존 Kotlin `RevisionLedger`에 S3 gateway의 저장 유형 확인을 추가한다. LOCAL_ONLY 경로 회귀와 잘못된 gateway 거부를 검사한다.
3. `tools/production/external_backup.py`: 스트리밍 암호화·복호화, 버전 지정 다운로드·해시 대조, 잘못된 키·손상·경로 탈출·덮어쓰기 거부와 128MiB 초과 파일을 검사한다. 기존 O4 원본은 변경하지 않는다.
4. `tools/production/prepare_server.py`, `infra/server/`: 비밀값 없는 입력으로 운영 Compose·장치별 ACL·S3 최소 권한 정책·실행 순서를 생성한다. 미확정 입력, 비고정 이미지, 관리 포트 공개, 잘못된 도메인·장치 ID를 거부한다. 생성만 하며 up/등록/구매를 실행하지 않는다.
5. 별도 로컬 시험에서 외부 어댑터 HTTP·S3 경로와 실제 백업 파일 회수를 검증하고 증거를 보존한다. 문서·ADR·구조 그림·현재 상태·작업표를 갱신한다.
6. Python 및 변경된 Kotlin 검사, 문서 재생성·링크/계약 보존 검사, 최종 코드 검토. 실제 IAM·S3 지역 장애·공인 인증서·실서버 성능·외부 인수는 미검증으로 남긴다.

## 수행 결과

위 1~6의 로컬 구현과 검증 기록을 [실행 근거](../../../validation/external-storage-local-2026-11-19/README.md)에 보존한다. DB 복원 시험은 새 PostgreSQL의 1개 검증 테이블 기준이며 전체 제품 DB·실서버 인수가 아니다. 운영 timer 설치, 보존 삭제, 공인 인증서 발급·갱신, 실제 AWS 권한/키 회수와 전체 서버 복구는 남아 있다. 후속 사용자 요청에 따라 구현·검증 근거를 커밋하고 PR로 공유한다. 실제 계정·서버 생성·구매·외부 배포는 수행하지 않는다.
