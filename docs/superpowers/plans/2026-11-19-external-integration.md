# PR #12 CI 복구와 전체 서비스 외부 저장 로컬 인수

2026-11-19 · 사용자 승인: CI 실패 해결 및 전체 서비스 연결 검증. 기존 데이터 보존. 실제 계정/서버 생성·구매·외부 배포 없음.

1. CI 실패 원본을 보존한다. Maven 429는 작업별 재실행으로 구분하고, DB 준비 실패는 Linux UID/secret 권한을 재현한다. 시험용 secret의 host 부모는 비공개로 유지하고 개별 파일만 read-only mount한다. 실패 진단에는 비밀값을 가린 DB 로그를 남긴다.
2. 별도 로컬 프로젝트에서 실제 Spring/MQTT/HTTPS/제품 DB를 모의 S3 gateway와 연결한다. production SDK의 endpoint 제한은 변경하지 않는다. 시험 전용 fixture에서만 내부 모의 S3를 주입한다.
3. 사건 수신/저장/ACK, server_backup.py의 전체 제품 테이블 dump/격리 복원/fence/업로드, 버전 지정 회수/age 복호화를 실제 실행한다. 원본 DB를 보존한 새 DB로 복원하고 기존 O4 hold/reconcile/명시 손실 인수/새 revision 재개와 SSE/ACK 복귀를 확인한다.
4. 원장 장애 차단, 백업 실패 시 성공 시각 유지, 외부 백업 지표를 확인한다. 모든 기존 컨테이너·볼륨을 보존하고 새 시험 프로젝트만 정리한다. localhost 테스트는 실제 AWS IAM·공인 TLS·전체 호스트 RTO를 입증하지 않는다.
5. 로그·수치·실패 원인·소스 해시와 문서/이슈를 갱신하고 PR #12에 후속 커밋을 반영한다. CI 최종 상태를 확인한다. 병합은 실패 해결과 최종 검토 후 판단하며 외부 자원 작업은 실행하지 않는다.
