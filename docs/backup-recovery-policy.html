가상 사건 데이터는 장애 후 다시 만들 수 있다. 발표·블로그에 쓰는 원래 로그·캡처·검증 수치는 반드시 보존한다. 다시 실행한 시험의 결과로 과거 증거를 대체하지 않는다. 이 구분을 바탕으로 아래 주기·목표·보관 기간을 승인했다. 구매, 계정·버킷·금고·DNS 생성, 외부 배포, 예약 작업 설치는 승인하거나 수행하지 않았다.

전체 준비는 O5 결정표, 후속 구현은 이슈 #6에서 추적한다. 목표 승인으로 F1 전체 또는 F2~F6이 완료되지는 않는다.

1. 승인한 주기와 목표

RPO는 잃어도 되는 최근 자료의 범위, RTO는 다시 사용할 수 있을 때까지 허용하는 시간이다. 서비스 복구, 증거 회수, 발표 계속하기를 별도 목표로 관리한다. 아래 값은 공급자의 보장이나 이미 측정한 성과가 아니다. AWS 복구 목표 안내

DB 백업은 일관된 스냅샷, 암호화 외부 사본, 무결성 확인이 성공해야 최근 성공 시각을 갱신한다. 매일 실행한다는 설정만으로 RPO 24시간을 달성한 것으로 보지 않는다. 실패·지연으로 최신 성공 백업이 24시간보다 오래되면 목표 위반을 알리고 재시도하며, 실패한 백업은 정상 세대를 밀어내지 않는다. 실행 중 로그도 마지막 외부 복사 성공 이후 5분을 넘으면 목표 위반으로 기록한다. 이 감시·알림은 후속 구현이다.

서비스 RTO 2시간은 서비스 중단부터 HTTPS 로그인과 새 가상 사건 갱신이 다시 가능할 때까지다. 인지·대응, 계정·키 회수, 다운로드, 서버 준비, DB 복원, 최신 revision 대조·명시 인수 시간을 포함한다. 증거 회수 15분은 원래 서버를 사용할 수 없는 상태에서 회수를 시작해 복호화·해시 확인 후 파일을 열 때까지다. 발표 전환 5분은 장애로 시연이 중단된 시점부터 대체 자료로 설명을 계속할 때까지다.

2. 증거를 보존 완료로 표시하는 조건

각 시험의 실행 ID·시각별로 다음을 한 묶음으로 만든다.

  • 성공과 실패를 포함한 원본 로그, 캡처, 가공 전 측정값과 요약 수치
  • 코드 커밋, 이미지 식별자, 실행 환경·명령, 시작·종료 시각과 측정 조건
  • 파일 목록과 SHA-256 해시, 공개용 사본을 만들었다면 가림·변환 내역

작업용 사본 외에 서로 독립된 두 곳으로 복사하고, 각 사본을 다시 읽어 해시·파일 열람이 되는지 확인해야 보존 완료로 표시한다. 후보 구성은 작업 PC + 별도 계정의 비공개 S3 + 다른 물리 장소에 분리 보관한 오프라인 매체다. 같은 PC의 폴더 두 개, 계속 연결된 같은 장소의 매체만으로 독립 사본 둘을 충족했다고 판단하지 않는다. 독립 사본을 확인하기 전 원본을 정리하지 않는다. 저장소·매체의 실제 선택과 접근 검증은 아직 남아 있다.

손실 0은 보존 완료된 묶음에 대한 목표다. 생성 중인 자료, 아직 외부 복사가 끝나지 않은 로그까지 무손실을 보장하지 않는다. 중요한 측정 후에는 보존 확인을 다음 시험이나 환경 정리보다 먼저 수행한다. 보존이 실패하면 시험 결과와 보존 실패를 함께 기록하며 보존 완료로 표시하지 않는다.

원본에 자격증명·개인정보가 포함되면 비공개 암호화 사본으로 제한하고 GitHub에는 가림 처리한 공유본만 남긴다. 가림으로 측정값을 바꾸지 않는다. Git 이력과 CI 로그·첨부파일·PR/Checks 정보의 보관 범위는 다르므로 필요한 CI 자료와 메타데이터도 별도 묶음에 넣는다. 현재 CI 설정의 첨부파일 보관은 7일이다. GitHub에 링크만 남기는 것은 증거 파일의 장기 보존을 대신하지 않는다. GitHub 저장소 백업 안내

4. 계정·키는 본인이 단독 관리한다

사용자는 보조 담당자 없이 본인 한 명이 관리하기로 했다. 공개 문서에는 역할만 기록하고 계정 이메일·결제 정보·키·복구 코드·보관 장소의 상세는 넣지 않는다. 운영/백업 AWS 계정 분리와 Bitwarden 무료 개인 금고·암호화 USB·종이 복구 안내서 구성은 승인했다. 실제 계정 생성·매체 확보·보관 장소·접근 시험은 미완료다.

계정 수와 담당자 수는 다르다. 한 사람이 운영하며 운영용 AWS 계정과 백업용 AWS 계정을 분리하기로 확정했다. 계정 분리는 운영 계정의 실수·권한 오용이 백업 관리까지 번지는 범위를 줄인다. 같은 이메일 계정·기기·금고의 침해가 양쪽 접근으로 이어질 수 있어 복구 경로도 확인해야 한다. 실제 계정·이메일·결제·접근 경로는 아직 준비하지 않았다. AWS 계정 분리 지침

소유자 접근, 일상 관리, 서버 자동 작업의 권한을 나눈다. root는 필요한 소유자 작업에만 쓰고 서버에 root 자격이나 백업 관리자 권한을 두지 않는다. 자동 업로더에는 필요한 업로드·검증 읽기만, revision 런타임에는 필요한 읽기·조건부 갱신만 주며 삭제·보존 설정 변경은 금지하는 안이다. 실제 권한 거부 시험이 필요하다. AWS root 관리 지침

O4는 대칭키로 백업을 만들기 때문에 제한된 작업용 키가 서버에도 필요하다. 서버 밖 사본은 키 유실 대비이며, 서버 침해 시 작업용 키 유출 위험까지 없애지는 않는다. 본인이 부재하거나 대응할 수 없으면 대신 복구할 사람이 없다. 서비스 복구 2시간 목표는 그대로 유지하며, 본인의 대응 가능 여부와 실제 시험으로 달성 가능성을 판단한다. 이 한계를 숨기거나 목표 측정 시작을 복원 명령 시점으로 늦추지 않는다.
