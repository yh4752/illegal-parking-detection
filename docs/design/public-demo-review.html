착수 전에 더 결정을 기다릴 필요가 없는 것

백엔드·프론트 기술, API 경로, 데이터 계약, 권한 매핑, 최신성 기준, SSE 복구, 첫 화면, 자동 시험, 배포 형태를 정했습니다. AI 팀의 보드 언어·카메라 결정 없이 계약에 맞는 가상 장치로 구현할 수 있습니다. 서버는 차량 판정을 새로 수행하지 않습니다.

실제 실행하며 검증할 것

  • 기존 수신 코드에서 공통 구역 쓰기를 추출할 때 중복·충돌·역순 처리 회귀가 없어야 합니다.
  • Spring MVC의 SSE 연결 timeout을 개별 write timeout으로 오해하면 안 됩니다. 5초 전송 제한과 느린 연결 종료가 실제 Tomcat/Nginx 환경에서 동작하는지 PD13/18에서 확인하고, 달성하지 못하면 메커니즘을 수정한 뒤 완료 처리합니다.
  • 세션 활동과 자동 HTTP 조회를 구별합니다. 현재 결정은 HTTP 조회도 idle을 연장하되 absolute 8시간에서 종료합니다. ‘사람이 마우스를 움직인 시간’을 서버가 안다고 가정하지 않습니다.
  • EventDetail 전체 원문 배열은 큰 응답이 될 수 있습니다. 첫 범위의 시나리오 데이터로 응답 크기와 지연을 남기고, 상한이 필요하면 몰래 자르지 않고 계약 변경으로 처리합니다.
  • 50 SSE 연결·4 worker 등의 값은 운영 초기값이며 측정 성능이 아닙니다. CI 기능 시험 결과를 실차 정확도·수백 대 처리 성능으로 표현하지 않습니다.
  • DB 복원은 manifest 최신성·대조 수신·운영자 인수가 필요합니다. 같은 범위 내 과거 DB 복원은 현재 코드가 자동 감지하지 못합니다.

외부 공개 전에만 필요한 입력

서버/계정·예산, 도메인/DNS, 계정 전달 대상, DB 복원 밖 revision 사본과 백업 위치를 확인해야 합니다. 지금 로컬 구현·자동 시험을 막는 항목은 아닙니다. 실제 외부 접속 증거가 없으면 M6를 완료 처리하지 않습니다.

기능 시험의 목록과 상태는 작업·인수 조건 JSON, 이번 문서 검사의 실제 결과는 설계 검증 기록에 둡니다. 둘을 혼동하지 않습니다.
