사건 수신·저장·ACK의 정상·중복·충돌·역순 처리를 MQTT/SQL로 확인했습니다. 로그인·조회 API와 heartbeat·실시간 화면을 작성했고, 인계 환경을 통합 시험 중입니다. 공개 배포와 외부 접속 검증은 별도입니다. 그림은 목표 구조이며 구현·시험의 실제 범위는 현재 상태에서 확인하세요.

오늘 프론트 인계를 위한 작업표

인계 브랜치에서 React·heartbeat·SSE·가상 장치·별도 실행 구성을 작성했습니다. 로컬 검사 후 새 체크아웃 Docker/브라우저 통합 검사를 진행 중입니다. 아래 표의 미착수 표시는 이전 계획이며 최종 판정은 검증 기록과 후속 현황으로 갱신합니다. 공개 서버/DNS·상대방 저장소 접근은 아직 확인되지 않았습니다.

현재 어디까지 되었나요?

로그인·권한·조회 API 완료 세션·CSRF·구역 권한, 상태·목록·상세 등 7개 경로
웹 계정 관리 완료 계정 생성·구역 권한 부여/회수·비활성화 CLI

heartbeat·SSE 미구현 장치 연결 최신성 판정과 브라우저 실시간 전달 필요
재현 가능한 통합 데모 일부 준비 예제 출력·등록 SQL·초기화 도구 있음. 자동 가상 장치와 브라우저 통합 시험 없음
공개 HTTPS·인계 미완료 배포 파일·공개 주소·외부 접속 검증·새 클론 시험 필요

테스트 수는 백엔드 검증 결과입니다. 프론트가 동작하거나 외부에서 접속할 수 있다는 증거가 아닙니다.

남은 작업과 순서

순서 작업 완료를 확인하는 방법 현재
H01 React + TypeScript + Vite, 라우팅, 계약 타입, API/인증 모듈 설치·타입 검사·빌드 성공, 실제 로그인과 CSRF 교체 미착수
H02 로그인 / 구역 현황 / 사건 목록·상세 3종 화면 실제 API로 자료 표시. 로딩·빈 값·권한·만료·오류/재시도 구분 미착수
H03 별도 데모 DB·계정·가상 사건·실행 절차 가상 메시지 → MQTT → DB → API → 화면의 ID·순번 일치 일부 도구 있음
H04 heartbeat·연결 상태·SSE와 화면 결합 송신 중지 시 STALE/OFFLINE, 복귀·재접속 시 최신 상태, 권한 회수 시 전송 중단 미구현
H05 배포 구성·HTTPS·계정·복구 검증 같은 HTTPS 주소에서 화면/API/SSE 사용, 내부 포트 비공개, 재시작·백업/복원 확인 미구현·접속 정보 필요
H06 프론트 인계 문서·수정 경계·GitHub 접근 담당자가 어디를 고칠지 알고 저장소를 받을 수 있음 기존 공통 문서만 있음
H07 새 클론·외부 PC에서 최종 인수 담당자가 로그인→상태→이력→로그아웃을 재현, 재연결·계정 회수 확인 미수행

실행 순서는 H01 → H02 → H03 → H04 → H05 → H07입니다. H06 문서는 코드와 함께 작성합니다. 배포 환경·저장소 접근 정보는 화면 작업과 별도로 미리 확인합니다. 상세 구현은 공개 데모 설계, 원래 단계와 인수 조건은 작업 JSON을 따릅니다.

오늘 우선 만들 화면

화면 먼저 보여줄 것 포함할 실패 상태
로그인 아이디·비밀번호, 로그인/로그아웃 인증 실패·시도 제한·세션 만료
구역 현황 사건 상태·차량 분류·안내 횟수·관측 시각·카메라 상태·연결 상태 아직 관측 없음·과거 자료·통신 오류·접근 권한 없음
사건 목록·상세 기간/상태 필터, 다음 페이지, 사건 요약·수신 이력 빈 목록·404·410·403·조회 실패

첫 화면은 REST로 검증합니다. H04 이전에는 새로고침으로 다시 조회할 수 있게 하고, 실시간으로 동작하는 것처럼 표시하지 않습니다. 사건을 받았다는 이유만으로 장치를 ONLINE으로 만들지 않습니다. SSE를 붙이면 기존 설계대로 최초/재접속 REST 조회와 revision 비교를 적용합니다. 사건 이력의 10초 재조회는 SSE와 별개입니다.

주차 지도·내 차 찾기·영상 스트리밍·장식용 제어 버튼은 이번 불법주정차 안내 시스템의 첫 인계 범위에 넣지 않습니다. 가상 데이터에는 ‘가상 장치 데모’를 표시합니다.

인계 전 체크리스트

  • frontend/에 실행 코드·lockfile·환경변수 예시가 있고, 설치/실행/빌드 명령이 검증되어 있다.
  • 성공 DTO는 유효 OpenAPI에서 생성한 타입을 사용하고, API 경로·필드를 임의로 축약하지 않는다.
  • 실제 서버와 로그인·CSRF 재발급·상태/이력 조회·로그아웃이 연결되어 있다.
  • 구역 ID는 서버에서 허용한 대상을 사용한다. 미구현 구역 목록 API나 브라우저의 자체 권한 판단을 추가하지 않는다.
  • 브라우저·서버 오류, 장치 연결 상태, 카메라 상태를 서로 다른 표시로 구분한다.
  • 키보드 조작·입력 label·로딩·빈 상태·오류·세션 만료를 실제 화면에서 확인했다.
  • 별도 데모 자료로 MQTT 저장 결과와 화면을 대조했다. 기존 사용자 DB를 초기화하지 않았다.
  • API/인증/SSE 모듈과 화면·스타일을 나누고 frontend/README.md·AGENTS.md에 수정 범위를 적었다.
  • 전달할 브랜치/커밋, 실행 방법, 미구현 기능, 확인한 테스트를 명시했다.
  • 담당자의 저장소 접근과 계정 전달 방법을 확인했다. 비밀번호·서버 비밀값은 저장소/문서에 넣지 않았다.
  • 공개 URL은 외부 PC에서 HTTPS 로그인·조회·SSE·재로그인을 확인했다.
  • 새 클론에서 실행과 수정 후 빌드를 재현했다.

오늘 전달할 때의 완료 판정

코드 인계 가능: H01~H03, H06과 새 클론 실행 검증이 끝난 상태입니다. 담당자가 실제 API에 연결된 UI를 받아 수정할 수 있습니다. 공개 주소가 준비되지 않았다면 ‘로컬 실행 인계판’이라고 분명히 적습니다.

원래 요청한 공개 인계 완료: 여기에 H04·H05와 외부 접속 검증까지 끝난 상태입니다. 팀원이 HTTPS 주소로 로그인하고 실시간 변화를 확인합니다. 로컬 코드 인계만으로 이 목표가 완료되었다고 표시하지 않습니다.

현재는 두 기준 모두 미완료입니다. 오늘 공개 완료 여부는 남은 구현·통합 시험과 서버/DNS 준비에 달려 있습니다. 우선 H01/H02에 착수하여 실행 가능한 화면을 확보하고, 위 체크리스트에 실행 증거가 생긴 항목만 완료 처리합니다.
