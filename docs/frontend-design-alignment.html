프론트 시안을 기존 프로젝트에 적용하는 기준

2026-11-15 · 공통 개발 기준 main · 제품 동작 v1.43

제공받은 주차관리_Edge_통합관제.html의 색·메뉴·카드 배치를 기존 React 앱에 적용한다. HTML의 CSS·문구·시나리오 코드를 검토한 결과이며, 브라우저에서 시안의 전체 사용성을 시험한 결과는 아니다. 시안 파일은 참고 자료이고 실제 데이터·상태의 기준은 서버 응답이다.

먼저 맞출 차이

항목 전달받은 시안 이번 적용 기준과 근거
정차·안내 시간 1분 감지 → 3분 현장 안내 → 5분 관리자 확인 정차 후보 3초 확인 → 같은 유효 후보 300초와 출력 조건 충족 시 첫 안내 → 고정한 최초 후보 시작에서 600초 미해소 시 관리자 확인. A1, A2
반복 안내 3분 안내 중심의 고정 장면 같은 사건 최대 2회. 첫 재생 종료 후 30초 이상이면서 현재 유효 후보가 300초 이상이어야 재안내. 10분 미해소 이후 새 안내 금지. A2
가림 후 복귀 정상화 버튼으로 곧바로 안내 장면 복귀 품질 5초 연속 정상, 동일성·중지 사유 해소 등 조건 확인 후 새 정차 후보를 쌓음. 카메라 방향 변경·수동 중지를 자동 해제하지 않음. A1, A3, C5
차량 이탈 미리 만든 이탈 장면 선택 같은 차량의 구역 밖 이동을 3초 연속 실제 관측해야 종료. 미검출·통신 단절은 이탈 아님. A2
제어 완료 시뮬레이션 ACK 버튼으로 중지/재개 적용 요청·수신·장치 적용 결과를 구분. 이벤트 저장 ACK는 명령 적용 확인이 아님. 실제 명령 기능은 아직 미구현이며 이번 UI에서 가짜 성공으로 추가하지 않음. C5, 구현 상태
사건 이력 이력 행 선택 시 현재 시연 상태도 변경 과거 사건 상세를 조회하며 현재 구역 상태는 그대로 유지
상태 신뢰 고정된 정상/빈 구역 상태와 시연 값 최초 관측 전·차량 없음·장치 통신·카메라 품질·웹 연결을 구분. 단절 시 마지막 관측임을 표시. 인계 설명서
현장·지도 서울 → 광진구 → 세종대 앞, GWJ-001 우선 실제 연결된 단일 구역 화면부터 적용. 실험 장소는 미정이며 장소·구역 ID를 임의로 확정하지 않음. 서울 전체 지도와 여러 현장 데이터는 이번 구현 범위 밖
처리 용어 현장 확인·단속 처리 요청 관리자 확인·현장 조치 요청. 과태료·법적 단속 기능으로 표현하지 않음. 프로젝트 범위

위 시간은 엣지의 판단 규칙이다. 프론트가 자체 타이머로 사건 상태를 바꾸거나 안내를 실행하지 않는다. 서버가 전달한 상태·후보 시간·안내 결과를 표시한다. 정차 후보가 초기화돼도 최초 미해소 기준 시각은 유지될 수 있으므로 5분 안내 시간과 10분 미해소 시간을 같은 카운터로 만들지 않는다.

최근 차량 분류 논의와 구분

일반/예외 차량 2개 분류, body_type 형태 분류 요구 완화, 예외 차량의 유효 연속 정차 300초 후 관리자 웹 표시·이력 기록은 최근 논의한 변경 방향이다. 예외 차량의 알림은 LED·음성 이동 안내를 뜻하지 않는다.

이 내용은 현재 v1.43 원본과 실행 계약에 반영되지 않았다. 이번 프론트 적용에서는 기존 v1.43 동작을 우선하고, 새로운 예외 차량 분류값·자동 예외 처리를 임의로 추가하지 않는다. 백엔드·AI 계약 변경을 문서와 예제로 반영한 뒤 UI를 연결한다. body_type 필드도 현재 구현에서 임의 삭제하지 않는다. 기존 사고·공사 등의 관리자 중지 설계와 자동 예외 차량 분류는 별개다.

이번 PR에 담을 것

  1. 다크 테마·청록색 포인트, 사이드 메뉴, 상태 카드와 상세 패널 배치를 React 컴포넌트·CSS로 적용한다.
  2. 이미 동작하는 로그인·구역 상태·사건 목록/상세부터 개선한다. 로그인·로그아웃·세션·CSRF·권한과 REST/SSE 연결을 유지한다.
  3. 시안의 하드코딩 데이터·시나리오 전환 함수를 실제 화면의 상태 처리로 옮기지 않는다. 고정 OP 사용자, 브라우저 메모리에만 남는 사건 이력도 실제 사용자·조회 API로 대체한다.
  4. 새 영상·사진·지도·수동 제어·정책 변경 버튼은 이번 PR에 넣지 않는다. 후속 기능이 필요하면 화면 요구와 필요한 API를 정리해 별도로 협의한다.
  5. 이미 클론한 경우 CONTRIBUTING의 main 전환 절차를 따르고, feat/console-ui 같은 본인 브랜치에 커밋·push한 뒤 main 대상 PR을 만든다.

PR에 남길 확인 결과

  • 로그인 → 구역 상태 → 사건 상세 → 로그아웃이 실제 API로 동작
  • 가상 장치 송신 후 상태·이력이 갱신되고, 이력 조회가 현재 상태를 바꾸지 않음
  • 첫 관측 전·빈 이력·오류·장치 응답 지연/연결 미확인 표시 유지
  • 모바일·키보드 이동·경고 문구가 새 배치에서도 확인 가능

  • 통신·사용 흐름 변경 시 격리된 환경의 E2E도 확인. 변경 전후 화면과 미구현 범위 첨부

시안 적용 완료 여부는 이 목록으로 확인한다. v1.43의 모든 현장 기능 구현이나 실제 보드 시험 완료를 의미하지 않는다.
