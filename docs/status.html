O2 로컬 HTTPS 구현·인수 (2026-11-16)

로컬 HTTPS 안내에 요청 흐름 그림, 실행 명령, 설정 이유, 오류별 확인 순서를 정리했다. infra/deploy/compose.yaml·Nginx로 같은 출처의 HTTPS 화면/API/SSE를 연결했다. 학습 환경은 parking-https, HTTPS 18443/HTTP 18480의 localhost 바인딩만 사용한다. DB·MQTT·Spring은 호스트 포트를 열지 않는다.

새 DB 전용 초기화와 별도 operator 계정 관리, 파일 secrets, 로컬 이미지 ID·설정 해시 대조, 데이터 보존 중지/기동, web 인증서 갱신/reload 도구를 추가했다. 시스템 인증서 신뢰 저장소는 바꾸지 않는다. 학습 Chromium은 시험 인증서 공개키 하나만 허용하고, 별도 HTTPS 클라이언트가 CA/SAN을 엄격히 검사한다.

Chromium에서도 로그인·가상 사건·오프라인/재접속·로그아웃을 실행했다. 네트워크/이미지 보호 단위 검사 5개, 프론트 24개와 계약 생성·포맷·타입·빌드 검사도 통과했다. O2 검증 기록에 실행 범위·이미지 ID·소스 해시를 보관했다.

당시에는 CI job만 추가했고 원격 실행은 하지 않았다. 이후 공유 검증은 위 최신 요약을 따른다. 로컬 Linux ARM64 컨테이너 결과이며 Linux x86_64 서버·공인 인증서/ACME·외부 PC 인수는 미수행이다. 기존 v1.43 원본·제품 계약·기존 로컬 서비스는 보존했다.

O3 로컬 모니터링 구현·인수 (2026-11-16)

Micrometer 업무 계측, 파일 인증을 쓰는 별도 관리 포트 9091, 5초 간격 DB/revision 읽기 probe를 추가했다. Prometheus가 15초마다 수집하며 Grafana의 21개 패널·13개 경보로 수신·커밋·ACK·연결·SSE·JVM/풀·Linux 자원·내부 HTTPS를 구분한다. 사람용 모니터링 안내에 역할·지표 이유·그래프 해석·실습을 정리했다.

DB 커밋 후 ACK 발행은 MQTT 5 PUBACK reason code까지 확인한다. 브로커의 거부 응답을 성공으로 세지 않으며, 성공도 장치의 응용 처리 완료를 보장하지 않는다. 브로커 단절은 기존 조회 readiness를 내리지 않고, DB/revision 문제는 liveness와 별도로 표시한다.

학습 환경은 parking-monitoring: HTTPS 19443/HTTP 19480과 Grafana 13000만 localhost에 바인딩한다. 기존 O2 환경과 별도 DB·인증서·계정을 쓴다. Prometheus·management·exporter는 호스트에 공개하지 않는다. Grafana 계정은 monitoring-admin, 비밀번호는 .local-state/monitoring/secrets/grafana-password다.

최종 격리 인수는 **O3_ACCEPTANCE_PASSED**로 통과했다. 실제 DB 쓰기 거부·DB 정지·ACK ACL 거부·MQTT 단절·revision hold·backend 중단과 복구를 실행했다. 지표·경보 발생/해제, Prometheus·Grafana 재시작 후 같은 과거 수집값 조회, 제품 이력 보존을 확인했다. Chromium에서 로그인·가상 사건·정상 상태 값·그래프 데이터와 실제 경보 행까지 검사했다. 일반 백엔드 166개, DB 76개, 프론트 24개, 네트워크/이미지 보호 8개, 규칙 시계열 19개와 계약 보호 6개 시험을 통과했다. ACK 경로 변경 후 O1 TLS/권한 및 O2 HTTPS 전체 인수도 다시 통과했다. O3 검증 기록에 실제 범위·이미지·해시를 기록했다.

자원 수집은 Docker Linux runtime과 exporter 루트 파일시스템 범위다. macOS 전체·실서버 DB/백업 디스크를 모두 검증한 것은 아니다. 실제 디스크 고갈 대신 경보 규칙을 합성 시계열로 시험한다. 외부 알림·서버 전체 장애 관측·실서버 배포는 O5, 검증 백업 시각과 복원은 뒤의 O4에서 구현·인수했다. 당시에는 GitHub CI job만 추가했고 원격 실행은 하지 않았다. 이후 공유 검증은 위 최신 요약을 따른다.

O4 로컬 백업·독립 revision·복원 인수 (2026-11-16)

**O4_ACCEPTANCE_PASSED**로 실제 로컬 복원 훈련을 통과했다. 백업·복원 설명서에 두 자료의 차이, 번호 예시, 복원 순서와 실습 명령을 정리했다. 별도 parking-backup 환경에서만 실행했으며 외부 배포·기존 O2/O3 데이터 변환은 하지 않았다.

읽기 전용 pg_dump, SQLite backup API, 별도 키의 인증 암호화, 복호화 후 임시 DB 복원과 전 테이블 행 수/내용 비교를 구현했다. 독립 기록은 내부 전용 HTTP·SQLite 버전/CAS 참조 어댑터이며 DB 백업과 함께 되돌리지 않는다. 예약/초기화 claim은 독립 기록 → 로컬 두 파일 → DB 순서다. 백업 완료 뒤에도 새 범위로 옮겨 복원본과 최신 기록을 구분한다.

DB-only 및 DB+두 파일 롤백 시 실제 backend 기동 거부, hold 중 API/SSE·일반 사건/중복 ACK/heartbeat/정리 차단, 오프라인 장치 보고 대조·감사 증거, 보고서 해시와 손실 인수 후 새 revision 재개, DUPLICATE 재전송을 시험했다. 독립 기록 단절은 gate를 닫으며 연결만 돌아와도 자동 개방하지 않는다. 기존 자료 adopt·상한 건너뛰기·예약 단계별 중단 상태·잘못된 숫자·누락/변조·CAS 경쟁·오래되거나 대조 증거 없는 인수 보고서도 시험했다.

백엔드 일반 169개, PostgreSQL 85개, Python 도구 30개가 통과했다. 실제 Prometheus의 검증 백업 시각/유효성, Grafana 전용 3개 패널, O4 경보 2개와 합성 조건을 확인했다. 이번 작은 가상 자료의 HTTPS 복구는 85.65초, 선택 백업 나이는 72.81초였고 백업 이후 ACK된 사건 1건이 과거 복원본에 없었다. 이는 해당 훈련 실측이며 운영 RPO/RTO 보장이 아니다. 검증 JSON에 실행 명령·이미지·해시·범위와 한계를 기록한다.

모든 저장소와 키는 같은 PC에 있다. 외부 저장소 API·TLS·내구성·독립 키 보관·호스트 전체 유실·실제 장치·PITR/WAL·대용량·운영 스케줄/자동 보존 삭제·외부 알림은 미수행이다. O4 인수 당시에는 원격 실행·커밋·푸시 전이었다. 이후 공유 상태는 위 최신 요약을 따른다. 메모리 여유를 위해 새 O4 환경은 데이터 보존 상태로 중지하고 기존 O3 학습 환경을 재개한다.

O5 배포 준비 문서 (2026-11-16)

배포 준비 안내에 학교 서버의 확인 조건, Lightsail 4GB/8GB 후보, 월 6만/10만 원 관리 예산과 첫 달·3개월 지출, 도메인/DNS/갱신 책임, 별도 계정의 S3 백업·revision 버킷, 주·부 담당자의 금고·추가 키 사본을 정리했다. 공식 단가와 계획용 환율·사용량 가정을 예산 예시로 분리했다. 추천안은 미확정이고 입력 양식의 실제 선택값은 미정으로 남겼다.

O5 상태는 준비 문서 작성이며 외부 배포 인수 완료가 아니다. 실제 S3 원장 어댑터·운영 백업 자동화·호스트 없는 키 회수/복원·공인 인증서·linux/amd64 registry release·외부 가용성/알림·서버 부하 시험이 남아 있다. 현재 LOCAL_ONLY 제한과 128MiB 백업 도구 한계도 안내했다. 자원 구매·계정/버킷 생성·DNS 변경·키 생성/공유·외부 배포를 하지 않았다.

이번 문서·예시 변경의 문서 재생성, 구조/링크·v1.43 보존, 계약 생성 일치, JSON·비용 산식과 공백 오류 검사를 통과했다. O1~O4 실행 결과를 이번에 다시 실행한 것으로 세지 않는다. 실제 명령과 결과는 O5 준비 검증 기록에 보관한다.
