## 최신 운영 작업 요약

**O1~O4는 로컬 구현·인수 완료, O5는 준비 문서 작성 상태다.** 운영 코드·문서·실행 증거의 변경 이력은 [PR #5](https://github.com/yh4752/parking-system/pull/5)에서 확인한다. 실제 반영 상태는 PR의 병합 기록과 [main의 CI](https://github.com/yh4752/parking-system/actions/workflows/verify.yml?query=branch%3Amain)를 따른다. 코드 병합은 외부 배포·실서버 인수 완료를 뜻하지 않는다. 아래 과거 단계별 수치는 당시 기록이며 최신 값과 합산하지 않는다.

| 단계 | 현재 상태 | 먼저 읽을 자료 |
|---|---|---|
| O1 운영 프로필·DB 역할·MQTT TLS/인증/ACL | 로컬 인수 완료 | [개념·이해 질문](production-basics.md) |
| O2 HTTPS·Nginx·로그인/SSE | 로컬 인수 완료 | [HTTPS 실습](local-https.md) |
| O3 Prometheus·Grafana·장애 경보 | 로컬 인수 완료. 외부 알림 미구현 | [모니터링](local-monitoring.md) |
| O4 백업·독립 revision 참조 구현·복원 | 로컬 인수 완료. 실제 호스트 독립성 미검증 | [백업·복원](local-backup.md) |
| O5 실제 자원·외부 배포 | 추천/입력표 완료. 실제 자원·외부 어댑터·배포 인수 미완료 | [배포 준비](deployment-readiness.md) |

**남은 운영 작업은 [후속 이슈 #6](https://github.com/yh4752/parking-system/issues/6)에서 추적한다.** F1 자원·비용·책임·복구 목표 확정 → F2 외부 revision 어댑터 → F3 자동 백업·보존·키 회수 → F4 실제 서버·HTTPS·릴리스 준비 → F5 서버 유실 복구·외부 관측/알림 → F6 팀원 외부 PC 인수 순서다. 각 항목의 의존 관계와 완료 증거를 이슈에 기록했으며 모두 후속 범위다. 첫 단계는 [비밀값 없는 결정표](deployment-readiness.md#6-지금-준비할-결정표)를 채우는 것이다. 이슈 등록이나 main 병합으로 유료 자원 생성·DNS 변경·외부 배포가 실행되지는 않는다.

실물 보드·AI/실차 성능·LED/스피커·관리 명령·정책 변경·사진 기능은 운영 후속과 별도의 제품 작업으로 남아 있다.

기존 O4 기록의 백엔드 일반 **169개**, PostgreSQL **85개**, Python 운영 도구 **30개**는 당시 실행 수치다. 현재 운영 도구 검사는 후속 회귀를 포함해 **34개**다. 프론트 **24개** 등 다른 범위는 각각의 기록 날짜를 따른다. 11월 16일 복원 **85.65초**, 17일 재검증 **100.30초**는 각각 작은 로컬 자료의 복원~준비 구간이며 전체 장애 RTO나 성능 개선 비교가 아니다. 보존한 [로그·캡처·측정 근거와 학습 질문](operations-learning-evidence.md)에 조건과 한계를 함께 기록했다.

PR 반영 전 재검사와 원격 CI는 [PR 공유 검증 기록](../validation/pr5-publication-2026-11-16.json)을 기준으로 한다. 원격 실행은 로컬 수치와 구분하며, GitHub Checks 통과도 실제 외부 배포·팀원 PC 인수를 대신하지 않는다.

첫 Linux CI(`3654f91`)는 8개 작업 중 6개가 통과했고 O2·O4에서 환경 차이를 발견했다. O2는 중단된 backend의 504를 502로 바뀔 때까지 기다리던 검사 가정을 수정했고, O4는 비공개 원장 폴더의 소유자 UID:GID로 실행하도록 수정했다. [실패 발췌·권한 재현 근거](operations-learning-evidence.md#6-linux-ci에서-확인한-환경-차이)를 보존했다. 과거 O4 해시 기록은 변경하지 않으며, 수정 후 정확한 커밋과 최종 원격 결과는 [PR #5 Checks](https://github.com/yh4752/parking-system/pull/5/checks)와 PR 본문에서 확인한다.

후속 Linux 검증에서는 O4 전체 복원을 포함해 7개 작업이 통과했고, O2의 자동 subnet에 특정 IP를 지정하던 시험도 주소 자동 할당으로 수정했다. 새 backend IP가 실제로 달라야 한다는 검사는 유지한다. 로컬 O2 재검사는 통과했다. 당시 추가 로컬 O4는 Docker 실행 환경 오류·시간 초과로 미완료였으며, 아래 11월 17일 별도 재검증으로 완료했다.

`71b12c6`의 Linux O2 인수도 통과했다. O3 반복 검증에서는 초기 지표의 단일 값이 없을 때 비교 오류가 나와, 네 수집 대상의 존재와 각 지표의 실제 양수 값을 제한 시간 안에 확인하도록 보강했다. 미수집·지속 부재 회귀 시험 2개를 더한 당시 Python 운영 도구 검사는 **32개**였으며, 과거 O4의 30개 기록은 그대로 둔다.

**2026-11-17 로컬 O4 재검증 완료:** 이전 34초 시간 초과와 같은 시간대의 Docker OOM 보고를 확인했다. O2/O3 학습 컨테이너 12개만 잠시 중지한 뒤 별도 `parking-o4-*`에서 기존 시간 제한으로 `O4_ACCEPTANCE_PASSED`를 확인했다. 첫 가상 장치 실행은 **5.08초**, 복원~준비는 **100.30초**, 관측 중 OOM 증가 **0**이었다. 과거 실패에서 어느 프로세스가 직접 멈췄는지는 출력이 폐기돼 단정할 수 없다. 명령 시간 초과 때 비밀값을 가린 부분 출력·제한 시간을 보존하도록 수정했고 회귀 2개를 추가해 **34개**가 통과했다. 기존 O4 볼륨 **7개·1,833항목**과 원장·키 등을 포함한 **47항목**의 전후 해시가 일치하며, 학습 컨테이너는 원래 실행 상태로 돌렸다. [새 실행·보존 근거](../validation/o4-local-recheck-2026-11-17/summary.json)와 [원인·한계 설명](operations-learning-evidence.md#7-로컬-o4의-34초-시간-초과를-다시-확인하기)을 함께 읽는다.

## 이전 프론트 인계판 검사 기록 (2026-11-14)

이 절의 기록은 운영 작업 전 인계판 기준이다. 당시 로컬 자동 검사: 백엔드 일반 **144개**, PostgreSQL **75개**, 프론트 **24개**, 가상 장치 **3개**, 계약 보호 **6개**. 빌드·타입 검사도 수행했습니다. 버전·커밋·CI별 성공 여부와 수정 이력은 [검증 JSON](../validation/frontend-handoff-2026-11-14.json)을 기준으로 합니다.

별도 Linux CI에서 처음 설치부터 Docker 기동·실제 브라우저 로그인·MQTT 저장·SSE·모바일·재접속을 검사합니다. 뒤늦은 낮은 순번 원문도 현재 구역 revision을 바꾸지 않고 상세 화면에 자동 반영되는지 확인합니다. DB 단절 중 성공 ACK 금지, 브로커 단절 시 outbox 보존과 복귀, 서버 재시작 후 이력 보존·이전 세션 무효화도 실제 서비스로 시험합니다.

사용자가 기존에 실행한 `parking-local`의 DB·컨테이너는 초기화하지 않았습니다. 인계 환경은 `parking-handoff`, 포트 18080/18081, 별도 DB/볼륨/쿠키를 사용합니다. CI 통과는 상대방 PC에서의 실제 인수나 외부 HTTPS 접속 성공을 대신하지 않습니다.

## 배포·운영 설계 추가 (2026-11-16)

[배포 요약](deployment-operations.md)·[운영 구현 명세](design/deployment-operations-plan.md)·[작업 JSON](design/deployment-operations-workplan.json)을 작성했다. 단일 Linux/Compose/Nginx, 운영 프로필·TLS/ACL·DB 권한 분리·지표·독립 revision 기록과 복원 인수 기준을 정했다. 구현 전 검토에서 로컬 MQTT 설정, health와 readiness의 혼동, 과거 DB/manifest 동시 복원, ACK 이후 데이터 손실 경계를 확인해 반영했다.

최초 설계 커밋은 문서·입력 양식만 추가했다. 이후 O1에서 다음을 구현했다. 클라우드 자원 생성과 외부 배포는 하지 않았다. 서버·도메인·독립 저장소·알림 경로는 입력이 필요하다. 기존 v1.43 원본과 실행 계약은 유지한다.

## O1 운영 프로필·권한 구현 (2026-11-16)

- `app-prod`와 공통 `mqtt-ingest`, 필수 configtree 파일·로컬 프로필 혼합 거부, Secure cookie와 runtime 전용 DB 설정.
- migrator/runtime/operator/backup SQL 분리, 일회성 migration CLI, 실제 로그인·현재 역할·마이그레이션 검증. 사건 원문 UPDATE와 정책·계정 변경·DDL은 runtime에 허용하지 않는다.
- 세 MQTT 연결과 가상 장치의 TLS CA/SAN 검증·암호 인증, Mosquitto 2.0.22 장치별 ACL.
- 임시 Docker 환경의 자동 인수 시험과 CI job. 운영 구성 파일·입력 방법은 [운영 설정 안내](../infra/deploy/README.md)를 따른다.

백엔드 일반 **154개**, 별도 PostgreSQL 회귀 **75개**, 가상 장치 **6개**, 계약 보호 **6개**를 실행해 통과했다. O1의 최종 격리 인수 시험은 `O1_ACCEPTANCE_PASSED`로 통과했다. 파일 secret 누락 우회, 관리자 접속 후 역할만 낮추는 경우, 실제 서버·가상 장치의 TLS/계정 실패를 포함한다. 실제 저장·커밋 후 ACK, 중복/충돌/역순, DB 실패 시 ACK 금지·재시도, 보관 만료도 확인했다. [검증 기록](../validation/production-boundaries-2026-11-16.json)에 실행 범위와 소스 해시를 보관했다. 당시에는 GitHub CI job만 추가했고 원격 실행은 하지 않았다. 이후 공유 검증은 위 최신 요약을 따른다.

O1 다음에 O2의 로컬 HTTPS 인수를 완료했다. 모니터링 O3의 로컬 인수도 완료했다. O4 로컬 독립 revision 기록·복원 인수도 완료했다. DB 백업 계정의 dump 성공은 복원 성공이나 외부 공개 인수를 뜻하지 않는다.

## O2 로컬 HTTPS 구현·인수 (2026-11-16)

[로컬 HTTPS 안내](local-https.md)에 요청 흐름 그림, 실행 명령, 설정 이유, 오류별 확인 순서를 정리했다. `infra/deploy/compose.yaml`·Nginx로 같은 출처의 HTTPS 화면/API/SSE를 연결했다. 학습 환경은 `parking-https`, HTTPS 18443/HTTP 18480의 localhost 바인딩만 사용한다. DB·MQTT·Spring은 호스트 포트를 열지 않는다.

새 DB 전용 초기화와 별도 operator 계정 관리, 파일 secrets, 로컬 이미지 ID·설정 해시 대조, 데이터 보존 중지/기동, web 인증서 갱신/reload 도구를 추가했다. 시스템 인증서 신뢰 저장소는 바꾸지 않는다. 학습 Chromium은 시험 인증서 공개키 하나만 허용하고, 별도 HTTPS 클라이언트가 CA/SAN을 엄격히 검사한다.

최종 격리 인수는 **`O2_ACCEPTANCE_PASSED`**로 통과했다. 실제 TLS·HTTP 전환·로그인·CSRF·쿠키·MQTT 커밋/SSE·로그아웃·권한 회수·관리 경로 차단, 인증서 교체, backend 502/504·다른 IP로 재생성 후 DNS 복구·세션 초기화·이력 보존·query 로그 제외를 검증했다. Chromium에서도 로그인·가상 사건·오프라인/재접속·로그아웃을 실행했다. 네트워크/이미지 보호 단위 검사 **5개**, 프론트 **24개**와 계약 생성·포맷·타입·빌드 검사도 통과했다. [O2 검증 기록](../validation/local-https-2026-11-16.json)에 실행 범위·이미지 ID·소스 해시를 보관했다.

당시에는 CI job만 추가했고 원격 실행은 하지 않았다. 이후 공유 검증은 위 최신 요약을 따른다. 로컬 Linux ARM64 컨테이너 결과이며 Linux x86_64 서버·공인 인증서/ACME·외부 PC 인수는 미수행이다. 기존 v1.43 원본·제품 계약·기존 로컬 서비스는 보존했다.

## O3 로컬 모니터링 구현·인수 (2026-11-16)

Micrometer 업무 계측, 파일 인증을 쓰는 별도 관리 포트 9091, 5초 간격 DB/revision 읽기 probe를 추가했다. Prometheus가 15초마다 수집하며 Grafana의 21개 패널·13개 경보로 수신·커밋·ACK·연결·SSE·JVM/풀·Linux 자원·내부 HTTPS를 구분한다. [사람용 모니터링 안내](local-monitoring.md)에 역할·지표 이유·그래프 해석·실습을 정리했다.

DB 커밋 후 ACK 발행은 MQTT 5 PUBACK reason code까지 확인한다. 브로커의 거부 응답을 성공으로 세지 않으며, 성공도 장치의 응용 처리 완료를 보장하지 않는다. 브로커 단절은 기존 조회 readiness를 내리지 않고, DB/revision 문제는 liveness와 별도로 표시한다.

학습 환경은 `parking-monitoring`: HTTPS 19443/HTTP 19480과 Grafana 13000만 localhost에 바인딩한다. 기존 O2 환경과 별도 DB·인증서·계정을 쓴다. Prometheus·management·exporter는 호스트에 공개하지 않는다. Grafana 계정은 `monitoring-admin`, 비밀번호는 `.local-state/monitoring/secrets/grafana-password`다.

최종 격리 인수는 **`O3_ACCEPTANCE_PASSED`**로 통과했다. 실제 DB 쓰기 거부·DB 정지·ACK ACL 거부·MQTT 단절·revision hold·backend 중단과 복구를 실행했다. 지표·경보 발생/해제, Prometheus·Grafana 재시작 후 같은 과거 수집값 조회, 제품 이력 보존을 확인했다. Chromium에서 로그인·가상 사건·정상 상태 값·그래프 데이터와 실제 경보 행까지 검사했다. 일반 백엔드 **166개**, DB **76개**, 프론트 **24개**, 네트워크/이미지 보호 **8개**, 규칙 시계열 **19개**와 계약 보호 **6개** 시험을 통과했다. ACK 경로 변경 후 O1 TLS/권한 및 O2 HTTPS 전체 인수도 다시 통과했다. [O3 검증 기록](../validation/local-monitoring-2026-11-16.json)에 실제 범위·이미지·해시를 기록했다.

자원 수집은 Docker Linux runtime과 exporter 루트 파일시스템 범위다. macOS 전체·실서버 DB/백업 디스크를 모두 검증한 것은 아니다. 실제 디스크 고갈 대신 경보 규칙을 합성 시계열로 시험한다. 외부 알림·서버 전체 장애 관측·실서버 배포는 O5, 검증 백업 시각과 복원은 뒤의 O4에서 구현·인수했다. 당시에는 GitHub CI job만 추가했고 원격 실행은 하지 않았다. 이후 공유 검증은 위 최신 요약을 따른다.

## O4 로컬 백업·독립 revision·복원 인수 (2026-11-16)

**`O4_ACCEPTANCE_PASSED`**로 실제 로컬 복원 훈련을 통과했다. [백업·복원 설명서](local-backup.md)에 두 자료의 차이, 번호 예시, 복원 순서와 실습 명령을 정리했다. 별도 `parking-backup` 환경에서만 실행했으며 외부 배포·기존 O2/O3 데이터 변환은 하지 않았다.

읽기 전용 pg_dump, SQLite backup API, 별도 키의 인증 암호화, 복호화 후 임시 DB 복원과 전 테이블 행 수/내용 비교를 구현했다. 독립 기록은 내부 전용 HTTP·SQLite 버전/CAS 참조 어댑터이며 DB 백업과 함께 되돌리지 않는다. 예약/초기화 claim은 독립 기록 → 로컬 두 파일 → DB 순서다. 백업 완료 뒤에도 새 범위로 옮겨 복원본과 최신 기록을 구분한다.

DB-only 및 DB+두 파일 롤백 시 실제 backend 기동 거부, hold 중 API/SSE·일반 사건/중복 ACK/heartbeat/정리 차단, 오프라인 장치 보고 대조·감사 증거, 보고서 해시와 손실 인수 후 새 revision 재개, DUPLICATE 재전송을 시험했다. 독립 기록 단절은 gate를 닫으며 연결만 돌아와도 자동 개방하지 않는다. 기존 자료 adopt·상한 건너뛰기·예약 단계별 중단 상태·잘못된 숫자·누락/변조·CAS 경쟁·오래되거나 대조 증거 없는 인수 보고서도 시험했다.

백엔드 일반 **169개**, PostgreSQL **85개**, Python 도구 **30개**가 통과했다. 실제 Prometheus의 검증 백업 시각/유효성, Grafana 전용 3개 패널, O4 경보 2개와 합성 조건을 확인했다. 이번 작은 가상 자료의 HTTPS 복구는 **85.65초**, 선택 백업 나이는 **72.81초**였고 백업 이후 ACK된 사건 **1건**이 과거 복원본에 없었다. 이는 해당 훈련 실측이며 운영 RPO/RTO 보장이 아니다. [검증 JSON](../validation/local-backup-2026-11-16.json)에 실행 명령·이미지·해시·범위와 한계를 기록한다.

모든 저장소와 키는 같은 PC에 있다. 외부 저장소 API·TLS·내구성·독립 키 보관·호스트 전체 유실·실제 장치·PITR/WAL·대용량·운영 스케줄/자동 보존 삭제·외부 알림은 미수행이다. O4 인수 당시에는 원격 실행·커밋·푸시 전이었다. 이후 공유 상태는 위 최신 요약을 따른다. 메모리 여유를 위해 새 O4 환경은 데이터 보존 상태로 중지하고 기존 O3 학습 환경을 재개한다.


## O5 배포 준비 문서 (2026-11-16)

[배포 준비 안내](deployment-readiness.md)에 학교 서버의 확인 조건, Lightsail 4GB/8GB 후보, 월 6만/10만 원 관리 예산과 첫 달·3개월 지출, 도메인/DNS/갱신 책임, 별도 계정의 S3 백업·revision 버킷, 주·부 담당자의 금고·추가 키 사본을 정리했다. 공식 단가와 계획용 환율·사용량 가정을 [예산 예시](../infra/deploy/budget.example.json)로 분리했다. 추천안은 미확정이고 [입력 양식](../infra/deploy/inputs.example.json)의 실제 선택값은 미정으로 남겼다.

**O5 상태는 준비 문서 작성이며 외부 배포 인수 완료가 아니다.** 실제 S3 원장 어댑터·운영 백업 자동화·호스트 없는 키 회수/복원·공인 인증서·linux/amd64 registry release·외부 가용성/알림·서버 부하 시험이 남아 있다. 현재 LOCAL_ONLY 제한과 128MiB 백업 도구 한계도 안내했다. 자원 구매·계정/버킷 생성·DNS 변경·키 생성/공유·외부 배포를 하지 않았다.

이번 문서·예시 변경의 문서 재생성, 구조/링크·v1.43 보존, 계약 생성 일치, JSON·비용 산식과 공백 오류 검사를 통과했다. O1~O4 실행 결과를 이번에 다시 실행한 것으로 세지 않는다. 실제 명령과 결과는 [O5 준비 검증 기록](../validation/deployment-readiness-2026-11-16.json)에 보관한다.


## 설명·공유 자료 보강 (2026-11-16)

O1 개념 안내에 TLS/계정/ACL·DB 네 역할·session_user/current_user·파일 secrets를 설명하고 이해 확인 질문 10개를 추가했다. 단계별 학습 질문과 의사결정 근거를 묶었으며, 학습자가 직접 이해하거나 실습했다고 대신 기록하지 않았다. 공개 검토한 로그 3개·원본 캡처 4개·JUnit 요약·측정값을 Git에 포함하는 증거 폴더로 보존했다. 과거 증거 해시는 그대로 두고, 이번 공유 전 검사와 원격 CI 결과는 별도 검증 기록으로 구분한다. 외부 배포는 수행하지 않았다.
