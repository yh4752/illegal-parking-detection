# ADR-003 사건 검증과 저장 판단의 경계

2026-11-13 · 채택 · 사용자 요청: 저장 구현 전에 설계 확정

## 문제

현재 코드는 v1.43의 EventMessage Schema와 SC01 및 등록 관계를 검사한다. 상세 명세 C5/C12/A2의 추가 조합까지 모두 검사하는 것은 아니다. Schema 통과를 저장 가능한 상태로 취급하면 모순을 수용하고, 무조건 강한 검사를 추가하면 정상 과거 보고·출력 전환을 거부한다.

## 결정

[사건 수신·저장 전 검증 기준 v1](../design/event-ingest-v1.md)을 구현 보완 기준으로 채택한다. wire 필드·타입·MQTT 경로·schema_version=2와 reference/v1.43은 유지한다. 현재 코드 완료 상태와 추가할 규칙을 문서에서 분리한다.

- 형식 검사와 메시지 내부 모순은 DB 저장 전에 검사한다.
- 기존 상태와 비교해야 하는 조건은 구역 잠금 아래 트랜잭션에서 검사한다.
- 실제 인식·시각 정확성·물리 출력은 엣지의 책임이다.
- snapshot과 event가 같은 사건이면 공통 요약이 일치하도록 SDK와 서버가 보장한다. 다른 사건이면 일치를 강제하지 않는다.
- 동일한 거부 메시지 재전송은 REJECTED를 유지한다. MESSAGE_ID_CONFLICT는 원래 receipt를 덮어쓰지 않는다.
- 충돌 원문은 V1의 고유키를 완화하지 않고 별도 quarantine V2로 저장한다. 원문은 최초 수신부터 30일, 최소 receipt는 유지한다.
- state 변경 전에 D6의 revision 범위를 확보한다. 초기 범위 0을 제약 삭제로 우회하지 않는다.

## 검토한 대안

Schema만 적용하면 C12의 시각 불신·정차시간 조합 등을 놓친다. 모든 상세 조건을 Schema에 복제하면 원본·SDK·서버가 서로 다른 규칙을 유지하기 쉽다. 의미 검사는 ID가 있는 별도 기준과 시험 예제로 추적한다.

같은 ID의 충돌 메시지를 event_message에 넣으면 기본키와 충돌하고 원래 증거를 잃을 수 있다. 별도 저장소가 요구사항을 만족한다. JSON 파싱 불가 입력의 무제한 수집은 채택하지 않는다.

## 영향

서버 검증기와 SDK의 전송 전 검사, 저장 인수 시험에 적용한다. 기존 예제 3건은 유지하며 추가 정상/모순 예제를 남긴다. V1 migration은 변경하지 않는다. 이 ADR은 설계 결정이며 V2·추가 검증·사건 저장 구현 완료를 의미하지 않는다. C4의 배치와 책임 경계는 변경하지 않는다.
