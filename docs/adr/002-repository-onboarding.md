# ADR-002: 클론한 팀원과 개발 에이전트의 진입점

- 날짜: 2026-11-11
- 상태: 채택. 문서 책임을 설계한 후 README·CONTRIBUTING·루트/백엔드 AGENTS에 반영했다.
- 당시 저장소: 개인 계정 yh4752의 비공개 parking-system. 현재 공개 범위는 [ADR-009](009-public-repository-sharing.md), 현재 이름은 [ADR-011](011-project-identity.md)을 따른다. 팀원 계정·초대는 별도.

## 해결할 문제

기존 README는 이전 대화와 설계 판본을 아는 사람을 대상으로 쓰였다. 클론 명령·필수 도구·예상 결과·담당별 첫 작업이 한 경로로 이어지지 않는다. 수정 전 AGENTS.md에는 ‘아직 미구현’ 같은 변하기 쉬운 상태가 반복되어 기능 추가 후 지침과 코드가 충돌할 수 있다.

## 문서별 책임

| 문서 | 독자·역할 | 넣지 않을 내용 |
|---|---|---|
| README.md | 처음 보는 사람: 문제·목표 동작·현재 실행 가능 범위·클론/실행·담당별 링크 | 대화 경과, 개발 도구 내부 사정, 모든 설계 규칙 |
| CONTRIBUTING.md | 팀원: 접근 권한·도구·브랜치/PR·검증·변경 절차·막혔을 때 확인할 곳 | 정식 메시지 필드의 복사본 |
| AGENTS.md | AI: 읽는 순서·작업 범위·정식 기준 위치·명령·변경/보고 원칙 | 고정된 ‘다음 작업’, 개인 경로, 항상 변하는 완료 상태 |
| backend/AGENTS.md | 백엔드 작업의 추가 규칙: 판단 소유권·트랜잭션·검증 경계 | 루트 규칙의 반복 |
| docs/status.md | 모든 독자: 실제 작성·실행 여부 | 명세의 미래 목표를 실행 결과로 기록 |
| docs/architecture.md 등 | 역할·구조·기능 상세를 필요할 때 탐색 | README의 클론 절차 중복 |

루트 지침과 backend 추가 지침만 만든다. frontend·edge-sdk에는 실제 코드가 아직 없으므로 별도 규칙 파일은 만들지 않는다. 사용 AI가 AGENTS.md를 자동으로 읽는다고 가정하지 않고 수동 진입 문구를 제공한다. 저장소 지침은 사용자 요청과 개발 도구의 상위 정책을 덮어쓰지 않는다.

## 개발 흐름

클론 → README에서 현재 범위 확인 → 로컬 기동 또는 문서 검사 → 역할별 첫 작업 선택 → 브랜치 → 코드·영향 문서·시험 수정 → PR 확인 순서로 진행한다. 개발자가 수행할 작업에는 기존 v1.43 계약을 연결하되 첫 진입에서 127개 원본을 모두 읽게 하지 않는다.

CI는 문서·설정과 백엔드 빌드를 구분한다. 제품 동작은 새로 구현하지 않는다. 실제 빌드나 초기 CI가 실패하면 재현 가능한 원인만 수정하고 실패를 숨기기 위해 검사를 끄지 않는다.

## 검토 기준

- README만 보고 무엇을 만드는지, 지금 무엇을 실행할 수 있는지 설명할 수 있다.
- 클론 URL·작업 디렉터리·필수 도구·명령·예상 결과·중지 방법이 일치한다.
- 공통 규칙과 변동 상태의 원본이 분리되어 있다. 규칙은 검증 가능한 행동으로 작성한다.
- 실제 보드와 PC 가상 장치, 브로커 수신과 DB 저장, 작성과 실행 성공을 구분한다.
- 개인 경로·실제 비밀값·데이터 원본 없이 클론할 수 있고 상세 계약은 보존한다.
- 별도 검토 후 중요한 지적을 반영하고, 공개할 결과에 맞는 실제 검증을 수행한다.

## 채택하지 않는 것

지금은 조직 생성·협업자 자동 초대·브랜치 보호의 강제 적용·실서비스 배포·모든 AI 도구용 중복 규칙 파일을 추가하지 않는다. 필요한 정보나 실제 사용 도구가 확인되면 확장한다.

## 검토와 반영

독립 검토에서 기존 문서의 ‘v1.43 원본 수정’ 안내와 원본 해시 보존 검사가 충돌하는 점을 지적했다. 보존본을 임의로 바꾸지 않고, 계약 변경 시 ADR과 새 기준 위치·관련 예제·검증을 함께 기록하도록 수정했다. 실제 검증 결과는 [현재 상태](../status.md)에서 확인한다.

문서 분리 기준은 [GitHub README 안내](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes), 에이전트 파일 적용 범위는 [AGENTS.md 안내](https://developers.openai.com/codex/guides/agents-md)를 참고했다.
