ADR-010: 첫 공개 배포와 복구 경계

2026-11-16 · 설계 채택, O1~O4 로컬 인수 통과, O5 준비 추천 작성, 외부 배포 전

기존 ADR-005/008의 단일 서버·조회 인계판을 유지한다. Linux x86_64 + Compose + Nginx, 백엔드 1개로 공개한다. 최초에는 가상 장치만 연결하고 MQTT 외부 포트를 열지 않는다. 운영 내부 MQTT에도 TLS/계정/ACL을 적용한다. 관리 지표는 내부 수집과 SSH 터널로 확인한다.

배포·복원은 별도 작업이며 main 병합이 자동 배포를 뜻하지 않는다. 운영 프로필·권한·모니터링·격리 복원 시험이 완료되기 전에 기존 로컬 Compose를 외부로 열지 않는다.

기존 로컬 revision 파일 두 개만으로 동시 과거 복원·호스트 유실을 검출할 수 없다. O4는 범위·초기화 claim을 독립 CAS → 로컬 두 파일 → DB 순서로 확정한다. 백업 뒤 새 범위를 예약하고 복구 때 최대 상한 다음으로 이동한다. 별도 로컬 HTTP/SQLite 서비스는 버전 이력·삭제 API 부재·동기화 저장을 검증하는 참조 어댑터다. 외부 공급자의 TLS·최신성·내구성·삭제 권한은 아직 인수하지 않았다. 독립 기록의 최신성을 증명하지 못하면 자동 복구하지 않는다.

복원은 원본을 보존한 새 DB에서 시작한다. 일반 MQTT·중복 ACK·heartbeat·배경 정리와 보호된 API/SSE는 hold 중 차단한다. 별도 오프라인 CLI만 더 최신인 장치 보고를 같은 업무 검증기로 대조하고 감사 증거를 남긴다. 보고서의 DB 지문·독립 버전·장치 보고 증거와 명시적 손실 인수가 맞아야 hold를 해제한다. wire·REST 계약과 기존 migration은 변경하지 않는다. 백업은 암호화한 결과를 실제 격리 DB로 복원·전 테이블 비교한 후 성공으로 기록한다. O4 안내·저장 경계 그림에 구현과 한계를 설명한다.

운영 부담은 단일 서버 장애 시 중단과 수동 배포·인수다. 고가용성·무손실 복구·실보드 성능을 보장하지 않는다. 코드 저장소 공개·v1.43 제품 원본·MQTT DTO는 변경하지 않는다.

O1에서는 새 서버를 나누지 않고 공통 MQTT 옵션을 세 연결(사건/ACK/telemetry)에 적용했다. runtime은 스키마 검증만 하며 migration은 별도 CLI에서 실행한다. operator는 현재 계정 관리에만 사용하고 복원 권한은 O4 전까지 부여하지 않는다. 파일 이름·최소 GRANT·장치별 ACL과 시험 명령은 운영 설정 안내에 기록한다.

O2에서는 web/app/data/mqtt 망을 분리한 Compose로 HTTPS 정적 화면과 API/SSE를 같은 출처에 연결했다. 실제 외부 배포 없이 loopback 포트와 로컬 CA로 시험한다. OS 신뢰 저장소를 바꾸지 않고 엄격한 CA/SAN 시험과 해당 공개키만 허용한 별도 Chromium 시험을 구분한다. Nginx는 SSE buffering을 끄고 Docker DNS를 재조회한다. backend IP 변경·인증서 reload·계정 회수·데이터 보존 시험을 통과했다. 요청 오류 로그의 원본 URI 노출을 피하려고 해당 로그를 끄고 정제된 접근 로그·backend 로그로 진단한다. 로컬 release의 이미지 ID·설정 해시는 외부 배포 승인이나 레지스트리 게시를 뜻하지 않는다.

O3에서는 Micrometer 결과를 별도 management 포트의 전용 인증으로 수집하고, Prometheus와 Grafana를 내부 관찰 경로로 추가했다. 제품 로그인 경로와 관리 인증을 분리한다. DB/revision 읽기 준비와 프로세스 liveness·MQTT 연결을 분리하며, 실제 커밋 뒤 ACK 발행의 MQTT 5 거부 응답도 실패로 센다. node exporter는 Docker Linux 범위만 관찰하고 Docker socket·호스트 루트·privileged는 사용하지 않는다. 외부 전체 서버 감시·알림 전달은 O5, 실제 백업 성공 계측은 O4에 남긴다. 지표 해석과 실습을 함께 제공한다.

2026-11-16 O5 초기 준비에서는 학교 서버 우선, Lightsail 4GB·8GB와 월 6만·10만 원을 비교했다. 현재 선택은 아래 11월 17일 갱신과 O5 결정표를 따른다. 별도 AWS 계정의 비공개 S3 일반 목적 버킷을 백업과 revision으로 나누는 안은 추천 단계다. 강한 읽기 일관성·Versioning·조건부 쓰기는 원장 구현의 근거이지 구현 완료의 증거가 아니다. 실제 어댑터에서 단조 증가·최신성·CAS 경쟁·실패 중단과 권한을 검증해야 한다.

대칭키의 운영 작업용 사본과 서버 밖 복구용 사본을 구분한다. 초기 주·부 담당자 공유안은 사용자의 단독 관리 선택으로 대체하며 개인 금고·추가 오프라인 사본을 추천한다. runtime에 저장소 관리자·백업 키·삭제 권한을 함께 주지 않는다. 백업 보존과 revision 최신 기록 보존은 별도 정책으로 관리한다. 같은 리전·공급자 장애와 본인 부재 시 대응 공백은 남는 한계다. 외부 계정·버킷·키·DNS를 생성하지 않았다. 비용·권한·복구 조건은 O5 안내, 경계는 O5 추천 그림에 있다.

2026-11-17: 자료 중요도와 단독 관리에 따른 목표 승인

사용자는 총 3만 원·발표 전 일주일의 Lightsail 4GB 조건부 안, 미등록 DuckDNS 후보, 재생성 가능한 가상 사건과 반드시 보존할 발표·블로그 증거의 구분을 정했다. 백업·복구 목표는 승인 정책을 기준으로 한다. DB 24시간 손실/서비스 2시간 복구, 보존 완료 증거 손실 0/15분 회수, 실행 중 로그 5분 외부 복사, 발표 대체 5분을 목표로 한다. 확정 증거의 손실 0은 두 독립 사본의 검증 완료 이후에 적용한다.

DB는 매일 03:00 KST와 변경·종료 전에 백업하고 성공 일별 7세대·보호 사본을 관리한다. 최종 DB는 2027-01-10까지 보관 후 검토하고, 증거·최종 revision은 최소 2027-12-11까지 및 사용 중인 기간에 보존한다. 증거는 자동 삭제하지 않고 키는 필요한 암호화 파일보다 먼저 폐기하지 않는다.

본인이 계정·키를 단독 관리하며 보조 담당자는 두지 않는다. 원래 서버·주 로그인 기기 없이 추가 복구 수단으로 회수하는 시험을 인수 조건으로 삼는다. 운영/백업 AWS 계정 분리와 Bitwarden 무료 개인 금고·암호화 USB·종이 복구 안내서 구성은 승인했다. 실제 계정 생성·매체 확보·암호화 도구·보관 장소·납부자·권한·복구 시험은 남아 있다. 장소 회수·이동 시간을 포함해 15분 목표를 시험하며, 키 사본은 증거 파일의 독립 사본을 대신하지 않는다. 목표 승인으로 외부 실행을 승인하거나 F1 전체를 완료 처리하지 않는다.
